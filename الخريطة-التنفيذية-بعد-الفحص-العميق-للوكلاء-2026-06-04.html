1 · فحص الاستيرادات الكامنة (نمط ADMIN-DEFECT-1)

ADMIN-DEFECT-1 كان NameError: select not defined لأنّ operations_router.py يستورد مساعدات SQLAlchemy محليًّا في كلّ دالّة، ونقطة list_driver_abandonments نسيتها. خشية نقاط أخرى مصابة، شُغِّل ماسح AST على كلّ الراوترات الكبرى:

# scan: operations/* finance/* catalog/* dispatch/* orders/* providers/* complaints_service._hash_description : missing {text} → إيجابيّ كاذب (text معامِل دالّة) dispatch_router._cash_sum / _wallet_sum : missing {select,func} → إيجابيّ كاذب (دالّتان متداخلتان ترثان النطاق) # لا استيراد مفقود حقيقيّ آخر — list_driver_abandonments (بعد الإصلاح) نظيف
تصلّب جذريّ مقترح (P2): استبدال نمط «الاستيراد المحليّ لكلّ دالّة» في operations_router.py باستيراد على مستوى الوحدة (from sqlalchemy import select, func, and_, or_, desc) لمنع تكرار هذا الصنف من الأعطال في أيّ نقطة مستقبليّة. تغيير ميكانيكيّ منخفض الخطورة.

2 · الخريطة التنفيذيّة المُرتّبة بالأولويّة

P0 ADMIN-DEFECT-1 — نشر إصلاح الـ500 الحيّ على الإنتاج

الحالة: الكود مُصلَح ومُختبَر محليًّا (سطر from sqlalchemy import select, func في operations_router.py:~4389) + اختبار وقاية جديد. لكنّ العيب ما زال حيًّا على tawanow.com (نُشر ضمن aa25).
الإجراء: إعادة نشر الباكند عبر deploy/deploy_be.sh (يحفظ القاعدة) — بلا migration (تغيير كود فقط). ثمّ تحقّق حيّ: GET /operations/driver-abandonments بتوكن OPS → 200 (كان 500).
التحقّق: 19/19 اختبار محليّ ناجح · FIN-COR PASS · بعد النشر: استدعاء حيّ 200 + سجلّ بلا NameError.
الخطورة: منخفضة جدًّا (إضافة سطرَي استيراد، لا تغيير سلوك آخر). القرار المطلوب: إذن النشر.

P2 COV-1 — اختبار تطابق التسوية ↔ الدفتر المزدوج

التتبّع: generate_settlement:40 يحسب net = gross − fees − tax → التطابق سليم بالبناء؛ approve_settlement يكتب أسطر ORDER_GROSS/PLATFORM_FEE. لا عيب مشتبه — الناقص اختبار يؤكّد رقميًّا أنّ مجموع أسطر الدفتر للطلب متوازن ومطابق للتسوية.
الإجراء: اختبار (وحدة/تكامل) ينشئ طلبًا مُسلَّمًا → generate+approve → يؤكّد ΣDR=ΣCR لمرجع الطلب وgross=net+fees+tax وPLATFORM_REVENUE_credit==fees. + إضافة عائلة في محرّك الأدمين (بعد بذر COA). تاريخ CRIT-02 يجعلها عالية القيمة.
الخطورة: صفر على المنتج (اختبار فقط).

P2 COV-2 — اختبار مهلة قبول المزوّد + تحرير حجز المحفظة

التتبّع: accept_timeout_service.auto_reject_stale_orders:56 يُنفّذ آلة الحالات + يحرّر حجز WALLET (سطر 95-98) + يُشعِر order.provider_timeout — مُصلَح بالم447. فجوة اختبار فقط.
الإجراء: اختبار يترك طلب WALLET بلا قبول، يستدعي auto_reject، ويؤكّد: الحالة الانتقاليّة + WalletReservation.state==RELEASED + الإشعار. (مهلة قابلة للضبط — backdate أو حقن نافذة 0.)

P3 PROV-6 — حارس active-status على إنشاء الصنف (دفاع-في-العمق اختياريّ)

التتبّع: create_catalog_item (catalog_router.py:273) يستخدم require_role(PROVIDER_ADMIN) بلا فحص provider.status==ACTIVE → مزوّد PENDING ينشئ صنف DRAFT. لكنّ التسريب محجوب أصلًا للعميل بـPhase 450-W1-4 (الكتالوج العامّ + النشر يشترطان ACTIVE؛ الاختبارات تُفعّل المزوّد أولًا).
الإجراء (إن طُبِّق): بعد جلب المزوّد، if provider.status!='ACTIVE': 403. نطاق الأثر: آمن — اختبارات الكتالوج (phase399/175/master_pick) تُنفّذ UPDATE providers SET status='ACTIVE' قبل الإنشاء (بفضل 450-W1-4)، فلا تتراجع. القيمة: منخفضة (تكرار لحماية قائمة).
التوصية: اختياريّ — يُطبَّق مع تشغيل الحزمة الكاملة للتأكّد، أو يُؤجَّل بلا ضرر.

P3 توسيع التغطية + تحسينات المحرّك

فجوات تغطية ذات قيمة: حجب دَين no-show للعميل (م437) · بوّابة OTP لـCOD عالي القيمة (م427) · إطلاق المجدول (م439) · تقييم أعمى بعد النافذة (م434) · سلّة متعدّدة المزوّدين · سلسلة chargeback · إغلاق الفترة المحاسبيّة + حجب القيد · موافقة مزدوجة بوكيلَي ماليّة مختلفين · CRUD قواعد الاحتيال · سلّم غرامة التخلّي الكامل + استثناء VEHICLE_FAILURE + reinstate يعكس.
تحسينات المحرّك (بنية اختبار لا منتج): طلب الاسترداد يبدؤه العميل لا FINANCE · بذر COA على النسخة المحليّة · مسارات earnings hist/bal · حقل/دور تعليق المنطقة · سقف نقد السائق يُختبَر دون إعادة ضبط في عائلة مخصّصة.
