تقرير ② — فحص كل اللوحات بحثًا عن تشوّه (قبل الإصلاح)

دراسة شاملة للوحات المشروع: ما هو مشوّه، ولماذا، وكيف يُصلَح تقرير قبل الإصلاح — لم أُصلِح شيئًا
2026-06-11 · فحص ثابت للأكواد (CSS + بنية الصفحات) لكلّ لوحات OPS/الإدارة + صفحات العميل/السائق/المزوّد

الجواب المختصر

المشروع نظيف إلى حدّ كبير من التشوّه الحادّ: لا توجد أصناف Tailwind غير مُنسَّقة (السبب التاريخيّ الأكبر) — صفر. وتشوّه الاعتماد (checkbox) أُصلِح عالميًّا فعلاً.
التشوّه المتبقّي المُكتشَف: 5 لوحات OPS تستخدم حاوية ضيّقة .page (سقف 960px) بدل .page-ops (عرض كامل) → على الشاشات العريضة يظهر محتواها محصورًا في الوسط بفراغات جانبيّة، وجداولها لا تأخذ معالجة OPS للعرض الكامل/التمرير. تشوّه متوسّط (تفاوت عرض/فراغ)، لا حادّ.

منهجيّة الفحص

  • فحص أصناف Tailwind غير المُنسَّقة (السبب التاريخيّ للتشوّه في 394/395): بحث شامل في src/ → صفر.
  • فحص نمط عيب الاعتماد (input بعرض 100% كشقيق flex بـflex-shrink:0): الحالة الوحيدة كانت checkbox الاعتماد، وأُصلِحت عالميًّا؛ لا حالة أخرى على input متأثّر.
  • فحص حاويات الصفحات: .page (سقف 480→720→960px) مقابل .page-ops (عرض كامل). لوحات OPS يجب أن تكون .page-ops.
  • فحص الجداول: معالجة التمرير الأفقيّ مطبّقة على .page-ops table/.card table فقط — جداول لوحات .page خارج بطاقة لا تُغطَّى.

اللوحات المشوّهة المُكتشَفة (5)

لوحات OPS تستخدم className="page" (الضيّقة) بدل page-ops — نفس العيب الذي أصلحته للتوّ في صفحة المندوبين:

OpsDriverCashLimit.tsxops/متوسّطمحصورة 960px

السبب الجذريّ

/* global.css */
.page    { max-width: 480px; }            /* + 720px ثمّ 960px للشاشات الأكبر — للعميل/الجوّال */
.page-ops{ width: 100%; }                 /* عرض كامل — للوحات OPS */
.page-ops table, .card table { ... }       /* تمرير أفقيّ للجداول العريضة — لا يشمل .page */

هذه اللوحات تُعرَض داخل قشرة OPS العريضة (.ops-main) لكنّها ملفوفة بـ.page → سقف 960px → فراغ جانبيّ على الشاشات العريضة + جداولها بلا معالجة OPS.

الإصلاح المقترح (سطر واحد لكلّ لوحة)

// في كلّ لوحة من الخمس
- <div className="page">
+ <div className="page-ops">
المخاطر: ضئيلة (تبديل صنف حاوية، واجهة فقط، بلا باكند). نفس الإصلاح الذي طُبِّق ونُشِر بنجاح على صفحة المندوبين. التحقّق: tsc/lint/build/Vitest + تصوير حيّ لكلّ لوحة على شاشة عريضة قبل/بعد.
قد تحتاج بعضها تعديلًا بسيطًا إضافيًّا (لفّ جدول داخل .card أو إزالة عرض ثابت) — يُحدَّد لكلّ لوحة أثناء الإصلاح بعد إذنك.

ما هو سليم (لا تشوّه)

  • صفر أصناف Tailwind غير مُنسَّقة في كامل src/ (نُظِّفت سابقًا ولم تُعَد).
  • تشوّه الاعتماد (checkbox) مُصلَح عالميًّا (يغطّي أيّ checkbox/radio في كلّ التطبيق).
  • 61 لوحة OPS تستخدم .page-ops الصحيحة (عرض كامل + جداول مُعالَجة).
  • صفحات العميل/السائق/المزوّد على .page الضيّقة صحيحة (مُصمَّمة للجوّال 480px).

الخلاصة + الطلب

التشوّه الحادّ مُعالَج. المتبقّي = 5 لوحات OPS على الحاوية الضيّقة (تشوّه متوسّط على الشاشات العريضة)، إصلاحها تبديل صنف بسيط. لم أُصلِح شيئًا بعد — أنتظر مراجعتك. قُل «أصلح اللوحات الخمس» لأبدأ بنفس المنهجيّة (إصلاح → بوّابات → نشر → تحقّق حيّ بالصور).
