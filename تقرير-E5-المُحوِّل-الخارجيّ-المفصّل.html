① الخلاصة والقرار الحاكم

نفّذتُ «الانتقال إلى تفعيل المزوّد الخارجيّ» بالقرار الموصى به المنضبط بالحوكمة: بنيتُ المُحوِّل الخارجيّ (الدفاع الحقيقيّ عن الانتحال/liveness بالـML) كاملًا وجاهزًا للتفعيل، لكنّه خامل خلف أربع بوّابات صريحة آخرها إقرار خصوصيّة مُنفَّذ. هذا نفس نمط FCM/الدفع في المشروع: التكامل جاهز، والتشغيل الفعليّ مرهون باعتمادات المالك واجتياز بوّابة الخصوصيّة.

على الإنتاج (افتراضيًّا)
خامل — is_external_configured=False (الأربعة فارغة) ⇒ لا تغادر أيّ صورة
ما يلزم للتفعيل
اسم مزوّد (≠local) + api_url + api_key + privacy_ack=true — الأربعة معًا
القلب الماليّ / الترحيل
لا مساس — FIN-COR PASS · بلا migration (جدول aa29)
حالة التفعيل
لم يُفعَّل مزوّد حقيقيّ — يحتاج حساب/اعتمادات المالك + DPA

② لماذا لا تفعيل فعليّ من هنا (الحدود الصلبة)

المزوّد الخارجيّ يُرسل صور هويّة المواطنين الليبيّين خارج المنصّة. هذا قرار قانونيّ/خصوصيّ يخصّ المالك، لا يصحّ تجاوزه.
الحاجزالتفصيل
لا حساب / اعتماداتخدمات Incode/Paravision تجاريّة تتطلّب عقدًا ومفاتيح API لا تُنشأ هنا
بوّابة الخصوصيّةالحوكمة تنصّ صراحةً: التفعيل «بعد اجتياز بوّابة الخصوصيّة» — يلزمه DPA + مراجعة قانونيّة + موافقة
PILOT-GAP-PRIVACYمفتوحة (OPEN_BLOCKING) في حالة المشروع

لذا: بُني المُحوِّل جاهزًا، والتشغيل مُؤمَّن خلف بوّابة الخصوصيّة المُنفَّذة برمجيًّا.

③ تصميم البوّابات الأربع (الحارس الأساس)

لا تغادر أيّ صورة المنصّة إلا إذا تحقّقت الأربع معًا — وأهمّها الرابعة (بوّابة الخصوصيّة):

vendor ≠ "local"& api_url& api_key& privacy_ack = true
المفتاح (config)الافتراضيّالدور
doc_verify_vendor""اسم المزوّد؛ local=المدمج، فارغ=خامل، غيرهما=خارجيّ
doc_verify_api_url""نقطة نهاية PAD للمزوّد
doc_verify_api_key""سرّ المزوّد (Bearer)
doc_verify_timeout_seconds8.0مهلة HTTP
doc_verify_external_privacy_ackFalseبوّابة الخصوصيّة المُنفَّذة — تُضبط true فقط بعد DPA/الإذن القانونيّ
حزام وحمّالة: حتى لو ضُبطت الاعتمادات (url+key)، فبدون privacy_ack يبقى is_external_configured()=False ⇒ لا نداء. هذا يحوّل «بوّابة الخصوصيّة» من توثيق إلى مفتاح مُدقَّق مفروض.

④ المُحوِّل بالكود — modules/kyc/external_doc_adapter.py (جديد)

أ — حارس التهيئة (يفرض الأربع)

def is_external_configured() -> bool:
    vendor = (settings.doc_verify_vendor or "").strip().lower()
    return bool(
        vendor and vendor != "local"
        and (settings.doc_verify_api_url or "").strip()
        and (settings.doc_verify_api_key or "").strip()
        and bool(settings.doc_verify_external_privacy_ack)   # بوّابة الخصوصيّة
    )

ب — نقطة الدخول (لا تُرسل صورة دون التهيئة الكاملة)

async def run_external_verification(object_key) -> dict:
    if not is_external_configured():
        raise RuntimeError("external … not configured (vendor/url/key/privacy-ack)")
    data = await run_in_threadpool(_fetch_object_bytes, object_key)  # من MinIO، خارج الحلقة
    if data is None: return {"score": 0, "flags": "MISSING_OBJECT"}
    payload = await _call_vendor(data, object_key)                  # httpx POST متعدّد الأجزاء
    return _map_response(payload)

ج — نداء المزوّد + المطابقة

async def _call_vendor(image, object_key) -> dict:    # نمط geo_providers
    async with httpx.AsyncClient(timeout=doc_verify_timeout_seconds) as c:
        resp = await c.post(url, headers={"Authorization": f"Bearer {key}"},
                              files={"file": (name, image)})
        resp.raise_for_status(); return resp.json()

def _map_response(payload) -> dict:                    # → {score 0..100, flags}
    score = clamp(int(payload.get("score")), 0, 100)   # متين على الغياب
    flags = join(payload.get("flags"))               # قائمة أو نصّ → نصّ
    return {"score": score, "flags": flags}

fail-open: أيّ خطأ HTTP/شبكة يُرفَع ويُلتقط أعلى السلسلة ⇒ ERROR غير حاجب (لا يعطّل الاعتماد).

⑧ التحقّق الحيّ على الإنتاج

  --- الحالة الافتراضيّة على الإنتاج (إعداد الخادم الحيّ) ---
  is_enabled (any vendor)      : False
  is_external_configured       : False
  env vendor/url/key/ack       : '' '' '' False

  --- منطق البوّابة (عمليّة رمَويّة، لا تمسّ الخادم الحيّ، بلا نداء خارجيّ) ---
  vendor+url+key, ack=False  -> is_external_configured = False  (يجب False — بوّابة الخصوصيّة)
  vendor+url+key, ack=True   -> is_external_configured = True   (تتفعّل فقط الآن)
  _map_response({score:250, flags:[FACE_MISMATCH]}) = {score:100, flags:'FACE_MISMATCH'}
✅ المُحوِّل الخارجيّ في الصورة المنشورة، خامل افتراضيًّا على الإنتاج (الأربعة فارغة ⇒ لا نداء)، وبوّابة الخصوصيّة مُثبَتة حيًّا: حتى مع الاعتمادات الكاملة، ack=False يمنع التهيئة. لم تُمسّ إعدادات الخادم الحيّ ولم يُجرَ أيّ نداء خارجيّ فعليّ. الحاويتان صحّيتان.

⑨ خطوات التفعيل المتبقّية لك (عند الجاهزيّة)

  1. اختيار مزوّد ML وفتح حساب والحصول على api_url + api_key.
  2. اجتياز بوّابة الخصوصيّة (DPA + مراجعة قانونيّة لنقل صور الهويّة) ثمّ ضبط doc_verify_external_privacy_ack=true.
  3. مواءمة _map_response مع مخطّط استجابة المزوّد المختار.
  4. ضبط doc_verify_vendor=<اسم المزوّد>.

عند اكتمالها يبدأ التقييم الحيّ بالـML ويبقى استشاريًّا (لا يحجب). للدفاع عن هجمات الحقن (كاميرا افتراضيّة/تزييف): SDK جهة العميل وقت الالتقاط — طبقة إضافيّة مستقبليّة.
