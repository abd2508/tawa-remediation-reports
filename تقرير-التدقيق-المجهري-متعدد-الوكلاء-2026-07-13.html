P1FACTMobile · Auth/State

F-27: OTP وحالات الطلب في Expo لا تطابق Backend

ببساطة: تطبيق الموبايل يطلب أغراض OTP لا يعرفها الخادم، ويستخدم أسماء حالات مختلفة لتتبع الطلب.

Expo يرسل CUSTOMER_LOGIN وDRIVER_LOGIN، بينما enum الخلفية لا يحتويهما، فتكون النتيجة العقدية 422. Expo يعرف 11 حالة مثل ACCEPTED وEN_ROUTE_TO_CUSTOMER؛ الخادم يعرف 28 ويستخدم ACCEPTED_BY_PROVIDER وEN_ROUTE.

الأثر: تعطل دخول العميل/السائق، badges وtimeline، واكتشاف نهاية الطلب/polling.

P1FACTMobile · Push/SSE/Session

F-28: Push وSSE وانتهاء الجلسة منجرفة

ببساطة: token push يُرسل بحروف كبيرة فيُرفض، وSSE يسمع النوع الخطأ من الأحداث، ومسح الرمز لا يحول حالة التطبيق إلى logged out.

Expo يرسل IOS/ANDROID والخادم يقبل lowercase؛ الخطأ يُبتلع. Expo يسمع message بينما الخادم يبث order.snapshot وorder.state_changed وغيرها. refresh 401/403 يمسح SecureStore لكن Zustand يبقى authenticated.

الأثر: إشعارات مفقودة، live updates لا تصل، وشاشة تبدو مسجلة رغم انتهاء الاعتماد.

P1FACTCI · Dependency/Contract

F-29: بوابات CI لا تختبر ما يُشحن ولا ما تدعيه الوثائق

ببساطة: صورة الإنتاج تستخدم lock، لكن CI يثبت ranges؛ والتحقق من العقد يبحث عن نصوص revision ولا يقارن Runtime API.

backend/Dockerfile يثبت requirements.lock مع hashes، بينما CI يستخدم pip install -e "backend/.[dev]". لا توجد بوابات Flutter/Expo/Playwright/Alembic upgrade/runtime OpenAPI/coverage/mypy. أداة OpenAPI gap لا تفشل عند وجود فجوات ولا تطابق HTTP method.

الأثر: CI أخضر لا يثبت تطابق الحزمة المشحونة أو الموبايل أو العقد الحي.

P3FACTDead/Dormant Code

F-30: وحدات غير موصولة بالـRuntime ومستخدمة فقط في الاختبارات

ببساطة: توجد خدمات تبدو كميزات، لكن لا يستدعيها أي router حي.

أمثلة مثبتة: donations_controller.py وhome_kitchens_controller.py يصرحان dead code؛ group_order_split.py، modifier_validator.py، plate_match_service.py، soft_launch_guard.py، payment_adapter.py dormant، وناشر pos_outbound.py. لم توجد routers معلنة غير مسجلة.

قد تكون ميزات مؤجلة؛ حذفها أو توصيلها يحتاج قرار منتج وموافقة، ولا يُستنتج من عدم الاستيراد وحده.

11. المتبقي

حتى بعد معالجة النتائج، تبقى أعمال تحقق لا يصح إعلان الإغلاق دونها:

  • اختبار متصفح مصفوفي لكل أدوار Customer/Driver/Provider/OPS، مع حسابات حقيقية معزولة.
  • تشغيل Expo real ضد بيئة ephemeral، واختبارات contract تحول snake_case/envelopes إلى نماذج UI.
  • اختبارات فشل إجبارية لـRedis أثناء وبعد تنفيذ العمليات، واختبارات concurrency.
  • اختبار points-only refund، وتعطل commission reversal، وتعطل ledger بعد PSP capture.
  • تحديد أي تطبيق موبايل هو مصدر الحقيقة ثم اختبار build/sign/update له.
  • تجربة accessibility بلوحة المفاتيح وقارئ شاشة، وقياس Web performance على جهاز فعلي.

12. اقتراحات تحتاج موافقة صريحة

SUGGESTION لم يُنفذ أي بند أدناه:

  1. حزمة P0 Idempotency: namespace بالمستخدم+المسار+method، بصمة body، حجز ذري/lock، عدم إعادة cached response قبل auth، وعدم استدعاء call_next ثانية عند فشل Redis.
  2. حزمة State Sync: استعادة ملفَي الجذر التالفين من مصدر موثوق، جعل الأداة تفشل على NUL/empty، وتوحيد phase وAlembic head والأعلام.
  3. حزمة Expo Real: mappers موحدة، تصحيح OTP/paths/payloads/statuses/push/SSE/session، إزالة no-op controls، وcontract tests حقيقية في CI.
  4. حزمة المال: اختبار وإصلاح points-only refund، جعل commission reversal قابلاً للاستعادة/المطابقة، وتصميم capture-ledger saga قبل تفعيل البطاقة.
  5. حزمة Web Offline: ربط outbox بهوية الحساب، مسحه/عزله عند logout، عدم حذف 401، وتوحيد banner مع IndexedDB الحقيقي.
  6. حزمة العقود وCI: اختيار Runtime OpenAPI أو عقد مقصود موثق، استخدام dependency locks المشحونة، وإضافة mobile/migration/E2E/type gates.
  7. حزمة E2E: حذف افتراض role picker القديم أو تحديث fixture، تقسيم suite لمنع احتجاز 157 اختباراً، وإصلاح localStorage navigation.
  8. حزمة الديون: baseline تدريجي لـMypy، warnings-as-errors انتقائية، وتحديث governance docs بأرقام مولدة آلياً.

13. الإجراء الصحيح التالي

الخطوة الصحيحة: تفويض مسارين P0 مستقلين، State Sync وIdempotency، قبل أي تفعيل مالي أو توسع Pilot.

في الحوكمة: استعادة مدخلات غير تالفة وجعل الأدوات تفشل عند فسادها. وفي التنفيذ: لا cache replay قبل auth، لا تصادم بين مستخدمين/مسارات، لا استدعاء ثان عند فشل Redis، وطلبان متزامنان بمفتاح واحد ينفذان handler مرة واحدة. بعد ذلك تأتي مواءمة Expo Real ثم سلامة الاسترداد والعقود.
