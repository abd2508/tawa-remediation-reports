١ ما هو سيرفر التجارب؟

سيرفر التجارب هو نسخة من منصّة تووا تعمل على جهازك المنزلي داخل حاويات Docker، باسم مجموعة tawalocal. يحمل أحدث كود + بيانات تجريبية، ويعمل بمعزل عن أي بيئة إنتاج.

٢ كيف يصل سيرفرك المنزلي إلى العالم؟

المشكلة المعتادة: جهازك المنزلي خلف راوتر، بلا عنوان IP عام ثابت، ولا يمكن فتح منافذ بأمان. الحلّ المستخدَم: نفق Cloudflare (Cloudflare Tunnel) — قناة صادرة آمنة من جهازك إلى شبكة Cloudflare، فيصبح الموقع متاحًا للعالم دون فتح أي منفذ ودون كشف عنوان جهازك.

الشكل ١: مسار الطلب — الزائر → Cloudflare (يستقبل عالميًّا) → النفق → حاويات جهازك. لا منافذ مفتوحة، ولا كشف لعنوانك.

٣ سجلّ العمل — المرحلة ١: التحقّق من الوصول الخارجي

المرحلة ١

قبل أي تعديل، تحقّقت من حالة السيرفر فعليًّا (لا افتراضًا). النتائج:

  • النفق كان يعمل عبر عملية يدويّة مؤقّتة (nohup, رقم العملية 1626966)، وخدمة systemd الدائمة غير مفعّلة → أي أنّ إعادة التشغيل كانت ستُسقط الموقع.
  • لا يوجد تحايل في /etc/hosts → أي اختبار يمرّ فعلًا عبر الإنترنت العام.
  • النطاق كان يُحلّ إلى عناوين Cloudflare (2606:4700:…).
  • اختبار خارجي أعطى HTTP 200، وفحص مستقلّ من شبكة أجنبية عرض «تووا | Tawa».
الخلاصة: الموقع كان يعمل من الخارج، لكنّه هشّ — معلّق على عملية يدويّة تموت عند إعادة التشغيل. هذا ما عالجته المرحلة ٢.

٤ المرحلة ٢: التقوية وجعل السيرفر دائمًا

المرحلة ٢

الهدف: أن يعمل السيرفر "طبيعيًّا كأنه سيرفر حقيقي" — يبدأ وحده ولا يتوقّف. نُفِّذت ثلاث خطوات (بصلاحيات النظام):

أ) تحويل النفق إلى خدمة نظام دائمة

أُنشئ ملف خدمة systemd يشغّل النفق تلقائيًّا، ويعيد تشغيل نفسه لو تعطّل، ويبدأ مع كل إقلاع:

# /etc/systemd/system/cloudflared-tawa.service
[Unit]
Description=Cloudflare Tunnel tawa-local (tawanow.com)
After=network-online.target docker.service
Wants=network-online.target

[Service]
User=a
ExecStart=/usr/local/bin/cloudflared tunnel --config /home/a/.cloudflared/config.yml run tawa-local
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
# التفعيل
sudo systemctl daemon-reload
sudo systemctl enable --now cloudflared-tawa
# النتيجة:
Created symlink …/multi-user.target.wants/cloudflared-tawa.service ✅

ب) منع الجهاز من النوم/التعليق

السيرفر يجب ألّا "ينام". عُطِّلت كل أوضاع النوم على مستوى النظام:

sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
# النتيجة:
Created symlink …/sleep.target → /dev/null ✅ (والثلاثة الأخرى)

ج) إيقاف النفق اليدوي المؤقّت

بعد أن بدأت الخدمة الدائمة، أُوقف النفق اليدوي القديم (دون انقطاع، إذ تداخلت النسختان لحظيًّا):

pkill -f "cloudflared tunnel run tawa-local"
نتيجة المرحلة ٢ (مُتحقَّقة): الخدمة cloudflared-tawa أصبحت active + enabled؛ بقيت نسخة نفق واحدة فقط (نسخة الخدمة)؛ العملية اليدوية القديمة (1626966) ماتت؛ النوم/التعليق masked؛ والموقع ظلّ يردّ HTTP 200 طوال العملية.

٥ المرحلة ٣: ربط test.tawanow.com بدل النطاق الرئيسي

المرحلة ٣

بطلبك: نقل سيرفر التجارب إلى نطاق فرعي مخصّص للتجارب، وتحرير النطاق الرئيسي للإنتاج لاحقًا.

أ) تعديل إعداد النفق (قبل / بعد)

قبل — يخدم النطاق الرئيسي 
# config.yml (قبل)
ingress:
  - hostname: tawanow.com
    service: http://localhost:8090
  - hostname: www.tawanow.com
    service: http://localhost:8090
  - service: http_status:404
بعد — يخدم نطاق التجارب فقط 
# config.yml (بعد)
ingress:
  - hostname: test.tawanow.com
    service: http://localhost:8090
  - service: http_status:404

ب) إنشاء سجلّ DNS للنطاق الفرعي

cloudflared tunnel route dns tawa-local test.tawanow.com
# النتيجة (2026-06-25T07:29:38Z):
INF Added CNAME test.tawanow.com which will route to this tunnel

ج) إعادة تشغيل الخدمة لتحميل الإعداد الجديد

sudo systemctl restart cloudflared-tawa   # → active
نتيجة المرحلة ٣ (مُتحقَّقة): test.tawanow.com ردّ HTTP 200 من أول محاولة (وفحص خارجي مستقلّ عرض «تووا | Tawa»)، بينما tawanow.com صار يردّ HTTP 404 (لم يعد يخدم سيرفر التجارب).

٨ الحدود والملاحظات المهمّة

شرطان فيزيائيّان (طبيعة السيرفر المنزلي):
  • ⚡ يجب أن يبقى جهازك مشغّلًا ومتّصلًا بالإنترنت. لو انقطعت كهرباء/إنترنت بيتك، يسقط الموقع حتى عودتها (الحاويات والنفق يعودان وحدهما عند التشغيل).
  • 🏠 لذلك هو ممتاز للتجارب، أمّا الإنتاج الحقيقي ٢٤/٧ فيبقى الأنسب له هتزنر أو ليبيان سبايدر (كما في تقريرَي الاستضافة في نفس المجلّد).
عن النطاق الرئيسي tawanow.com: سجلّه ما زال موجودًا في Cloudflare لكنّه يردّ 404 (لأنّ النفق لم يعد يخدمه). هو الآن حرّ: عند نشر الإنتاج تُعيد توجيهه للسيرفر الإنتاجي. إن أردت ألّا يظهر 404 إطلاقًا، يُحذف سجلّه من لوحة Cloudflare (يتطلّب توكن API أو الدخول للوحة).
تحسين اختياري لأقصى ثبات: وصل جهازك بـ UPS (بطارية احتياطية صغيرة) لحمايته من انقطاعات الكهرباء القصيرة — فيقترب أكثر من سلوك سيرفر حقيقي.

🏁 الخلاصة

حوّلتُ جهازك المنزلي من "موقع معلّق على عملية يدويّة هشّة" إلى سيرفر تجارب دائم يعمل من الإنترنت العام على https://test.tawanow.com: نفق دائم (systemd) يُصلح نفسه ويبدأ مع الإقلاع، نوم معطّل، حاويات ذاتية الإقلاع، عنوان الجهاز مخفيّ، والنطاق الرئيسي مُحرَّر للإنتاج. جاهز لتجاربك الآن.

منهجية التقرير: كل قيمة هنا مأخوذة من تنفيذ فعلي ومن مخرجات فحص مباشرة خلال جلسة العمل (حالة الحاويات، حالة خدمة systemd، نتائج curl الخارجية، وفحص مستقلّ من شبكة خارجية). لا توجد أرقام مفترضة.
