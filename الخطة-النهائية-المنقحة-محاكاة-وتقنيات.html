مسار DELETE للصلاحيات — إصلاح «تعذّر تنفيذ العملية» عطب مؤكّد

التغيير الدقيق
@router.delete("/me/staff/{staff_user_id}/permissions/{permission}", status_code=204)
async def clear_staff_permission(staff_user_id, permission,
    user = Depends(require_provider_permission("provider_staff:manage_permissions")),  # F1: المالك يمرّ
    db = Depends(get_db)):
    # 1) ABAC: نفس فحص _staff_of_my_store  2) remove_override  (idempotent)
    await _perm.remove_override(db, user_id=staff_user_id, permission=permission)  # :517 جاهزة
بديل بلا URL-encoding: تعديل clearPermission إلى POST effect="REVOKE". المعتمد: DELETE (يُعيد للأساس بدل REVOKE دائم).
تقنية: DELETE عديم-الأثر (idempotent) يُعيد 204 No Content، والواجهة تستخدم TanStack optimistic (المربّع يُلغى فورًا ثم يُثبَّت).
#سيناريو بناءالمتوقّع
B1الصلاحية تحوي «:» (provider_order:accept)ترميز URL يُفكّ صحيحًا في path param
B2نسيان فحص ABACثغرة عبر-المتاجر → إلزام _staff_of_my_store
B3نسيان إبطال كاش acctperm:*صلاحية «شبح» تبقى 60ث → remove_override يبطله
#سيناريو تشغيلالمتوقّع
R1مالك يزيل صلاحية ممنوحة204 + تختفي فورًا (optimistic)
R2مالك متجر آخر يحاول الإزالة404/403 (ABAC)
R3إزالة صلاحية غير ممنوحة أصلًا204 (idempotent، لا خطأ)
R4إزالة صلاحية Tier-Sمرفوض (غير قابلة للمنح أصلًا)
R5فشل الشبكة أثناء الإزالةrollback: المربّع يعود مؤشَّرًا + رسالة
R6موظّف موقوف حاليًا تُزال صلاحيتهينجح (الإيقاف منفصل عن الصلاحيات)
تمّ عندما: منح/إزالة أي صلاحية يعملان دون خطأ، مع اختبارات R1–R6 خضراء، والكاش يُبطَل.
