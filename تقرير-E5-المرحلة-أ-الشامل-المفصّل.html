① الخلاصة التنفيذيّة

أُنجزت المرحلة أ من E5 بالكامل ونُشِرت حيًّا على tawanow.com وتحقّقت بالصور. الميزة دفاع استشاريّ عن هجمات التقديم (Presentation-Attack Defence / liveness) لوثائق الهويّة في KYC، مبنيّ كـهيكل خامل مضبوط بالإعدادات (Dormant config-gate) على نمط FCM/Geofence المعتمد في المشروع.

  • خامل افتراضيًّا: بلا مزوّد مُعرَّف (doc_verify_vendor="") ⇐ كلّ وثيقة جديدة تُسجَّل نتيجتها SKIPPED — لم يُفحَص بلا أيّ نداء خارجيّ ولا مغادرة أيّ صورة للمنصّة.
  • استشاريّ غير حاجب (fail-open): التحقّق لا يحجب إنشاء أو اعتماد الوثيقة إطلاقًا؛ ولا يرفع استثناءً إلى مُستدعيه.
  • هويّة لا مال: لا مساس بالقلب الماليّ ⇒ FIN-COR PASS طوال البوّابة والنشر.
  • إضافيّ بحت متوافق رجعيًّا: جدول مستقلّ جديد، لا أعمدة على نماذج الوثائق، لا تغيير سلوك لأيّ تدفّق قائم.

② القرار المعماريّ والمحاكاة الذهنيّة

قبل البناء أُجري فحص كود + بحث تقنيّ 2026 + محاكاة ذهنيّة استخرجت ثلاثة قرارات حاكمة:

المُعرِّفالاكتشافالقرار المُطبَّق
SIM-E5-A1 إضافة أعمدة تحقّق على AgentDocument/DriverDocument/ProviderDocument تكرّر المخطّط وتلمس ثلاثة نماذج. جدول مستقلّ واحد document_verifications يحمل النتيجة لأيّ نوع وثيقة عبر doc_kind، دون لمس أيّ نموذج وثيقة.
SIM-E5-A2 التعليق على /files/upload يلتقط رفعًا خامًا قد لا يصير وثيقة رسميّة. المُطلِق عند إنشاء الوثيقة (add_document) لا عند الرفع — يطابق دورة حياة الوثيقة الفعليّة.
SIM-E5-INJECT هجمات الحقن (كاميرا افتراضيّة/تزييف عميق، +783% في 2024) لا يمنعها تقييم صورة مخزَّنة من جهة الخادم. المرحلة أ = دفاع تقديم فقط؛ الدفاع عن الحقن يحتاج SDK جهة العميل وقت الالتقاط = المرحلة ب (مُوثَّق صراحةً في كود الخدمة).

def is_enabled() -> bool:
    return bool((getattr(settings, "doc_verify_vendor", "") or "").strip())

async def queue_document_verification(db, *, doc_id, doc_kind, doc_type, object_key):
    rec = DocumentVerification(id=..., doc_id=doc_id, doc_kind=doc_kind,
          doc_type=doc_type, object_key=object_key, status="SKIPPED", created_at=now)
    if is_enabled():
        rec.vendor = settings.doc_verify_vendor.strip()[:40]
        try:
            result = await _run_vendor(object_key)

        except Exception:           # استشاريّ: فشل المزوّد لا يحجب أبدًا
            rec.status = "ERROR"
    db.add(rec); return rec

⑪ السلامة والحدود

  • القلب الماليّ: لا مساس — هويّة لا مال؛ FIN-COR PASS طوال البوّابة والنشر.
  • إضافيّ / متوافق رجعيًّا: جدول مستقلّ جديد، لا أعمدة على نماذج الوثائق، لا تغيير سلوك لأيّ تدفّق قائم.
  • fail-open: queue_document_verification لا يرفع داخل المُستدعي؛ مزوّد مُعرَّف بلا مُحوِّل ⇒ ERROR غير حاجب.
  • الخصوصيّة: خامل ⇒ لا تغادر أيّ صورة المنصّة؛ لا نداء خارجيّ إطلاقًا حتى التفعيل.
  • الحوكمة: بلا commit (نموذج مرحليّ) · رأس المستودع aa29.

⑫ نقطة التفعيل المستقبليّة (المرحلة ب — بإذنك)

  • تعيين DOC_VERIFY_VENDOR لاسم مزوّد (Incode / Paravision / …) بعد اجتياز بوّابة الخصوصيّة.
  • تنفيذ _run_vendor(object_key): قراءة الصورة من MinIO ← نداء PAD API للمزوّد ← إرجاع {score: 0..100, flags}.
  • للدفاع عن هجمات الحقن: SDK جهة العميل وقت الالتقاط (تقييم الصورة المخزَّنة وحده لا يكفي).
  • تبقى النتيجة استشاريّة دومًا (لا تحجب الاعتماد) ما لم يُقرَّر غير ذلك صراحةً.
