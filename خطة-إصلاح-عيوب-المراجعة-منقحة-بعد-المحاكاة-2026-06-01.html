3) R-2 — صفحة 404 متوسط

الحالة الفعليّة (مُصحَّحة)

قرار التصميم (D-5) — محسوم

أضع المسار داخل children الـ/ لكن بلا ProtectedRoute (عامّ، يظهر للضيف والمسجّل) ليحصل على قشرة Layout (هيدر/تنقّل) = أنظف UX:

web/src/router.tsx  (داخل children الفرع "/")
+ { path: "*", element: <NotFoundPage /> }   // آخر child، بلا ProtectedRoute
web/src/pages/NotFoundPage.tsx (جديد، نظام التصميم لا Tailwind)
+ رسالة "الصفحة غير موجودة 404" + زر "العودة للرئيسية" (Link to="/")
🧠 محاكاة: مسار معرّف → كالعادة. مسار مجهول تحت / → Layout + NotFoundPage. مسار مجهول top-level (مثل /xyz): React Router يطابق الفرع / (path="/" يطابق كبادئة) ثمّ child * → 404 داخل القشرة ✓. خطر: لو وُضع * على المستوى الأعلى (أخو /welcome) يلتقط كل شيء قبل أن يصل / children → يحجب التطبيق. خطر Tailwind: الذاكرة تؤكّد Tailwind غير مُهيّأ → يجب نظام التصميم (.btn/.card/tokens) لا أصناف Tailwind وإلا صفحة بلا تنسيق.
✓ التخفيف: المسار آخر child داخل / (لا top-level). NotFoundPage بنظام التصميم. اختبار Vitest: مسار مجهول يعرض «404»، مسار معرّف لا يتأثّر. frontend فقط · لا backend · nginx fallback يبقى.
