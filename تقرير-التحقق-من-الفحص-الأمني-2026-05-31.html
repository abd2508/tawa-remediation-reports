1) OpenAPI / Swagger — FALSE POSITIVE

الادّعاء

«/docs، /openapi.json، /swagger متاحة للعامة — تكشف كل endpoints»

الواقع

الـ4 مسارات كلّها تَرجع 200 OK — لكنّ الجسد نَفسه:

$ curl -s https://tawanow.com/docs | md5sum

$ curl -s https://tawanow.com/ | md5sum

$ curl -s https://tawanow.com/random-path-xyz | md5sum

$ curl -o /dev/null -w '%{http_code}' https://tawanow.com/api/openapi.json

app = FastAPI(

الحُكم

الـSwagger UI و OpenAPI JSON مَحظوران فِعلاً في الإنتاج. ما رآه المُفتِّش هو الـSPA fallback لأيّ مَسار غَير مَوجود. الـAPI ذاته (تَحت /api/) يَرجع 404 صَحيحاً.

الخطورة الفِعلية: صفر. لا حاجة لِفعل شيء.

2) JWT HS256 — صَحيح، الخطورة مُبالَغ فيها

الادّعاء

«JWT HS256 (متماثل) — نفس السر للتوقيع والتحقق. لو تسرب السر، أي شخص يزور أي دور»

الواقع

الـheader مَفكوكاً:

$ python -c "import base64,json; print(json.dumps(json.loads(
    base64.urlsafe_b64decode(TOKEN.split('.')[0] + '=='))))"
{"alg": "HS256", "typ": "JWT"}                  ← مَؤكَّد HS256

الإعداد:

# backend/app/config.py:49
jwt_algorithm: str = "HS256"

التَّقييم الدَّقيق

المُفتِّش مُحقّ تَقنياً: HS256 يَستخدم نَفس السرّ للتَّوقيع والتَّحقّق. لكنّ الخطورة تَعتمد على المعمار:

السيناريوHS256 مَلائم؟
تَطبيق monolithic (FastAPI واحد) — السرّ في environment variable واحد✅ نَعم — مَلائم وآمن (هذا هو tawa)
microservices مُتعدّدة تَتحقّق من الـtoken بِمفاتيح عامّة❌ يَجب RS256
تَفويض لِطَرف ثالث (OAuth provider)❌ يَجب RS256

tawa monolithic — السيرفر الذي يُصدر الـtoken هو نَفسه الذي يَتحقّق منه. HS256 صَحيح هَنا.

الـmitigations الموجودة في الكود:

  • الـjti field في الـtoken + Redis revocation list (rotation فِعليّ)
  • الـrole_status claim — لو طُرد المُستَخدِم، الـtoken يَفقد قيمته فوراً
  • صَلاحيّة 60 دَقيقة + refresh_token مع device-id binding
  • SECRET_KEY في environment variable، مَنوط بـSecrets Manager (P-205 staging deploy)

الحُكم

صَحيح تَقنيّاً، لكن الخطورة الفِعلية: 🟡 منخفضة (لا 🔴 عالية). الانتقال إلى RS256 يُحسِّن الـdefense-in-depth لكنّه ليس عاجلاً.

الإجراء المُوصى: رَفعه إلى backlog للمَرحلة المُقبلة، مع التَّركيز على تَدوير السرّ (secret rotation) كَأولويّة أَعلى من تَغيير الخَوارزمية.

3) Rate Limiting — جُزئيّاً صَحيح

الادّعاء

«تسجيل ودخول بدون حدود — brute force ممكن»

الواقع — يوجد rate limiter لكنّه ضَعيف على /auth/*

الكود يَحوي GlobalRateLimitMiddleware (Redis sliding-window، Phase 055):

# backend/app/core/rate_limiter.py
_WINDOW_SECONDS = 60
_MAX_REQUESTS_GENERAL = 180    ← 180 req/min على كل المسارات العامّة
_MAX_REQUESTS_OPS = 600          ← 600 req/min على /operations/

def _bucket_for(path):
    if path.startswith(_OPS_PREFIXES):
        return "ops", _MAX_REQUESTS_OPS
    return "general", _MAX_REQUESTS_GENERAL    ← /auth/* تَحت general

هذا يَعني: /auth/login مَحدود بـ180 محاولة/دَقيقة من نفس الـIP. حَدّ معقول لـAPI عامّ، لكن متساهل لـauth.

اختبار حَيّ — 50 طَلب login مُتوازي في ثانية واحدة:

50 requests in 0s ⇒ 50× 401  (zero 429)
                  ⇒ Retry-After header: empty
                  ⇒ X-RateLimit-Limit header: empty

الـcontract YAML (contracts/rate_limits.yaml) يَنصّ على سياسة أصرم لـauth:

otp_request:
  windows:
    - window: "10m", max: 3
    - window: "1h",  max: 6
otp_verify:
  window: "15m", max: 5

لكنّ هذه السياسة غَير مُطبَّقة فِعلياً في الـMiddleware — الـMiddleware يَستخدم حَدّاً عامّاً واحداً.

المخاطر الفِعلية

  • Credential stuffing بـ180/دَقيقة من 100 IP = 18,000/دَقيقة محاولة على حساب واحد. قَابل لِلاستغلال.
  • OTP brute-force: 6 أرقام = 10^6 احتمال. بـ180/دَقيقة من 100 IP = 18K/دَقيقة ⇒ كَشف خِلال دَقائق.

الحُكم

صَحيح جُزئياً — يُوجد rate limiter لكنّه فَضفاض على endpoints الحَسّاسة. الخطورة الفِعلية: عالية

الإصلاح المُقترَح (Pri-1)

  1. إضافة bucket مُنفصل في الـmiddleware لـauth: /auth/login, /auth/otp/verify, /auth/password-reset/confirm ⇒ 5/15دَقيقة لكلّ IP+phone.
  2. إضافة X-RateLimit-* headers على كلّ response (لا فقط 429).
  3. تَوسعة المفتاح: phone+device_id+ip لـauth بَدلاً من IP فَقط.
  4. Test pin: محاولة سادسة تَفشل وتَرجع 429 + Retry-After.

4+6) User Enumeration — صَحيح للـ/register فَقط

الادّعاء

«رسائل الخطأ تكشف إذا كان الهاتف مسجلاً أم لا»

الواقع — مَكشوف في /register فَقط

register مع هاتف مَوجود:

HTTP 409
{
  "code": "CONFLICT",
  "message_ar": "رقم الهاتف مسجل مسبقًا",
  "details": {"field": "phone"}                  ← مُؤكَّد: الهاتف مَوجود
}

register مع هاتف جَديد:

HTTP 201
{ "user_id": "...", "role": "CUSTOMER", "message": "Account created successfully." }

login مع كَلمة مرور خاطئة لهاتف مَوجود:

HTTP 401
{ "code": "UNAUTHORIZED", "message_ar": "بيانات الدخول غير صحيحة", "details": null }

login مع هاتف غَير مَوجود:

HTTP 401
{ "code": "UNAUTHORIZED", "message_ar": "بيانات الدخول غير صحيحة", "details": null }   ← مُماثلة بالضبط

التَّفصيل

المساركَشف؟تَعليق
/auth/register✗ نَعم — مَكشوف409 vs 201 يُميِّز الهاتف المَوجود
/auth/login✓ لا — مُحَصَّن401 مُوحَّد لكلتا الحالتَين، رسالة عربية مُوحَّدة، details:null
/auth/password-reset/request(لم يُختبَر)يَجب فَحصه — يَجب أن يَرجع 200 صامتاً للهاتف غَير المَوجود

الحُكم

صَحيح للـ/register، لكن الـ/login محميّ بالفعل. الخطورة: متوسّطة. الـ/register بطَبيعته يَكشف (لا يُمكن تَسجيل هاتف مَوجود) — لكنّ الـ409 يُفصِح أكثر مما يَجب. يَجب توحيد الاستجابة.

الإصلاح المُقترَح (Pri-2)

  1. /auth/register يُرجع صامتاً 200 لِكِلتا الحالتَين (مَوجود/جَديد) + يُرسل OTP إن كان مَوجوداً يَطلب recovery، وإلّا يُكمل التَّسجيل. هذا نَمط Twilio/AWS.
  2. أو على الأقلّ توحيد رَسالة الـ409 إلى «المُحاولة فَشلت» بِلا تَلميح للسبب.
  3. /auth/password-reset/request يَجب أن يَرجع 200 دائماً (لا تَلميح لِوجود الهاتف).

5) Security Headers — 5/6 مَوجودة · HSTS فَقط مَفقود

الادّعاء

«لا CSP، لا HSTS، لا Referrer-Policy»

الواقع — الـheaders الفِعلية من tawanow.com

$ curl -D - https://tawanow.com/

X-Frame-Options: DENY                                ✓
X-Content-Type-Options: nosniff                       ✓
Referrer-Policy: strict-origin-when-cross-origin     ✓ (المُفتِّش قال غَير مَوجود — خَطأ)
Content-Security-Policy:                              ✓ (المُفتِّش قال غَير مَوجود — خَطأ)
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  font-src 'self';
  connect-src 'self';
  frame-ancestors 'none';
Permissions-Policy: geolocation=(self), microphone=(), camera=(self)  ✓

Strict-Transport-Security:                            ✗ ABSENT (المُفتِّش مُحقّ)

التَّفصيل

الـheaderالادّعاءالواقع
CSPغَير مَوجودمَوجود مع 7 directives (default-src 'self' + frame-ancestors 'none')
HSTSغَير مَوجودغَير مَوجود فِعلاً
Referrer-Policyغَير مَوجودمَوجود: strict-origin-when-cross-origin
X-Frame-Options—DENY ✓
X-Content-Type-Options—nosniff ✓
Permissions-Policy—geolocation=(self), camera=(self), microphone=() ✓

سَجَل الإضافة في الـnginx.conf:

# web/nginx.conf:8-15
add_header X-Frame-Options DENY always;
add_header X-Content-Type-Options nosniff always;
add_header Referrer-Policy strict-origin-when-cross-origin always;
add_header Content-Security-Policy "default-src 'self'; ..." always;
add_header Permissions-Policy "geolocation=(self), microphone=(), camera=(self)" always;
# Strict-Transport-Security omitted: requires HTTPS/TLS termination (BLOCK-03).

التَعليق في الـnginx.conf يُؤكّد أنّ HSTS مُؤجَّل عَن قَصد — هَناك BLOCK-03 يَنتظر TLS termination قَبل تَفعيله.

الحُكم

المُفتِّش أخطأ في 2/3 من الادّعاءات. CSP و Referrer-Policy مَوجودان. HSTS فَقط مَفقود — وَهذا مَوثَّق و معلوم.

خطورة HSTS: متوسّطة — TLS مُفعَّل، لكنّ HSTS يَزيد المَناعة ضدّ SSL-strip attacks في public WiFi.

الإصلاح المُقترَح (Pri-2)

# web/nginx.conf
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;

تَحذير: preload + 63072000 (سَنتان) غَير قابل للإلغاء سَهلاً. يَنبغي البَدء بـmax-age=300 (5 دَقائق)، التَحقّق، ثم رَفعه. وَتَجاهل preload حتى استقرار TLS تَماماً.

7) /api/auth/me — FALSE POSITIVE — قرار تَصميميّ

الادّعاء

«/api/auth/me معطوب — يرجع 404»

الواقع

GET /api/auth/me        → 404                    ← هذا الـpath لا يُوجد
GET /api/customer/me    → 401                    ← مَوجود + يَطلب auth
GET /api/users/me       → 404

tawa لا تَستخدم النَّمط الـRFC-style /auth/me. بَدلاً منه، يَستخدم role-scoped endpoints:

  • /api/customer/me — للعَملاء
  • /api/provider/me — للمزوّدين
  • /api/driver/me — للسائقين
  • /api/operations/me — لطاقم العمليات

هذا نَمط تَصميميّ مَقصود يُحقّق:

  1. Defense-in-depth: كلّ endpoint يَتحقّق من الدور بالـauth dependency.
  2. أنواع رَدّ مُختلِفة: كائن العميل != كائن المزوّد != كائن السائق. لو وُجدت /auth/me مُوحَّدة لـتَطلَّبت polymorphic response.
  3. سَطح تَهديد أَضيق: المُهاجم لا يَستطيع استخدام /auth/me كأداة كَشف لِنوع الحساب.

الحُكم

الـ404 صَحيح ومَقصود. ليست ثَغرة، بل قرار معماريّ. لا حاجة لِفعل شيء.

هذا في الواقع أكثر أَماناً من النَّمط الـ/auth/me: لا يَكشف الـrole للأنونيمي.

9) ما لم يَفحَصه المُفتِّش الأصليّ

الفَحص الأصليّ لم يَلمس الطَّبقات التالية التي هي أكثر أهمّيّة لِمَنصة دَفع:

  • FIN-COR seal: production_payment_enabled + wallet_cash_out + wallet_peer_transfer كلّها SEALED-False في contracts/feature_flags.yaml. شَحن المحفظة الفِعليّ مَحجوب على tawanow.com (تَمّ نَشره اليَوم).
  • idempotency: كلّ نقطة money-moving تَتطلّب Idempotency-Key header (cash_collection, delivery_proof, dispatch_offer/decision).
  • JWT jti + Redis revocation: token rotation فِعلاً مُفعَّل (Phase 369).
  • OPS isolation: /ops bundle مَنفصل تماماً (Phase 377). حِزمة العميل لا تَحوي كود OPS.
  • SSE auth: token-in-querystring لـSSE مَع طَبقة Redis pub/sub.
  • F-W-01 SEAL (يَوم 2026-05-31): شَحن المحفظة الآن مَحجوب بِـSEAL يَمنع تَكوّن رَصيد مِن العَدم.

هذه الطَّبقات قَائمة وتَعمل، وَتُغلق نَواقل تَهديد أكبر بكَثير من البُنود السبعة التي ذَكرها المُفتِّش.

10) الحُكم النِّهائيّ

الفَحص الأصليّ عَثَر على 2 ثَغرة حَقيقية ⇒ rate-limit ضَعيف على /auth + غِياب HSTS. هاتان تَستحقّان الإصلاح. لكنّه أَطلق إنذاراً كاذباً على 3 بُنود مَحلولة بالفعل (Swagger، CSP، Referrer-Policy)، وَصَنَّفَ سُلوكاً تَصميمياً سَليماً كَثَغرة (/auth/me).

التَّقييم الأصليّ ذَكر 5 بُنود «عالية/متوسّطة الخطورة»؛ الواقع: 1 عالية فَقط (rate-limit auth) + 1 متوسّطة (HSTS). البَاقي إمّا مَخفّف، أو مَوجود مُسبَقاً، أو سُوءُ تَفسير.

التَّوصية: اعتَمد فَقط P1 + P2 + P3 من القائمة أعلاه. تَجاهل البَند 1 (Swagger) و7 (/auth/me) — لا أساس لهما.

نهاية التَّحقُّق العَميق — مَبنيّ على فَحص حَيّ لـ7 endpoints + قراءة 5 ملفّات كود (config.py، main.py، rate_limiter.py، nginx.conf، feature_flags.yaml) + Redis observation + JWT decode + md5 comparison.
الإصلاحات تَنتظر إذنك للبَدء.
