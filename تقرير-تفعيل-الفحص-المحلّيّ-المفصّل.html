① الخلاصة

بإذنك «فعّل الفحص المحلّيّ» — فعّلتُ المُحوِّل المدمج (E5 المرحلة ب) على الإنتاج تفعيلًا دائمًا. انتقل النظام من خامل (SKIPPED) إلى عامل: الآن كلّ وثيقة KYC جديدة (AGENT/DRIVER/PROVIDER — المُطلِق موصول للثلاثة) تُقيَّم حيًّا داخل المنصّة بالكامل، استشاريًّا غير حاجب.

قبل
is_enabled=False — كلّ وثيقة SKIPPED «🔍 لم يُفحَص»
بعد
is_enabled=True · vendor=local — كلّ وثيقة جديدة DONE «🔍 درجة N»
الطبيعة
سلامة/جودة الصورة داخل العمليّة — لا نداء خارجيّ · لا مفتاح API · لا بوّابة خصوصيّة
القلب الماليّ
لا مساس — FIN-COR PASS · بلا migration/كود

② آليّة التفعيل (دائم يبقى عبر النشر)

مصدر إعدادات الباكند الحيّة = docker-compose.staging.yml (environment:). أُضيف المفتاح هناك (محليًّا و رُفع للريموت)، فيبقى التفعيل عبر عمليّات النشر القادمة (deploy_web.sh يرفع الـoverlay). 

# docker-compose.staging.yml → backend-core.environment (السطر 45)
DOC_VERIFY_VENDOR: "local"   # reversible: احذف السطر للعودة للخمول
تحرير الـoverlay (محليّ)← scp للريموت /home/deploy/platform← إعادة إنشاء backend-core (بلا rebuild)← is_enabled=True · vendor='local'
الخطوةالنتيجة
رفع الـoverlay المُحدَّثDOC_VERIFY_VENDOR: "local" في الريموت (السطر 45)
إعادة إنشاء الحاويةbackend-core صحّية + التقطت الإعداد الجديد
تأكيد التفعيلis_enabled = True · doc_verify_vendor = 'local'
الديمومة عبر النشرالـoverlay في الريبو المحليّ أيضًا ⇒ يرفعه deploy_web مستقبلًا

③ التحقّق الحيّ بالصور على tawanow.com

أنشأتُ صورتين حقيقيّتين في MinIO، وأضفتُ وثيقتين عبر درج وثائق مندوب اختباريّ في OPS — فقُيِّمتا فورًا بالمُحوِّل النشط:

الوثيقةالصورة (MinIO)النتيجة الحيّة
LICENSEgood.png (800×600، 442KB)DONE · 🔍 درجة 100 · flags=None
NATIONAL_ID_FRONTlowres.png (110×110)DONE · 🔍 درجة 55 · flags=LOW_RESOLUTION
حيّ على tawanow.com: الشارة صارت «🔍 درجة 100» و«🔍 درجة 55» (بدل «🔍 لم يُفحَص» الخامل) — المُحوِّل النشط ميّز الجودة.

④ تأكيد قاعدة البيانات

  good.png   → status=DONE  score=100  flags=None            vendor=local
  lowres.png → status=DONE  score=55   flags=LOW_RESOLUTION  vendor=local

صفوف document_verifications أُنشئت بـ status=DONE وvendor=local ودرجات حقيقيّة — برهان أنّ التقييم الحيّ جرى فعلًا (لا SKIPPED).

⑤ التنظيف وبقاء التفعيل

الفعلالنتيجة
حذف وثيقتَي العرض + تحقّقيهماagent_documents=0 · document_verifications=0
حذف صورتَي MinIOe5local/* فارغ تمامًا
التفعيل بعد التنظيفis_enabled = True (باقٍ — حذفتُ بيانات العرض فقط، لا الإعداد)
الحاوياتbackend · web · minio — كلّها صحّية
✅ التفعيل دائم ومُتحقَّق حيًّا بالصور (good→100 · lowres→55)، وبيانات العرض نُظِّفت دون أثر، والتفعيل باقٍ. ما بُني في E5 صار يعمل فعليًّا: يُقيّم جودة وثائق KYC استشاريًّا لمراجِع OPS.

⑥ السلامة والعكس

  • استشاريّ / غير حاجب: الدرجة لا تحجب اعتماد الوثيقة؛ أيّ خطأ ⇒ ERROR غير حاجب (fail-open).
  • الخصوصيّة: محلّيّ بالكامل — لا تغادر أيّ صورة المنصّة، لا نداء خارجيّ، لا حاجة لبوّابة خصوصيّة.
  • config فقط: لا تغيير كود/migration · FIN-COR PASS (العقود غير ممسوسة) · بلا commit.
  • قابل للعكس فورًا: حذف سطر DOC_VERIFY_VENDOR من الـoverlay + إعادة إنشاء backend ⇒ يعود خاملًا (SKIPPED).
  • المستقبل: الكشف الحقيقيّ بالـML (مزوّد خارجيّ) يبقى بإذنك بعد بوّابة الخصوصيّة/DPA.
