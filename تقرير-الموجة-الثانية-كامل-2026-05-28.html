الجزء 2 — ماذا يَحدث الآن إذا جرّبتَ التَدفّق

لأن الخادم في وضع EMAIL_OTP_PROVIDER=log، تَدفّق الـ«تَأكيد البريد» يَعمل كاملاً لكن رمز OTP يُطبع في سجلّات الخادم بدل أن يَصل إيميلاً.

الخطوة 1: تَدخل tawanow.com → تُسجِّل دخولك (هاتف + OTP كالمعتاد) الخطوة 2: ⚙️ الإعدادات → قسم «الملف الشخصي» الخطوة 3: تَرى الآن: ┌────────────────────────────────────────────────┐ │ 🔐 تأكيد البريد اختياريّ لكنه مهمّ — │ │ لاسترجاع حسابك إذا فقدتَ هاتفك. │ │ │ │ أَدخل بريدك: │ │ ┌──────────────────────────────────────┐ │ │ │ you@example.com │ │ │ └──────────────────────────────────────┘ │ │ │ │ [ إرسال رمز التحقق ] │ └────────────────────────────────────────────────┘ الخطوة 4: تَضغط الزر → الخادم يولّد OTP=4729 ويَطبعه في سجلّاته: EMAIL_OTP_LOG to=karam@gmail.com subject=رمز تأكيد بريدك — تووا BODY: مرحباً، رمز تأكيد بريدك في تووا: 4729 ... الخطوة 5: الواجهة تَنتقل لِشاشة إدخال الرمز: ┌────────────────────────────────────────────────┐ │ أَدخل الرمز الذي أرسلناه إلى k***m@gmail.com │ │ ┌──────────────────────────────────────┐ │ │ │ 4 7 2 9 _ _ │ │ │ └──────────────────────────────────────┘ │ │ [ تأكيد البريد ] │ │ إعادة إرسال بعد 58ث │ └────────────────────────────────────────────────┘ الخطوة 6: لكن... لا إيميل يَصل! (لأن الخادم في وضع log) لاستخراج الـOTP يدوياً: SSH للخادم ثم: docker logs tawa-backend-core-1 | grep EMAIL_OTP_LOG | tail -1 الخطوة 7 (لو أَدخلتَ الرمز الصحيح): ✅ يَظهر شارة «تَمّ تأكيد بريدك ✓»

⚠️ الخلاصة: الكود يَعمل 100%، لكن الإيميل الفعلي لا يَصل المستخدم. لِجَعله يَصل = مفتاح Resend + 3 سجلّات DNS في Cloudflare = ما أَحتاجه منك في الجزء التالي.

الجزء 3 — ما الذي حدث مع مفتاح Cloudflare الذي أعطيتَه

❌ المفتاح مَرفوض من Cloudflare
المفتاح الذي وَصلني: cfk_A3HIQel8jOyHI2UcT5h11cN98qq7KwRfIqjdbuq80f5cd485
عند اختباره مع Cloudflare API ردّت: {"success":false,"errors":[{"code":1000,"message":"Invalid API Token"}]}
جرّبتُ مع البادئة cfk_ وبدونها — كلاهما مَرفوض.

السبب المحتمل

  • بادئة cfk_ ليست بادئة Cloudflare API Tokens المعروفة (التي عادةً 40 حرف مختلط بدون بادئة).
  • ربما نَسختَ المفتاح من قسم آخر (Workers KV / R2 / Pages) لا يَعمل مع DNS.
  • أو المفتاح قُيِّد بأذونات لا تَشمل تَعديل DNS.
  • أو لربّما حُذف بعد إنشائه (للأمان).

كيف تُولّد مفتاحاً صحيحاً (دقيقتان)

1افتح dash.cloudflare.com

سَجِّل دخولك بنفس الحساب الذي اشتريتَ منه الدومين.

2اضغط أيقونة الملف الشخصي يمين أعلى

القائمة تَنزل → اختر «My Profile».

3التَبويب «API Tokens» → «Create Token»

قائمة من القوالب الجاهزة. اختر «Edit zone DNS» (الأبسط لما نحتاج).

4حدِّد المجال

في خانة Zone Resources ← Include ← Specific zone ← tawanow.com فقط. ولِأمان أكبر، أَضِف بـ«Permissions»:

  • Zone ← DNS ← Edit (الافتراضي)
  • Zone ← Email Routing Addresses ← Edit (لو أردنا تَفعيل Cloudflare Email Routing لاحقاً)

5Continue → Create Token → انسخ المفتاح

المفتاح سيَظهر مرّةً واحدةً فقط (40-حرفاً بدون بادئة cfk_). انسخه وأرسله لي.

الجزء 4 — ماذا أحتاج منك بالضبط (3 أشياء فقط)

تَفصيل الأمر #2 و#3 — حساب Resend (5 دقائق)

1سَجِّل في resend.com

افتح https://resend.com/signup → بإيميلك الشخصي → فعّل الحساب من رابط التَأكيد.

2أَضِف الدومين tawanow.com

في لوحة Resend → Domains → Add Domain → اكتب tawanow.com → اختر منطقة (US-East الافتراضية ممتازة).

3انسخ السجلّات الثلاثة التي يُعطيك

سيَظهر جدول مثل هذا — انسخه كاملاً وأرسله لي:

resend.com — Domains → tawanow.com
TypeNameValue
TXTsend.tawanow.com"v=spf1 include:amazonses.com ~all"
CNAMEresend._domainkeyresend._domainkey.tawanow.com.dkim.resend.com
TXT_dmarc"v=DMARC1; p=none;"

ملاحظة: القيم الفعلية ستَختلف قليلاً عن المثال أعلاه — Resend يُولّد قيماً خاصّة بحسابك. لا تُعدِّل شيئاً، أرسل لي الجدول كما هو.

4أنشِئ API key

في لوحة Resend → API Keys → Create API Key → اسم: tawanow-production → Full Access → انسخ المفتاح فوراً (يَظهر مرّة واحدة، يَبدأ بـre_).

5أرسل لي الثلاثة في رسالة واحدة 
1. مفتاح Cloudflare:    [الـ40 حرفاً]
2. سجلّات Resend DNS:   [الجدول الذي ظَهر في الخطوة 3]
3. مفتاح Resend:        re_xxxxxxxxxxxxxxxx

الجزء 5 — ماذا أَفعل تلقائياً عندما تَصلني الثلاثة

لن تَفعل أنت شيئاً بعد إرسال الثلاثة. أنا أَتولّى الباقي:

Aأُضيف سجلّات Resend الثلاثة في Cloudflare

عبر Cloudflare API مُباشرةً (TXT + CNAME + TXT). يَستغرق ثوانٍ.

Bأَتحقّق من سجلّات DNS

أَنتظر Resend يَعترف بها (دقيقة على الأكثر).

Cأُحدِّث .env على الخادم 
EMAIL_OTP_PROVIDER=resend         # ← كان log
RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
EMAIL_FROM=noreply@tawanow.com
EMAIL_FROM_NAME=تووا
Dأُعيد تشغيل الخلفية

أمر واحد: docker compose restart backend-core — يَستغرق 10 ثوانٍ، الواجهة لا تَتأثّر.

Eنَختبر معاً

أَطلب منك أن تَدخل tawanow.com بحسابك، تَفتح الإعدادات، تَضغط «إرسال رمز التحقق» — الإيميل يَصلك في صندوقك خلال ثوانٍ برمز 6-أرقام. تُدخل الرمز → ✅ شارة مُؤكَّد.

F(اختياري) Cloudflare Email Routing

لو أردتَ أيضاً استلام رسائل أعمال على info@tawanow.com في صندوقك الشخصي، أُفعّلها بنقرة API. أَخبرني بـ«الإيميل الشخصي الذي تُريد التحويل إليه» وأَفعل.

تَحسينات أُضيفها أيضاً (لم تَطلبها صراحةً لكنها تَخدم المشروع)

  • تنبيه استرجاع الحساب — تَنبيه أصفر صريح في صفحة الإعدادات قبل البدء («اختياريّ لكن مهمّ — لاسترجاع حسابك إذا فقدتَ هاتفك»). تَنفيذ مباشر لطَلبك السابق.
  • OTP 6-أرقام مع تَنسيق وسطيّ كبير — UX مُتعرّف عليه من Instagram/Uber بدل token طويل غير مفهوم.
  • عدّاد cooldown 60 ثانية + زرّ «أعد إرسال» — يَمنع spam ويَعطي ثِقة بأن النِظام يَعمل.
  • سقف 5 طلبات/ساعة لكل مستخدم — حماية ضد brute-force + إغراق Resend.
  • إيميل عربي RTL منسّق — قالب HTML احترافي يَنفع للعلامة التجارية.
  • تَقنيع البريد في الواجهة (j***@gmail.com) — يُؤكّد الإرسال دون تَسريب البريد الكامل في الـscreen.
  • تَغيير البريد يَمسح حالة التَأكيد — لو أدخل المستخدم بريداً خاطئاً، تَغييره يُعيده لـunverified تلقائياً (آمن).
  • تَدفّق آمن للـtoken — استَعمل نمط module-level import inside function لضَمان أن اختبارات fakeredis تَعمل بدون الحاجة لـRedis حقيقية.
  • قابلية الـ1-line activation — switch إلى Resend = تَغيير سطر واحد في .env + إعادة تشغيل الحاوية. لا تَعديل كود.
  • قابلية تَبديل المُزوّد — لو احتجنا AWS SES أو Mailgun لاحقاً، إضافة class جديد في email_provider.py = أقلّ من 50 سطر.
