W1-1 · إصلاح accept_timeout sweep dormant failure

العيب
الـsweep يَفشل كل دقيقة بـInFailedSQLTransactionError منذ ساعات (>100 مرّة/14س). السبب: SSE CancelledError يَترك asyncpg tx aborted ثم الـbackground job يَستعير الـconnection.
الملفّ
backend/app/main.py + backend/app/db/session.py
الإصلاح
الـsweep يَفتح engine منفصلاً (pool خاص به، لا يُشارك pool الـHTTP) عبر create_async_engine(settings.DATABASE_URL, pool_pre_ping=True, pool_recycle=900, poolclass=NullPool) + try/except InFailedSQLTransactionError → rollback → continue داخل الحلقة.
migration
لا
اختبار
اختبار جديد test_phase450_sweep_isolation.py: تَزييف cancelled tx على pool واحد + التأكّد أنّ الـsweep يُكمل على الـpool المنفصل. مراقبة logs staging لـ24 ساعة بعد النشر: 0 InFailedSQLTransactionError.
✓ القبول: لا خطأ accept_timeout sweep failed في logs ساعة كاملة بعد النشر · sweep يُسجّل «swept N stale orders» عند تَوفّر مرشّحين.
⚠ مخاطر: منخفضة — pool منفصل لـbackground هو نمط مَوثّق (FastAPI docs). NullPool يَفتح connection لكل sweep (مرّة كل دقيقة = مَقبول).
↶ rollback: revert تَغيير main.py وdb/session.py → سَلوك مثل اليوم (الـsweep يَفشل لكن لا يُسبّب خطأً حادّاً).
