الخطة المنقّحة بعد المراجعة العميقة

2026-05-30 · مراجعة دقيقة جدّاً للخطة الأصلية مقابل الكود الفعلي مع محاكاة ذهنية لكل خطوة. الإطارات الملوّنة تُبيّن إضافات، تصحيحات، وبنود أُسقطت.

منهج المراجعة (ما الذي تغيّر)

لكل بند فحصتُ المسار الفعلي في الكود (الملف:السطر)، حدّدتُ كل المستدعين، حاكيتُ السلوك أثناء البناء وأثناء التشغيل، وبحثتُ عن أثر جانبي خفيّ. النتائج الجوهرية:

  • عيب كود حقيقي اكتُشف (لم تذكره الخطة الأصلية): KYC-1.A — قائمة VALID_PROVIDER_DOC_TYPES تفتقد MEAT_HANDLING_PERMIT ⇒ الجزّار لا يستطيع رفع تصريحه الإلزامي (422).
  • الخطة الأصلية بالغت في تعقيد PROV-1 (تفعيل تلقائي عند توقيع العقد بشرط نشر صنف). محاكاة التدفّق الطبيعي (المزوّد يوقّع قبل النشر) كشفت أنّ هذا الشرط لن يتحقّق غالباً ⇒ تبسيط للتصميم.
  • PROV-2: الخلفية تُرجِع أصلاً رسائل دقيقة عبر validate_item_completeness؛ المشكلة الفعلية أنّ الواجهة لا تعرضها. تغيير نطاق الإصلاح.
  • D-5: ثلاث حالات «بلا سائق» لا واحدة (READY_FOR_PICKUP, AWAITING_DRIVER, NO_DRIVER_ESCALATION) — توسيع الشمول.
  • تقييمات (driver_id): المسار الساذج يولّد N+1 على قائمة الطلبات ⇒ يجب جلب جماعي.
  • API-3: لا اختبار يؤكّد 200 ⇒ تغيير 201 آمن.

الترميز اللوني أدناه يميّز كل تعديل عن الخطة الأصلية.

١) عالٍ PROV-1 — «افتح المتجر» بنقرة واحدة (مُبسَّط)

المحاكاة الذهنية أثناء التنفيذ

async def try_dispatch_to_newly_available(driver: Driver) -> Optional[DispatchOffer]:
    """Best-effort: when a driver flips to available, scan eligible orders within
    a radius and create ONE offer for the nearest. Fail-open."""
    if driver.current_lat is None or driver.current_lng is None: return None
    eligible_states = {"READY_FOR_PICKUP", "AWAITING_DRIVER", "NO_DRIVER_ESCALATION"}
    # candidate orders: in eligible state, no live SENT/ACCEPTED offer
    no_live_offer = ~exists(
        select(1).where(DispatchOffer.order_id == Order.id,
                        DispatchOffer.state.in_(("SENT","ACCEPTED")),
                        DispatchOffer.expires_at > now()))
    rows = await session.execute(
        select(Order, Provider.lat, Provider.lng)
        .join(Provider, Provider.id == Order.provider_id)
        .where(Order.order_state.in_(eligible_states),
               Provider.lat.isnot(None), Provider.lng.isnot(None),
               no_live_offer)
        .limit(50))
    # haversine ≤ 50 km, pick nearest, create_offer (which re-validates ACCEPTED + cash + cash_allowed)
