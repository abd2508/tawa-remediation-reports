١ المنهجيّة — كيف بنينا بأمان (لا إفساد)

بلغة بسيطة: قبل كتابة أيّ سطر، شغّلنا «محاكاة عدائيّة»: 5 خبراء افتراضيّين حاولوا كسر كلّ ميزة على الورق فاستخرجوا 66 خطأً محتملًا. ثمّ بنينا كلّ بند مع إصلاح أخطائه مسبقًا، واختبرناه، ونشرناه — بند-بند، لا دفعة واحدة.
عقد التنفيذ لكلّ بند: فحص كود (file:line) → إصلاح عيوب المحاكاة → هجرة PG (صعود+هبوط) → خلفيّة → واجهة → اختبارات (تقفل كلّ عيب) → بناء → نشر بإذنك → تحقّق حيّ. المبادئ الثابتة: المليم (لا /100) · FIN-COR مختوم · ABAC · PII عابرة · صفر تغيير سلوك (كلّ ميزة opt-in/خلف علَم).

١ البند 1 — «شارك موقعي الحيّ» + Plus Codes ✅

بلغة بسيطة: ليبيا بلا عناوين شوارع ⇒ يتوه السائق. الآن العميل يضغط «شارك موقعي» أثناء التوصيل فيرى السائق نقطته الحيّة + رمز موقع قصير مجّانيّ (Plus Code) يعمل بلا إنترنت. اختياريّ ومُطفأ افتراضيًّا.
تقنيًّا (أبرز التغييرات): أصلحنا العيب الحرج (order_tracking._event_visible_to: حدث+قناة customer.location للسائق فقط) · نقطة POST /customer/me/location/{id} بـ3 حرّاس + حدود إحداثيّات + Redis TTL (لا أعمدة — PII) · get_order_for_driver يعرض الدبّوس (حالة نشطة، fail-soft) · هجرة aa53 (عمود موافقة) · واجهة: مفتاح إعدادات + زرّ مشاركة + استطلاع 12ث + بطاقة السائق. اختبارات A2 6/6.
التقنية المضافة (بحث 2026): Google Plus Codes (Open Location Code) — مفتوح مجّانيّ بلا إنترنت، بديل what3words المدفوع. حلّ عمليّ لعنونة ليبيا.

٢ البند 2 — توسعة الفئات (صيدليّة/مياه/بقالة) ✅

بلغة بسيطة: أضفنا أنواع متاجر جديدة (صيدليّة 💊، مياه 💧، بقالة 🥬) بجانب (مطعم/مقهى/سوق/مخبز/جزارة). الذكيّ: التبويب الجديد يظهر للعميل فقط حين يوجد متجر فعليّ من نوعه — فلا تبويبات فارغة.
تقنيًّا: اكتُشِف أنّ البنية شبه جاهزة (فلتر النوع + نقطة الأنواع + تبويبات موجودة). أضفنا: 3 أنواع للتصنيف (provider_types.py + config/providerTypes.ts + i18n×3) + باراميتر active_only على /providers/types (يُرجِع الأنواع التي لها مزوّدون نشطون) + شريط HomePage ديناميكيّ. بلا هجرة (النوع عمود نصّ حرّ). اختبارات A3 3/3 + i18n parity 11/11.
التقنية المضافة (بحث 2026): الـQuick-commerce توسّعت لصيدليّة/تجميل/إلكترونيّات — التوسعة الرأسيّة محرّك نموّ. البذر الفعليّ (متاجر+أصناف) خطوة تشغيليّة لك/OPS.

٣ البند 3 — الظهور المدفوع (Sponsored) ✅

بلغة بسيطة: مطعم/محلّ يدفع ليظهر أعلى نتائج البحث بشارة «إعلان» شفّافة. مصدر دخل سهل ومألوف عالميًّا. تنتهي الرعاية تلقائيًّا بانتهاء مدّتها.
تقنيًّا (مع إصلاحات المحاكاة): هجرة aa54 (is_sponsored+sponsored_rank+sponsored_until timestamptz) · مُساعِد _sponsored_active tz-safe (يقسر naive→UTC — كان عيبًا عاليًا) · رفع المموّل في مساري البحث (geo + SQL case محمول) · شارة «إعلان» في ProviderCard (إفصاح تنظيميّ) · نقطة POST /operations/providers/{id}/sponsor (SUPER + تدقيق) · مدخل impactMap. اختبارات B2 5/5 + تحقّق إيجابيّ (المموّل تقييم 4.0 سبق العاديّ 4.9).
التقنية المضافة (بحث 2026): الإعلانات ثاني أكبر دخل لمنصّات التوصيل؛ بدأنا بسيطًا (ترتيب+شارة)، والاستهداف بالفئة/الميزانيّة لاحقًا.

٤ البنود 4–8 — لماذا تُسلسَل بحذر (بصدق)

صدقًا — وهذا يحمي مشروعك: بناء الثمانية كاملةً في جلسة واحدة بجودة إنتاج غير ممكن، ومحاولة حشرها = «إفساد المشروع» الذي حذّرتَ منه. لذا نُكمِل بند-بند. وهذه أسباب تسلسل الأربعة الباقية:

4 · دفع الويب push

محكوم بإعداد المالك
الخلفيّة مكتملة 100% (نموذج التوكِن + النقطة + إرسال FCM v1 + قيد فريد). الواجهة تحتاج مشروع Firebase + مفتاح VAPID لا أملكهما — تُنشئهما أنت. بناء كود واجهة بلا SDK = كود ميّت، فأجّلناه للتفعيل. الخطوة: تزوّدني بإعداد Firebase ⇒ أصِل الـhook + معالِج SW (~ساعات).

5 · الإكراميّة

يمسّ القلب الماليّ — جلسة مركّزة
الإكراميّة تمسّ FIN-COR المختوم: المحاكاة كشفت 8 عيوب متشابكة (أخطرها: لو حُسبت الإكراميّة ضمن عُهدة السائق يُحجَب ظلمًا؛ والمصالحة تُبلِّغ تبايُنًا كاذبًا؛ وحساب COA ناقص). إصلاحها صحيحًا يحتاج عملًا ماليًّا دقيقًا مركّزًا — حشره في نهاية جلسة ماراثونيّة خطر على دفتر الأموال. لذا يُنفَّذ بعناية في جلسته.

6 · تجميع الطلبات

خلف علَم + اختبار حِمل
الخوارزميّة مبنيّة ومختبَرة (446). الربط الحيّ يحتاج معالجة تزامن قبول السائقين (أقفال صفوف + 409) واختبار حِمل قبل التفعيل. يُبنى خلف علَم OFF ثمّ يُفعَّل بعد إثبات المكسب.

7 · اطلب أيّ شيء — 🚦 قرار G1

أعلى مخاطرة
ليس إضافة بسيطة: يمسّ 40+ موضعًا (provider_id إجباريّ، آلة الحالات، التسوية، التقريب، المحفظة). يحتاج قرارك: نموذج المشوار (بلا مزوّد؟ COD مرن أم WALLET بميزانيّة؟). موجة مستقلّة بعد قرارك.

8 · الذكاء + River — 🚦 G2/G3

إذن + بيانات
يحتاج: دور قاعدة قراءة-فقط (رفضه حاجز الأمان — تُنشئه أنت بـpsql) + قرار دلالة الوسم (RTO أم احتيال) + بيانات إطلاق حقيقيّة (الآن 24 طلبًا تجريبيًّا فقط). يُفعَّل بعد الإطلاق.
