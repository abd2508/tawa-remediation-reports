1 البطاقة المفتوحة ← معطّلة + «قريبًا»

الجذر المتتبَّع

payment_resolver.py:47-51 — فرع CARD يُعيد available=True دائمًا؛ العلَم production_payment_enabled يضبط sandbox_only فقط. الواجهة CheckoutPage.tsx:902 تُظهِر كلّ available.

التغيير الدقيق

backend: available = feature_flags.is_enabled("production_payment_enabled") (يبقى sandbox_only كإشارة «قريبًا»). FE: بدل حذف غير المتاح، اعرضه معطّلًا رماديًّا + شارة «قريبًا».
تحسين 2026: الممارسة المعياريّة (OpenFeature) — الطريقة التي «ستوجد لاحقًا» تُعرَض معطّلة مع «قريبًا» (تبني التوقّع وتوضّح خارطة الطريق)، ولا تُحذَف إلّا إن كانت ممنوعة دائمًا. ⇒ نوصي بالرماديّة لا الإخفاء.
الاختبارات: اختبار يؤكّد CARD `available=False` حين العلَم off + `True` حين on. المخاطر: صفر — المصدر واحد، النقد/المحفظة بلا مساس. FIN-COR: العلَم موجود سلفًا (لا تغيير عقد).

2 النقد يشترط هاتفًا + بريدًا مؤكَّدًا

الجذر المتتبَّع

نموذج المستخدم فيه email_verified فقط (يُضبَط بـregistration_router.py:1071)؛ لا حقل phone_verified — OTP التسجيل يُثبِت الملكيّة لكن بلا علَم مخزَّن. create_order للنقد فيه بوّابات مخاطر/OTP لكن لا تحقّق هاتف/بريد.

التغيير الدقيق

(1) حقل phone_verified + هجرة. (2) ضبطه True عند استهلاك توكن OTP التسجيل + نقطة «أكّد هاتفي» للحاليّين. (3) بوّابة في create_order للنقد خلف cod_require_verified_contact (افتراضي OFF). (4) واجهة ترشد للتأكيد.
أخطر خطر متتبَّع (حاسم): العملاء الحاليّون phone_verified=false+email_verified=false افتراضيًّا ⇒ تفعيل البوّابة بلا تحضير يحجب كلّ عملائك عن النقد فورًا. ⇒ إلزاميّ: (أ) علَم config افتراضيّ OFF، (ب) backfill: ضبط phone_verified=true للمستخدمين النشطين الذين سجّلوا بـOTP، (ج) تفعيل تدريجيّ بإذنك.
تحسين 2026 (ترخيص متدرّج بالثقة): الأفضل ممارسةً ليس حجبًا مطلقًا بل طبقات: هاتف مؤكَّد إلزاميّ (طبقة 1) + trust_score يقرّر الاحتكاك (لديك 3 طبقات + OTP قيمة عالية مرحلة 427). ادمج البريد المؤكَّد كإشارة ثقة لا كحاجز صلب. (MENA ~60% طلبات نقد؛ RTO أهمّ خسارة.)
الاختبارات: نقد بلا تأكيد→422 (حين العلَم on) · مع تأكيد→201 · العلَم off→لا تغيير. FIN-COR: لا يُمَسّ.

3 زرّ «الحساب» الأحمر محجوب خلف الشريط السفليّ

الجذر المتتبَّع (مؤكَّد باللقطة)

bottom-nav ‏position:fixed (global.css:820). Layout.tsx:202 يضع <Outlet/> مباشرةً بلا غلاف ذي حشوة سفليّة ⇒ آخر محتوى صفحة الإعدادات (زرّ الخروج الأحمر) يُقصَّ خلف الشريط.

التغيير الدقيق (جذريّ لكلّ الصفحات)

لفّ <Outlet/> في Layout.tsx بـ<div className="app-content"> له padding-bottom: calc(5rem + env(safe-area-inset-bottom)) ⇒ يُصلِح كلّ صفحات العميل دفعةً واحدة لا الإعدادات فقط.
الاختبارات: لقطة بصريّة: زرّ الخروج يظهر كاملًا فوق الشريط. المخاطر: صفر (حشوة فقط). تحقّق: قِسناه — الزرّ مبنيّ (خلفيّة حمراء `rgb(240,114,111)`) لكنّه محجوب.

4 مبدّل الفاتح/الداكن دائمًا في الشريط العلويّ

الجذر المتتبَّع

المبدّل في الإعدادات فقط (CustomerSettings.tsx:546 + Driver/Provider). الشريط العلويّ Layout.tsx (قسم العميل ~172 + قسم OPS ~107) فيه زرّ اللغة فقط — بلا مبدّل ثيم. الزائر بلا إعدادات ⇒ محروم.

التغيير الدقيق

زرّ ثيم (☀️/🌙) بجانب زرّ اللغة في الشريطين عبر toggleTheme/currentTheme من utils/theme.ts (جاهز)؛ يظهر دائمًا حتى للزائر. إزالة/إبقاء نسخة الإعدادات (نوصي بالإبقاء للاكتشاف).
تحسين 2026: المعيار = أيقونة في الرأس بثلاث حالات (نظام/فاتح/داكن) تحترم prefers-color-scheme افتراضيًّا + تطبيق ما قبل الرسم (سكربت head) لمنع وميض. واستعمال light-dark() CSS وcolor-scheme (الذي أصلحناه سابقًا — حلّ عيب القوائم البيضاء) لتقليص كود الثيم. نبدأ بثنائيّ (فاتح/داكن) ونرقّيه لثلاثيّ لاحقًا.
الاختبارات: نقر الزرّ يقلب data-theme ويحفظه؛ يظهر للزائر. المخاطر: صفر.

5 ألوان سجلّ التحويلات

التغيير الدقيق

الاختبارات: صفّ OUT أحمر/−، IN أخضر/+. المخاطر: صفر. ملاحظة: إصرارك أنّ القائمة الرئيسيّة غير ملوّنة = كاش قديم على جهازك (الكود المنشور صحيح، مُثبَت بلقطة) — يكفي إعادة فتح التطبيق.

7 مسار إضافة عنوان للمشوار

ErrandPage.tsx:140-152 قائمة <select> فقط، والإرسال مشروط بـ!!addressId ⇒ صفر عناوين = طريق مسدود. CheckoutPage.tsx:778-805 يحلّها برابط لـ/address-book (يستخدم LocationPicker: موقعي/خريطة/إحداثيّات/كتابة).

التغيير الدقيق

تحسين 2026 (عناوين ليبيا): الأفضل = دبّوس GPS + معلَم + Plus Code (Open Location Code: مجّانيّ، بلا API مدفوع، ~3م، يعمل دون اتّصال — أفضل من what3words المملوك). لديك Plus Codes أصلًا (بند «شارك موقعي + Plus Codes»). ⇒ اجعل LocationPicker يولّد Plus Code تلقائيًّا، واربط زرّ «موقعي الحالي» للمشوار مباشرةً.
الاختبارات: صفر عناوين ⇒ يظهر الرابط، لا طريق مسدود. المخاطر: صفر (LocationPicker موجود).
