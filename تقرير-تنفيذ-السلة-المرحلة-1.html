تقرير تنفيذ السلة — المرحلة س1 (الأساس) + تسعير السلة الآمن

بدأنا بناء السلة الموحّدة بالتسلسل الآمن: أنشأنا مجلد وحدة مخصّصاً داخل النظام، وأرسينا أساس «نموذج العنصر» + جدول السلة + ربط الطلبات + آلة حالات العنصر + تسعير السلة (للقراءة فقط) — مع تركيز أمنيّ عالٍ، واختبارات تثبت كل شيء.

التاريخ: 2026-07-01

النواة المالية + الأعلام المختومة: لم تُمسّ

ببساطة: ماذا فعلتُ في هذه المرحلة؟

وضعتُ «الهيكل العظمي» للسلة الموحّدة قبل أي عمليات مالية حسّاسة: (١) مجلد جديد يجمع كل كود السلة، (٢) جدول «السلة» (order_groups) الذي سيحمل الدفعة الواحدة لاحقاً، (٣) ربط كل طلب-متجر بسلّته عبر عمود group_id، (٤) قواعد حركة حالة كل عنصر (مؤكَّد→تحضير→جاهز→سُلّم…)، (٥) حساب أسعار السلة (سعر كل توصيل لكل متجر) — وهذا الأخير يعمل الآن فعلاً وآمن تماماً لأنه «قراءة فقط» (لا يحرّك مالاً).

أنشأتُ مجلد وحدة مخصّصاً داخل الخلفية يجمع «كل هذا»:

backend/app/modules/carts/ ├─ __init__.py # تعريف الوحدة ├─ models.py # OrderGroup (جدول السلة) ├─ item_states.py # آلة حالات العنصر + قواعد الانتقال ├─ service.py # quote_cart (تسعير السلة، قراءة فقط) └─ router.py # POST /carts/quote (محميّ للعميل)

٣ الناحية الأمنية (ركّزتُ عليها كما طلبت)

المبدأ: في هذه المرحلة لم نلمس أي عملية مالية؛ ومع ذلك طبّقنا كل الضوابط الأمنية على ما بنيناه:
الضابط الأمنيكيف طُبّق
🔒 صلاحية الوصول (RBAC)/carts/quote للعميل فقط (require_role(CUSTOMER)) — أي دور آخر يُرفَض ٤٠٣.
🔒 ملكية العنوان (ABAC)حساب الرسم يمرّ عبر quote_delivery_fee(customer_id) الذي يمنع استخدام عنوان عميل آخر (لا تجسّس على عناوين الغير).
🔒 لا حركة مالالتسعير قراءة فقط — لا إنشاء طلب، لا حجز، لا خصم. أكثر مسار آمن ممكن.
🔒 منع التكرار (Idempotency)جدول السلة فيه idempotency_key فريد — سيمنع ازدواج الدفعة عند البناء المالي.
🔒 حدود الإدخالسقف عدد المزوّدين في الطلب (≤١٠) لكبح الإساءة/التكلفة، وإزالة التكرار.
🔒 قيود قاعدة البياناتقيود CHECK على الحالة وطريقة الدفع والمبالغ غير السالبة (لا بيانات فاسدة).
🔒 حالة العنصر مُحكمةآلة حالات صارمة تمنع الانتقالات غير المنطقية (حماية من تلاعب الحالة).

٤ تسعير السلة — كيف يعمل (يعمل الآن)

ببساطة: ترسل قائمة المتاجر في سلّتك + عنوان التوصيل، فيُرجِع النظام رسم التوصيل لكل متجر ومجموعها، مع تنبيه «قد يقلّ عند جمعها لسائق واحد».
# الطلب POST /carts/quote { "address_id": "...", "provider_ids": ["مطعم", "سوق"] } # الردّ { "providers": [ {provider_id, delivery_fee_minor, distance_km, eta...}, ... ], "provider_count": 2, "total_delivery_fee_minor": 9000, "batching_may_reduce": true } # قد يقلّ عند التجميع

يُعيد استخدام نفس حساب الرسم الذي يستخدمه الدفع فعلاً (quote_delivery_fee) — فما تراه في السلة = ما سيُحسب عند الدفع (لا مفاجآت). أسعار السلع نفسها يعرفها التطبيق من الكتالوج ويجمعها محلياً.

٥ لماذا آمن ولا يكسر شيئاً؟

  • إضافي بالكامل: جدول جديد + عمود جديد فارغ افتراضياً. الطلبات المفردة الحالية (group_id=null) تعمل تماماً كما كانت.
  • لا مساس بالنواة المالية: لا تغيير في العمولة/التسوية/الدفتر.
  • لا مساس بالأعلام المختومة.
  • قراءة فقط للتسعير: لا آثار جانبية.
  • رأس alembic واحد نظيف (ab03 فوق ab02).
