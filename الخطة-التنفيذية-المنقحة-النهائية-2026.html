API Contract — nginx Location Blocks الثلاثة

الكود الكامل للـ 3 location blocks التي تحتاج إضافة/تعديل في nginx.conf

nginx.conf — http context (قبل server{})
# Cache zone للـ OSM tiles — يجب أن يكون في http context
proxy_cache_path /var/cache/nginx/tiles
  levels=1:2
  keys_zone=tiles:10m
  max_size=2g
  inactive=30d
  use_temp_path=off;
nginx.conf — داخل server{} — Block 1: sw.js (exact match)
# CRITICAL: exact match يجب أن يأتي قبل أي location ~ \.js$
location = /sw.js {
    root             /usr/share/nginx/html;
    add_header       Cache-Control "no-store";
    add_header       X-Content-Type-Options "nosniff";
    # no etag, no last-modified — browser re-fetches unconditionally
    etag             off;
    add_header       Last-Modified "";
}
nginx.conf — داخل server{} — Block 2: hashed assets (immutable)
# ^~ يمنع أي location ~ من التغلب عليه
location ^~ /assets/ {
    root             /usr/share/nginx/html;
    add_header       Cache-Control "public, max-age=31536000, immutable";
    add_header       X-Content-Type-Options "nosniff";
    # Content-hashed filenames → safe permanent cache
}
nginx.conf — داخل server{} — Block 3: index.html (no-cache)
# index.html يُعاد التحقق منه في كل طلب (ETag revalidation)
location = /index.html {
    root             /usr/share/nginx/html;
    add_header       Cache-Control "no-cache";
    add_header       X-Content-Type-Options "nosniff";
    # no-cache = "revalidate always via ETag/Last-Modified" — NOT "don't cache"
}
ترتيب الأولوية في nginx: location = (exact) يفوز على location ^~ يفوز على location ~ يفوز على location /. بدون exact match على /sw.js، أي location ~ \.js$ يتغلب عليه!

Workbox NavigationRoute — NetworkFirst (الإصلاح الثالث الإلزامي)

بدون هذا الإصلاح، PWA users سيحصلون على index.html من Cache Storage حتى مع no-cache على nginx

vite.config.ts — داخل VitePWA workbox config
// أضِف داخل workbox: {} في VitePWA plugin
navigationPreload: false, // تعطيل لضمان NetworkFirst يعمل بشكل صحيح
runtimeCaching: [
  {
    // NavigationRoute: HTML pages via NetworkFirst
    urlPattern: ({ request }) =>
      request.mode === 'navigate',
    handler: 'NetworkFirst',
    options: {
      cacheName: 'navigation-cache',
      networkTimeoutSeconds: 3,
      expiration: {
        maxEntries: 10,
        maxAgeSeconds: 86400 // 24h fallback only
      }
    }
  },
  // ... باقي runtimeCaching entries (delivery-proofs, cash-collections)
],
// استبعاد index.html من precache (NavigationRoute يتولى المهمة)
globIgnores: [
  'assets/ops-*.js',
  'assets/Ops*.js',
  'assets/ControlPanel*.js',
  'ops.html',
  'index.html' // ← أضِف هذا السطر
]
لا تحذف globIgnores الموجودة — أضِف 'index.html' فقط. الـ ops entries موجودة لسبب (عزل OPS build عن customer SW).

Cloudflare Cache Rules — الدفاع المستقل عن nginx

أي Page Rule بـ "Cache Everything" على الـ zone تُبطل إصلاحات nginx. Cache Rule صريحة تظل فعّالة حتى بعد nginx restart/rollback

الملف / المسارCF Cache Ruleالسبب
/sw.js Bypass Cache يجب revalidate عند كل طلب — أي cache = SW قديم
/index.html Bypass Cache HTML entry point — يحتاج ETag check دائماً
/assets/* Cache (Respect headers) Content-hashed → safe permanent cache (1 year)
/api/* Bypass Cache API calls يجب أن تصل للـ backend دائماً
/tiles/* Cache (30 days) OSM tiles — static geographical data
CF Cache Rule تُطبَّق من Dashboard → Rules → Cache Rules → Create Rule. لا يوجد ملف config تشترك مع nginx — يجب إعدادها يدوياً ومنفصلة.

الأعراض الجانبية — ماذا يحدث إذا لم نُصلح؟

مستخدمو PWA لا يرون تحديثات الـ app لأيام (تقرير Glovo: ~72h تأخير بدون no-store)
أخطاء 404 صامتة للـ offline requests بعد deploy (SW يطلب hashes قديمة محذوفة)
نافذة "تحديث متاح" لا تظهر أبداً (SW قديم لا يكتشف النسخة الجديدة)

🔬سيناريوهات nginx — الكاملة من بيانات الفحص

S-02 | CF Cache Everything + sw.js
Cloudflare تُخزّن sw.js رغم nginx no-store
الوضع: nginx يُرسل Cache-Control: no-store على /sw.js. CF Page Rule بـ "Cache Everything" على الـ zone تعترضها وتُخزّن الملف.
النتيجة: المتصفح يحصل على sw.js مخزّن → SW القديم يبقى → لا تحديثات.
الإصلاح: CF Cache Rule صريحة: URI = /sw.js → Bypass. مستقلة عن nginx، تظل فعّالة بعد rollback.
S-03 | CF Standard Cache + index.html
index.html مخزّن في Cloudflare = مستخدمون عالقون على نسخة قديمة
الوضع: nginx يُرسل no-cache على /index.html. CF Standard Caching تُخزّنها وتُعيد ETag القديم.
النتيجة: browser لا يحصل على HTML الجديدة → script hashes قديمة → 404 على الـ assets الجديدة.
الإصلاح: CF Cache Rule: URI = /index.html → Bypass.
S-04 | CF Rollback سيناريو
nginx rollback يُبطل الإصلاح — CF Rule تحمي
الوضع: بعد deploy، تعطّل nginx.conf جديد → rollback للقديم. nginx القديم لا يملك exact match → sw.js قد يُكاش مجدداً.
الإصلاح: CF Cache Rule مستقلة تبقى فعّالة بغض النظر عن حالة nginx.
S-05 | CF "Respect Existing Headers" — assets
Cloudflare قد تتجاهل immutable header على /assets/
الوضع: nginx يُرسل immutable, max-age=31536000 على /assets/*. بدون "Respect Existing Headers" في CF → CF تُعيد تعريفها.
الإصلاح: CF: Browser Cache TTL = "Respect Existing Headers" لـ /assets/* — يضمن immutable يصل للمتصفح.
S-06 | Docker build --cache يُكاش nginx.conf
إصلاح nginx.conf لا يصل للحاوية المنشورة
الوضع: COPY nginx.conf في Dockerfile مخزّن في Docker build cache. بناء عادي بدون --no-cache يُعيد الطبقة القديمة.
النتيجة: الـ container يعمل بـ nginx.conf قديم — الإصلاح لا يصل للإنتاج!
الإصلاح: docker build --no-cache عند أي تغيير في nginx.conf + RUN nginx -t كـ CI gate.
S-07 | nginx -t لا يُشغَّل قبل deploy
config معطوب يصل للإنتاج بدون كشف
الوضع: nginx.conf يحتوي خطأ syntax → nginx -t سيفشل. بدون RUN nginx -t في Dockerfile، الـ build ينجح والـ config المعطوب يُنشر.
الإصلاح: أضِف RUN nginx -t في Dockerfile بعد COPY — يُفشل الـ build مبكراً.
S-09 | location ~ \.js$ يتغلب على prefix /assets/
regex location يأكل /assets/*.js ويُطبّق headers مختلفة
الوضع: إذا وُجد location ~ \.js$ في nginx.conf (من plugin آخر أو legacy config)، يتغلب على location /assets/ prefix ويُلغي immutable header.
الإصلاح: استخدم location ^~ /assets/ — الـ ^~ يمنع regex matching من التغلب عليه.
S-11 | بدون exact match = /sw.js يُطابق /assets/ أو regex
sw.js يحصل على immutable بدلاً من no-store
الوضع: بدون location = /sw.js exact match، الطلب يقع تحت location ^~ /assets/ أو location ~ \.js$ → يحصل على max-age=31536000, immutable!
النتيجة: Browser يُخزّن sw.js لسنة كاملة — لا تحديثات PWA.
الإصلاح: location = /sw.js يجب أن يكون أول location في server{}.
S-12 | nginx -t يمر لكن الـ config لا يعمل كما يجب
syntax صحيح + سلوك خاطئ (location precedence)
الوضع: nginx -t ينجح لأن الـ syntax صحيح. لكن الـ location precedence خاطئة — exact match = /sw.js مكتوب بعد location ~ \.js$.
التحقق الإلزامي بعد deploy: curl -I https://tawanow.com/sw.js | grep -i cache-control يجب أن يُعيد no-store وليس immutable.
S-13 | CF Purge مطلوب بعد إصلاح CF Rules
CF تُخزّن نسخة قديمة من sw.js قبل إضافة الـ Bypass Rule
الوضع: قبل إضافة CF Bypass Rule، sw.js مخزّن في CF PoP. بعد إضافة الـ Rule، النسخة المخزّنة تبقى حتى تنتهي صلاحيتها.
الإصلاح: بعد إضافة CF Cache Rules: Purge Everything من CF Dashboard → Caching → Purge Cache.
S-14 | حذف hashed assets قبل 24h
مستخدمو SW القديم يحصلون على 404 offline
الوضع: بعد deploy جديد، SW القديم لا يزال نشطاً عند بعض المستخدمين. يطلب hashes قديمة من nginx → 404 لأن الملفات حُذفت.
القاعدة: احتفظ بنسختين سابقتين على الأقل (/assets/ من deploy n-1 و n-2) لمدة 24h.
S-17 | Workbox precache يُكاش index.html
nginx no-cache لا يحمي PWA users — SW يتجاوزه
الوضع: حتى مع nginx no-cache، Workbox يُدخل index.html في precache افتراضياً. SW يُعيد index.html من Cache Storage بدون الذهاب لـ nginx.
النتيجة: nginx no-cache عديم الأثر على PWA users!
الإصلاح: أضِف 'index.html' لـ globIgnores + NavigationRoute بـ NetworkFirst.
S-18 | location = /sw.js بعد location ~ \.js$
ترتيب خاطئ = exact match لا يعمل
الوضع: في nginx، exact match = /sw.js يفوز دائماً على regex — لكن إذا كُتب بعد regex block في ملف config يُضاف بـ include، بعض nginx versions القديمة لا تُطبّق الأولوية الصحيحة.
الإصلاح: ضع location = /sw.js كأول location في server{}. التحقق: curl بعد deploy.
S-23 | Rollback + hashes قديمة محذوفة
rollback يُعيد SW القديم الذي يطلب hashes غير موجودة
الوضع: deploy n+1 ثم rollback لـ n. SW من n يطلب hashes من n لكن /assets/ يخدم n+1 hashes. الـ rollback أعاد HTML القديمة لكن assets الجديدة لا تزال موجودة (صحيح). المشكلة لو حُذفت assets n قبل الـ rollback.
القاعدة: لا تحذف assets بعد deploy مباشرة — انتظر 24h لانتهاء SW القديم.
S-24 | CF Zone-level "Cache Everything" يُلغي الـ Headers
Zone setting يتغلب على Page Rules والـ nginx headers
الوضع: CF Zone → Caching → Caching Level = "Aggressive" أو قديم Page Rule. يُطبَّق على كل الـ responses بما فيها sw.js حتى مع Cache-Control: no-store.
الإصلاح: CF Cache Rule بـ Bypass تتغلب على Zone-level settings لأنها أكثر تخصيصاً. Order of precedence: Cache Rule > Page Rule > Zone setting.
S-26 | NetworkFirst timeout منخفض جداً
3G users يحصلون على نسخة cache قديمة لأن timeout انتهى
الوضع: navigationPreload + NetworkFirst بـ networkTimeoutSeconds: 1. مستخدم على 3G → network timeout → SW يُعيد cache → قد يكون قديماً.
الإصلاح: networkTimeoutSeconds: 3 (Deliveroo pattern). يوازن بين freshness و UX على شبكات بطيئة.
S-32 | Deploy بدون Cloudflare Purge
CF تُكمل الـ request بنسخة sw.js قديمة من PoP cache
الوضع: nginx محدّث + CF Rules صحيحة. لكن sw.js مخزّن في CF PoP قريب من المستخدم. المستخدم يصل للـ PoP، يحصل على نسخة قديمة.
الإصلاح: Purge Everything من CF Dashboard بعد كل deploy يمس nginx.conf أو sw.js.
S-33 | PwaReloadPrompt غير مُثبَّت في App.tsx
SW لا يُسجَّل أبداً — injectRegister:null يتطلب التثبيت اليدوي
الوضع: VitePWA config بـ injectRegister: null يعني الـ plugin لا يُسجّل SW تلقائياً. PwaReloadPrompt component هو الـ registrar الوحيد. إذا لم يُضَف لـ App.tsx → SW لا يُسجَّل أبداً → لا PWA لأي أحد.
التحقق: grep -r 'PwaReloadPrompt' web/src/App.tsx — يجب أن يُعيد نتيجة.
S-34 | SW BackgroundSync يفشل بدون client_operation_id
إعادة محاولة BackgroundSync تُنشئ طلبات مكرّرة
الوضع: delivery-proof-queue و cash-collection-queue يُعيدان المحاولة تلقائياً. إذا كانت الـ endpoint لا تدعم client_operation_id idempotency → إعادة المحاولة = طلبات مكرّرة (حسابات مالية مكرّرة!).
الحالة الحالية: الـ backend يتطلب client_operation_id بـ DB unique constraint → 409 على retry. ✓ آمن.

✅أفضل الممارسات — Cloudflare vs nginx headers

نمط Uber Eats / DoorDash

  • HTML: Cache-Control: no-cache
  • SW: Cache-Control: no-store
  • Hashed assets: immutable, max-age=31536000
  • CF: "Respect Existing Headers" لـ assets
  • CF: Bypass لـ sw.js وindex.html
  • لا تُخزّن sw.js أبداً على CDN layer

نمط Deliveroo / Just Eat

  • SW update: immediate check عند focus/visibility
  • updateViaCache: 'none' في sw registration
  • NetworkFirst بـ 3s timeout
  • Purge CF بعد كل production deploy
  • احتفظ بـ n-2 assets لـ 24h

الفرق الجوهري: no-cache vs no-store

الـ Headerالمعنى الحقيقيالاستخدام
no-store لا تُخزّن نهائياً في أي مكان sw.js، بيانات سرية
no-cache خزّن لكن تحقق (ETag) قبل استخدام index.html، HTML pages
immutable لا تتحقق أبداً — الملف لن يتغير /assets/*.js.css (content-hashed)

HSTS — Stage-2 Note

الحالة الحالية: max-age=86400 (بدون includeSubDomains).

Stage-2 ramp منطقي: ابدأ بـ 86400 ثم ارفع لـ 31536000 بعد تأكيد subdomain coverage.

لا تضِف includeSubDomains حتى تتأكد من TLS على كل subdomains بما فيها ops., api., staging.

3.6 — الأعراض الجانبية الرئيسية

⚠ Badge Drift — الأخطر

أي optimistic update للـ badge بدون مزامنة لاحقة من السيرفر يُراكم خطأً. بعد 5-10 أرشفات: badge يُظهر 3 وفي الـ DB هناك 7.
الحل: badge = truth يأتي من السيرفر دائمًا؛ optimistic = hint مؤقت فقط.

⚠ Undo بعد Cross-Device Read

frontend/src/hooks/useActiveStaffCount.ts
import { useState, useEffect, useRef } from 'react';
import { useAuth } from '@/hooks/useAuth';
import { API_BASE } from '@/config';

interface StaffCount {
  active: number;
  total: number;
}

export function useActiveStaffCount() {
  const { token } = useAuth();
  const [count, setCount] = useState<StaffCount | null>(null);
  const [status, setStatus] = useState<'connecting' | 'live' | 'error'>('connecting');
  const esRef = useRef<EventSource | null>(null);

  useEffect(() => {
    if (!token) return;

    // Initial REST snapshot (مرة واحدة عند mount)
    fetch(`${API_BASE}/providers/me/staff/active-count`, {
      headers: { Authorization: `Bearer ${token}` },
    })
      .then(r => r.json())
      .then(data => setCount({ active: data.active, total: data.total }))
      .catch(() => setStatus('error'));

    // SSE stream — absolute snapshots فقط، لا delta
    const es = new EventSource(
      `${API_BASE}/sse/provider-staff-count?token=${token}`
    );
    esRef.current = es;

    es.addEventListener('staff_count', (e: MessageEvent) => {
      const payload = JSON.parse(e.data) as StaffCount;
      setCount(payload);   // يستبدل القيمة كاملاً — ليس يزيد/ينقص
      setStatus('live');
    });

    es.onerror = () => setStatus('error');

    // Cleanup إلزامي عند unmount (P13-13)
    return () => {
      es.close();
      esRef.current = null;
    };
  }, [token]);  // يُعيد الاتصال فقط لو تغيّر الـ token

  return { count, status };
}

import { useState } from 'react';
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { putStaffEvaluation } from '@/api/staff';
import { toast } from '@/components/ui/Toast';

interface Props {
  staffId: string;
  initialStars: number | null;  // null = لم يُقيَّم بعد
  notes?: string;
  readOnly?: boolean;
}

export function StaffRating({ staffId, initialStars, notes: initialNotes, readOnly }: Props) {
  const [hovered, setHovered] = useState<number | null>(null);
  const [selected, setSelected] = useState<number | null>(initialStars);
  const [notes, setNotes]       = useState(initialNotes ?? '');
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (stars: number) => putStaffEvaluation(staffId, { stars, notes }),
    // Optimistic update — يتغير الـ UI فوراً
    onMutate: async (stars) => {
      await queryClient.cancelQueries({ queryKey: ['staff-evaluation', staffId] });
      const prev = queryClient.getQueryData(['staff-evaluation', staffId]);
      queryClient.setQueryData(['staff-evaluation', staffId], { stars, notes });
      return { prev };  // للـ rollback
    },
    onError: (_, __, ctx) => {
      // Rollback عند فشل الـ API
      queryClient.setQueryData(['staff-evaluation', staffId], ctx?.prev);
      setSelected(initialStars);
      toast.error('فشل حفظ التقييم — تم الإلغاء');
    },
    onSuccess: () => toast.success('تم حفظ التقييم'),
  });

  const handleStarClick = (star: number) => {
    if (readOnly) return;
    setSelected(star);
    mutation.mutate(star);  // stars دائماً integer 1-5
  };

  return (
    <div className="flex flex-col gap-2">
      {/* Stars row */}
      <div
        className="flex gap-1 text-3xl"
        style={{ direction: 'ltr' }}
        role="group"
        aria-label="تقييم بالنجوم"
      >
        {[1, 2, 3, 4, 5].map(star => (
          <button
            key={star}
            type="button"
            disabled={readOnly}
            className="focus:outline-none min-w-[44px] min-h-[44px] flex items-center justify-center"
            onMouseEnter={() => !readOnly && setHovered(star)}
            onMouseLeave={() => setHovered(null)}
            onClick={() => handleStarClick(star)}
            aria-label={`${star} نجوم`}
          >
            <span className={(hovered ?? selected ?? 0) >= star
              ? 'text-amber-400'
              : 'text-gray-300'
            }>
              ★
            </span>
          </button>
        ))}
      </div>
      {/* Notes */}
      {!readOnly && (
        <textarea
          value={notes}
          onChange={e => setNotes(e.target.value)}
          placeholder="ملاحظات اختيارية..."
          maxLength={500}
          className="border rounded p-2 text-sm resize-none"
          rows={2}
        />
      )}
      {!selected && (
        <span className="text-xs text-gray-400">لم يُقيَّم بعد</span>
      )}
    </div>
  );
}

import { useState } from 'react';
import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { getOpsPausedItems, pauseCatalogItem, restoreCatalogItem } from '@/api/ops';
import { toast } from '@/components/ui/Toast';

interface PauseModalProps {
  itemId: string;
  itemName: string;
  onClose: () => void;
}

function PauseModal({ itemId, itemName, onClose }: PauseModalProps) {
  const [reason, setReason] = useState('');
  const qc = useQueryClient();

  const mutation = useMutation({
    mutationFn: () => pauseCatalogItem(itemId, { reason, notify_provider: true }),
    onSuccess: () => {
      toast.success(`تم إيقاف "${itemName}" بنجاح`);
      qc.invalidateQueries({ queryKey: ['ops-paused-items'] });
      onClose();
    },
    onError: (err: any) => {
      if (err.status === 409) toast.error('المنتج مُوقف مسبقاً');
      else toast.error('فشل الإيقاف');
    },
  });

  return (
    <div className="fixed inset-0 bg-black/40 flex items-center justify-center z-50">
      <div className="bg-white rounded-xl p-6 w-full max-w-md">
        <h2 className="font-bold text-lg mb-4">إيقاف منتج: {itemName}</h2>
        <textarea
          value={reason}
          onChange={e => setReason(e.target.value)}
          placeholder="سبب الإيقاف (إلزامي)..."
          className="w-full border rounded p-3 text-sm h-24 resize-none"
          maxLength={500}
        />
        <div className="flex gap-3 mt-4 justify-end">
          <button onClick={onClose} className="px-4 py-2 text-gray-600 hover:bg-gray-100 rounded">
            إلغاء
          </button>
          <button
            disabled={!reason.trim() || mutation.isPending}
            onClick={() => mutation.mutate()}
            className="px-4 py-2 bg-red-600 text-white rounded hover:bg-red-700
                       disabled:opacity-50 disabled:cursor-not-allowed"
          >
            {mutation.isPending ? 'جارٍ الإيقاف...' : 'تأكيد الإيقاف'}
          </button>
        </div>
      </div>
    </div>
  );
}

def validate_cart_before_charge(cart_items: list[CartItem], db: Session) -> None:
    """
    يفحص كل بند قبل أي charge.
    سيناريو: زبون عنده منتج في سلة وقت الإيقاف.
    الكاش لا يُبطَل تلقائياً — هذه البوابة الوحيدة.

    for item in cart_items:
        catalog_item = db.get(CatalogItem, item.catalog_item_id)

        if catalog_item is None:
            raise HTTPException(422, f"المنتج {item.catalog_item_id} غير موجود")

        if catalog_item.ops_paused_at is not None:
            raise HTTPException(
                422,
                {
                    "code": "ITEM_OPS_PAUSED",
                    "item_id": str(item.catalog_item_id),
                    "item_name": catalog_item.name,
                    "message": f"المنتج '{catalog_item.name}' موقوف مؤقتاً"
                }
            )

        # visibility check الكامل
        if not catalog_item.provider.is_active or catalog_item.provider_paused_at:
            raise HTTPException(422, f"المتجر غير متاح حالياً")

الأعراض الجانبية المتوقعة
  • بحث الكاتالوج: query بحث يجب أن يشمل ops_paused_at IS NULL — وإلا المنتج الموقوف يظهر في نتائج البحث (ثغرة صامتة).
  • Cache invalidation: إذا كان الـ frontend يُخزّن قائمة المنتجات (React Query cache) — الإيقاف يجب أن يُبطل هذا الكاش. SSE event يستدعي queryClient.invalidateQueries.
  • تقارير OPS: ops_paused_at يُتيح تقارير "مدة الإيقاف" و"أكثر المنتجات إيقافاً" — قيمة إضافية مجانية من تصميم الـ timestamp.
  • الطلبات المعلّقة (pending orders): طلب وصل لـ "قيد التحضير" وأُوقف المنتج — الطلب يكتمل (لا تراجع). الإيقاف يؤثر على الطلبات الجديدة فقط.
  • إيقاف متجر كامل vs منتج واحد: هذا الـ endpoint لمنتج واحد. إيقاف المتجر الكامل من OPS يستلزم endpoint منفصل (ليس في scope هذا القسم).
