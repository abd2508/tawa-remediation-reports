تشبيه بسيط — متجر الكتب
تخيّل أن المنصة تشبه متجر كتب يطبع نسخاً جديدة كل يوم.
لكن بين الطابعة (السيرفر) والزبون (المتصفح) يوجد موزّع وسيط (Cloudflare) يحتفظ بمخزون خاص من النسخ القديمة.

المشكلة: الموزّع لا يفتح الباب على الطابعة إلا مرة كل 4 ساعات. حتى لو المتجر طبع كتاباً جديداً الآن، الزبون يحصل على النسخة القديمة من مخزون الموزّع.

وهناك مشكلة ثانية: المتصفح نفسه يحتفظ بنسخته الخاصة من الكتاب (Service Worker = حارس المخبأ). هذا الحارس يفحص "هل هناك طبعة جديدة؟" كل 60 ثانية — لكن يسأل الموزّع، لا الطابعة. فيجيبه الموزّع: "لا جديد" — لأنه هو نفسه لا يعلم بالجديد بعد!

باختصار: التحديثات موجودة على السيرفر بالفعل، لكن Cloudflare يمنع المتصفح من معرفة ذلك لمدة تصل إلى 4 ساعات.

ملف sw.js هو الملف الوحيد الذي يفحصه المتصفح ليعرف إذا كان هناك إصدار جديد من الموقع. إذا تغيّر sw.js → المتصفح يعرف → يعرض بانر "تحديث متاح". إذا لم يتغيّر → المتصفح يعتقد أن لا شيء جديد → يبقى على النسخة القديمة.
سببه: sw.js يحمل بصمة hash لكل ملف في الموقع — أي تغيير في الكود = بصمة جديدة = sw.js جديد

السبب الجذري الثاني

nginx.conf لا يعطي تعليمات تخزين صريحة لـ sw.js

لماذا هذا مشكلة؟
عندما nginx لا يقول صراحةً "هذا الملف لا يُخزَّن"، Cloudflare يتصرف بالافتراضي: يخزّن كل ملفات JavaScript لمدة 4 ساعات.
الحل: nginx يقول بوضوح لـ Cloudflare "sw.js ممنوع تخزينه أبداً".
الحالة الحالية — nginx.conf
لا تعليمات لـ sw.js → Cloudflare يتصرف بمفرده
الكود الحالي في nginx.conf:

location / {
  try_files $uri $uri/ /index.html;
}

— لا يوجد أي Cache-Control لـ sw.js أو index.html
— Cloudflare يرى JavaScript → يطبّق قاعدته الافتراضية: ٤ ساعات
الحالة المطلوبة — بعد الإصلاح
3 قواعد صريحة تُنهي المشكلة
sw.js: لا يُخزَّن أبداً (no-store)
index.html: تحقق دائماً (no-cache)
assets/*.js: خزَّن إلى الأبد (immutable)

تفصيل: Service Worker — كيف يعمل

Service Worker = حارس محلي في المتصفح

ما هو Service Worker بكلمات بسيطة؟
Service Worker = موظف غير مرئي يعيش في متصفحك ويعمل حتى عندما تغلق الموقع.
مهمته الأساسية: حفظ نسخة من الموقع كاملاً لتشغيله بدون إنترنت.
المشكلة: عندما يحفظ نسخة قديمة، يخدمها للمستخدم حتى بعد تحديث السيرفر.

دورة حياة Service Worker — مع التحديث والبدونه

الحل الكامل — خطوة بخطوة

الخطوة ١: تعديل nginx.conf (ملف الخادم)

يجب إضافة ٣ قواعد تخزين صريحة في web/nginx.conf:

server { listen 80; ... # Service Worker — ممنوع تخزينه أبداً (هو آلية الكشف عن التحديثات) location = /sw.js { add_header Cache-Control "no-store, no-cache, must-revalidate, max-age=0" always; add_header Pragma "no-cache" always; try_files $uri =404; } # index.html — يُجلب دائماً من السيرفر (بدون تخزين ثابت) location = /index.html { add_header Cache-Control "no-cache, must-revalidate" always; try_files $uri =404; } # ملفات assets ذات hash — تُخزَّن للأبد (hash يتغيّر مع كل build) location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable" always; try_files $uri =404; } location / { try_files $uri $uri/ /index.html; } }
شرح كل قاعدة بلغة بسيطة
sw.js = no-store: "يا Cloudflare، هذا الملف لا تلمسه أبداً. اجلب من السيرفر في كل مرة."

index.html = no-cache: "اجلب من السيرفر، لكن يمكنك التحقق من آخر تعديل (ETag) لتوفير الجلب إذا لم يتغيّر."

assets/* = immutable: "هذه الملفات باسمها الفريد (مثل main-COA-qDtF.js) لا تتغيّر محتوياتها أبداً. خزّنها للأبد."

الخطوة ٢: إضافة Cloudflare Cache Rule

1
افتح Cloudflare Dashboard
اذهب لـ cloudflare.com → اختر نطاق tawanow.com
2
اضغط Cache → Cache Rules → Create rule
اسم القاعدة: "No-cache for SW and HTML"
3
اضبط الشرط
URI Path → ends with → /sw.js أو /index.html
4
اضبط الإجراء: Cache Status = Bypass
Bypass = Cloudflare يُمرّر الطلب للسيرفر مباشرة بدون أي تخزين
5
اضغط "Purge Cache" → Custom Purge → أدخل /sw.js
يمسح النسخة القديمة من مخزن Cloudflare فوراً بدون انتظار
