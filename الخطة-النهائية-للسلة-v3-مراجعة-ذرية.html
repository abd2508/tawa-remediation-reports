٠ اشرحها لي ببساطة (لأي شخص)

كيسٌ واحد فيه أغراض من عدّة محلّات. على كل غرض بطاقة سعر وقسيمة إرجاع خاصّة. السلة تُريك ثمن كل سلعة وثمن التوصيل والإجمالي، وتدفع مرّة واحدة. تستطيع حذف غرضٍ واحد أو حذف محلٍّ بالكامل من الكيس قبل الدفع. وبعد الدفع، إذا أردتَ، تُرجِع غرضاً واحداً فتستردّ ثمنه فقط دون أن يتأثّر الباقي. والمنصّة ترسل مندوباً واحداً إن كانت المحلّات قريبة (برسم أقلّ) أو أكثر إن كانت بعيدة.

شكل مبسّط: السلة تعرض سعر كل سلعة + توصيل كل مزوّد + الإجمالي · حذف عنصر أو مزوّد كامل · دفعة واحدة · استرجاع عنصر واحد لاحقاً · توصيل ذكي.

★ نتائج المراجعة الذرّية — ٨ نقاط

#الخطورةالاكتشافالتصحيح في v3
G1حرجخطأ في v2: قلتُ «استرجاع العنصر = ثمنه + نصيبه من رسم التوصيل». هذا خاطئ — فالسائق وصل فعلاً.استرجاع العنصر = ثمن السلعة فقط. رسم التوصيل يُسترجَع فقط عند إلغاء المزوّد كاملاً قبل الإرسال (معيار الأسواق العالمية).
G2حرجحجز المحفظة كلّي (HELD→COMMITTED/RELEASED على المبلغ كلّه) — لا يدعم تحرير/التزام جزئياً، فيتعذّر استرجاع عنصر واحد من مزوّد له عناصر.إضافة تخصيص لكل عنصر (allocation) داخل حجز المزوّد + تحرير/التزام جزئي بالمبلغ (توسعة نموذج الحجز).
G3مهمالحدّ الأدنى للطلب لكل مزوّد (minimum_order_minor) مُطبَّق — وحذف عناصر قد يُنزل مزوّداً تحت الحدّ.تحقّق الحدّ الأدنى لكل مزوّد في السلة وعند الدفع + تنبيه واضح («أضف X لإكمال طلب هذا المتجر أو احذفه»).
G4مهمرسم التوصيل لكل مزوّد، والسلة الموحّدة بها عدّة رسوم — وقرار التجميع (سائق واحد) يُحسَم وقت الإرسال لا وقت السلة.السلة تعرض رسم كل مزوّد + إجمالي تقديري مع «قد يقلّ عند التجميع»؛ ويُطبَّق الرسم المحفّز عند التجميع ويُسوَّى.
G5مهمخلط مفهومين: تعديل السلة (قبل الدفع) مقابل تعديل الطلب (بعد الدفع).فصل واضح: قبل الدفع = حذف/تعديل سلة مجّاني؛ بعد الدفع = إلغاء/استرجاع لكل عنصر/مزوّد حسب حالته.
G6مهمالكوبون يُوزَّع بالتناسب — لكن عند استرجاع عنصر يجب أن يُسترجَع الصافي المدفوع فعلاً لا الإجمالي.تخزين الصافي بعد الخصم لكل عنصر → الاسترجاع يعيد ما دُفع فعلاً (دفتر صحيح).
G7مهمحذف «مزوّد كامل» بعد الدفع = إلغاء عدّة عناصر + رسم توصيله معاً (ذرّياً) وإلا تضارب.عملية «إلغاء مجموعة المزوّد» ذرّية: تُلغي كل عناصره + تُحرّر/تسترجع رسمه (قبل الإرسال) في معاملة واحدة idempotent.
G8مهمالإجراءات الجزئية (إلغاء/استرجاع عنصر) قد تتكرّر (شبكة/نقر مزدوج).مرجع idempotency لكل (عنصر + إجراء) → لا تكرار للحركة المالية.
الخلاصة: جوهر «نموذج العنصر» سليم، لكن المراجعة كشفت أنّ الاسترجاع الجزئي يحتاج تخصيصاً لكل عنصر + حجزاً جزئياً للمحفظة (G2)، وأنّ رسم التوصيل لا يُجزّأ على العناصر (G1). هذان هما أهمّ تصحيحين، وقد دُمجا في كل أقسام v3.

١ الحذف على مستوى العنصر والمزوّد (تعديلك ١)

ببساطة: في السلة تستطيع حذف سلعة واحدة أو محلّ بأكمله. قبل الدفع = حذف مجّاني فوري. بعد الدفع = إلغاء/استرداد (لذلك العنصر أو ذلك المحلّ فقط).
الحالةحذف عنصر واحدحذف مزوّد كامل
قبل الدفع (تعديل سلة)إزالة من السلة فوراً (مجّاني). ✅ آلية موجودة (decrementLine)إزالة كل عناصر المزوّد + رسمه (مجّاني). ✅ (نمط discardBasket موحّداً)
بعد الدفع (تعديل طلب)إلغاء العنصر (قبل التحضير) = تحرير/استرجاع ثمنه فقط. 🟣إلغاء مجموعة المزوّد ذرّياً = إلغاء كل عناصره + تحرير/استرجاع ثمنها + رسم توصيله (قبل الإرسال). 🟣 G7
قاعدة دقيقة (G1): استرجاع رسم التوصيل يحدث فقط عند حذف/إلغاء المزوّد كاملاً قبل الإرسال. حذف عنصر واحد من مزوّد له بقيّة عناصر لا يُرجِع رسم التوصيل (السائق سيوصّل الباقي).

٢ أسعار السلة: سعر السلعة + سعر التوصيل (تعديلك ٢)

ببساطة: السلة تُظهر بوضوح: ثمن كل سلعة · رسم توصيل كل محلّ · مجموع السلع · مجموع التوصيل · الإجمالي — قبل أن تدفع.
  • سعر السلعة: موجود لكل عنصر (line_total_minor) — يُعرَض بجانب كل سلعة.
  • سعر التوصيل لكل مزوّد: يُحسَب بمسافة عنوان التسليم (نفس quote_delivery_fee الحالي) — استدعاء لكل مزوّد في السلة. order_service.quote_delivery_fee
  • الإجمالي: مجموع أسعار السلع + مجموع رسوم التوصيل، مع ملاحظة «قد يقلّ التوصيل عند تجميعه بسائق واحد» (G4).
  • تحديث حيّ: حذف عنصر/مزوّد يُحدّث الأسعار والإجمالي فوراً.
🌐 شفافية السعر قبل الدفع (Baymard): إظهار رسوم التوصيل مبكراً يقلّل هجر السلة؛ وإظهار رسم لكل محلّ + إجمالي يجعل قرار «الحذف لتوفير التوصيل» واعياً.

٣ النموذج ثلاثي الطبقات (ثابت من v2)

ببساطة: (١) الكيس/الدفعة · (٢) فرز حسب المحلّ للتحضير والتسوية والتوصيل · (٣) العنصر هو الأساس (سعر/حالة/استرجاع).
شكل: الطبقات الثلاث — العنصر أساس (سعر/حالة/استرجاع/تخصيص)، وتجميع المزوّد يحمل رسم التوصيل والتسوية، والسلة فوقها دفعة واحدة.

٤ دورة حياة العنصر (ثابت)

ببساطة: كل سلعة تمرّ: مؤكَّدة → قيد التحضير → جاهزة → سُلِّمت، وقد تتفرّع: نفدت / استُبدِلت / أُلغيت / استُرجِعت. كل خطوة تحرّك مال تلك السلعة وحدها.
الحالةمتىالأثر المالي (لهذا العنصر فقط)
CONFIRMED → PREPARING → READY → DELIVEREDالمسار السعيدالتزام حصّة العنصر عند التسليم.
UNAVAILABLEنفد قبل التحضيرتحرير/استرجاع ثمن العنصر.
SUBSTITUTEDبديل بموافقةتعديل الثمن (فرق يُرجَع أو يُطلَب بموافقة — قرار ٤).
CANCELLEDأُلغي قبل التحضيرتحرير ثمنه (والمزوّد كاملاً → + رسمه، G1).
REFUNDEDاستُرجِع بعد التسليمإيداع ثمن العنصر (لا التوصيل) + إعادة عمولته.

٥ الدفعة الواحدة + التخصيص لكل عنصر

ببساطة: تدفع الإجمالي مرّة واحدة؛ النظام «يلصق» على كل سلعة حصّتها من المبلغ (صافي بعد الخصم) — فيصبح تحرير/استرجاع أيّ سلعة دقيقاً.
  • دفع مختلط مسموح (قرار ١): مزوّد بالمحفظة (يُحجَز الآن) ومزوّد بالنقد (يُحصَّل عند بابه) في نفس السلة.
  • تخصيص (allocation): لكل عنصر الصافي المدفوع (بعد توزيع الكوبون، G6) → مرجع كل قيد دفتر = order_item_id (idempotent).
  • ذرّية: إنشاء الأب + العناصر + الحجوزات + الدفعة في معاملة واحدة (إمّا الكل أو لا شيء، G قبل الدفع).

٦ الاسترجاع: ثمن السلعة لا التوصيل (G1 مصحّح)

ببساطة: ترجِع سلعة → تستردّ ثمنها فقط. أمّا رسم التوصيل فلا يُرجَع إلا إذا ألغيتَ المحلّ بأكمله قبل أن ينطلق السائق.
شكل: قاعدة الاسترجاع المصحّحة — ثمن السلعة لكل عنصر؛ رسم التوصيل فقط عند إلغاء المزوّد كاملاً قبل الإرسال.

٧ الحجز الجزئي للمحفظة (G2 — توسعة ضرورية)

ببساطة: اليوم حجز المحفظة «كتلة واحدة» تُلتزَم أو تُحرَّر بالكامل. لاسترجاع سلعة واحدة، نحتاج أن نحرّر/نلتزم جزءاً من الحجز بقدر ثمن تلك السلعة.
  • الواقع: wallet_reservations له amount_minor واحد + حالة كلّية (HELD/COMMITTED/RELEASED). models/payment.py
  • الحلّ المعتمد (الأقوى): تخصيص لكل عنصر داخل حجز المزوّد + دعم مبالغ جزئية للالتزام/التحرير (إمّا حجز لكل عنصر، أو حجز للمزوّد مع جدول تخصيص عناصر + متبقٍّ). التوصية: تخصيص عناصر + تحرير/التزام جزئي بالمبلغ (أقلّ صفوفاً، يتّسق مع التسوية لكل مزوّد).
  • التوافق: الطلب المفرد (عنصر واحد/مزوّد واحد) يبقى كحالة خاصّة من هذا (حجز = عنصر واحد) → لا كسر.

٨ الحدّ الأدنى لكل مزوّد (G3)

ببساطة: بعض المحلّات تشترط حدّاً أدنى للطلب. إن حذفتَ سلعاً حتى نزل محلٌّ تحت حدّه، ننبّهك: «أضف لإكمال طلب هذا المحلّ أو احذفه».

يُتحقَّق الحدّ الأدنى لكل مزوّد على حدة في السلة وقبل الدفع (نفس minimum_order_minor الحالي مطبَّقاً على المجموع الفرعي لعناصر ذلك المزوّد). order_service.py:710-713

٩ الفشل الجزئي (تعويض idempotent — ثابت)

ببساطة: لو تعثّر محلّ بعد الدفع، نُصلح عنصره/مجموعته وحدها (نعيد المال)، والباقي يكمل. والإصلاح آمن عند التكرار (G8).

١١ محاكاة ذهنية دقيقة

محاكاة ١ — حذف مزوّد كامل قبل الدفع
  1. السلة: مطعم [برجر+مشروب] + صيدلية [دواء]. السلة تعرض: ثمن كل سلعة + توصيل المطعم + توصيل الصيدلية + الإجمالي.
  2. العميل يضغط «حذف الصيدلية كاملاً» → تُزال عناصرها ورسمها فوراً → يتحدّث الإجمالي (مجّاني، قبل الدفع).
  3. يبقى المطعم؛ يدفع الإجمالي الجديد مرّة واحدة.
محاكاة ٢ — استرجاع عنصر واحد (G1 + G2)
  1. سلة محفظة: مطعم [برجر 15 + مشروب 3] (توصيل 5) → حُجز ٢٣ للمزوّد، بتخصيص: برجر 15 · مشروب 3 · توصيل 5.
  2. سُلِّم كل شيء → التُزِم الحجز كاملاً → سُوّي للمطعم.
  3. العميل يرجِع «المشروب» (تالف) → استرجاع = ٣ فقط (ثمن السلعة، لا التوصيل) → تحرير/استرجاع جزئي بمقدار ٣ + إعادة عمولة المشروب فقط. البرجر والتوصيل لا يتأثّران.
محاكاة ٣ — حذف مزوّد كامل بعد الدفع وقبل الإرسال (G7)
  1. سلة محفظة: مطعم + سوق. دُفع، حُجزت الحصص (شاملة رسمَي التوصيل).
  2. قبل أن ينطلق سائق السوق، العميل يلغي «السوق كاملاً».
  3. عملية ذرّية: إلغاء كل عناصر السوق + تحرير ثمنها + رسم توصيلها (لم يُرسَل) → يعود للرصيد. المطعم يكمل.
محاكاة ٤ — كوبون ثم استرجاع (G6)
  1. كوبون ١٠٪ على سلة ٣ عناصر → يُوزَّع بالتناسب → يُخزَّن الصافي المدفوع لكل عنصر.
  2. استرجاع عنصر → يُعاد صافيه (بعد الخصم) لا سعره الكامل → الدفتر متوازن والعميل يستردّ ما دفعه فعلاً.
محاكاة ٥ — الحدّ الأدنى عند الحذف (G3)
  1. مطعم حدّه الأدنى ٢٠؛ السلة منه ٢٥. العميل يحذف سلعة بـ١٠ → يصبح ١٥ < الحدّ.
  2. تنبيه فوري: «طلب مطعم البركة أقلّ من الحدّ الأدنى (٢٠) — أضف أو احذف المتجر». الدفع محجوب لذلك المزوّد حتى يُحَلّ.

١٢ مكتبة السيناريوهات (محدّثة لـ v3)

أُبقِيت كل سيناريوهات v2 (٦٦) على مستوى العنصر، وأُضيفت مجموعتان جديدتان للحذف/التسعير.

DEL — الحذف (عنصر/مزوّد) DEL1–DEL12
#الموقفالسلوك المتوقّع
DEL1حذف عنصر قبل الدفع.إزالة فورية + تحديث الإجمالي (مجّاني).
DEL2حذف آخر عنصر لمزوّد قبل الدفع.يختفي المزوّد ورسمه من السلة تلقائياً.
DEL3حذف مزوّد كامل قبل الدفع.إزالة كل عناصره + رسمه + تحديث الإجمالي.
DEL4حذف عنصر بعد الدفع قبل التحضير.CANCELLED → تحرير/استرجاع ثمنه فقط (لا توصيل، G1).
DEL5حذف مزوّد كامل بعد الدفع قبل الإرسال.ذرّياً: عناصره + رسمه يُحرَّر/يُسترجَع (G7).
DEL6حذف عنصر بعد بدء تحضيره.حسب سياسة المتجر (قد يُمنع/يُغرَّم) لذلك العنصر.
DEL7حذف يُنزل المزوّد تحت الحدّ الأدنى.تنبيه + حجب دفع ذلك المزوّد حتى يُحَلّ (G3).
DEL8حذف كل عناصر السلة.سلة فارغة (وقبل الدفع: لا طلب).
DEL9حذف عنصر مكرّر النقر (تزامن).idempotent → إزالة واحدة (G8).
DEL10حذف مزوّد بعد إرسال سائقه.لم يعد إلغاءً مجّانياً — يتبع مسار عدم الحضور/الاسترجاع لعناصره.
DEL11حذف عنصر نقدي قبل التحصيل.إلغاء نظيف بلا استرجاع (لا مال تحرّك).
DEL12حذف عنصر استُبدِل.إلغاء/استرجاع بالسعر النهائي بعد الاستبدال.
PRC — تسعير السلة PRC1–PRC8
#الموقفالسلوك المتوقّع
PRC1عرض سعر كل سلعة.line_total لكل عنصر بجانبه.
PRC2عرض رسم توصيل كل مزوّد.quote لكل مزوّد بمسافة العنوان.
PRC3عرض المجموع الفرعي + التوصيل + الإجمالي.ثلاثة أسطر واضحة.
PRC4تغيّر العنوان.إعادة حساب رسوم التوصيل حيّاً.
PRC5ملاحظة التجميع.«قد يقلّ التوصيل عند سائق واحد» (G4).
PRC6كوبون مطبَّق.سطر خصم + تحديث الإجمالي (الصافي لكل عنصر، G6).
PRC7حذف عنصر/مزوّد.تحديث فوري لكل الأسطر.
PRC8مزوّد تحت الحدّ الأدنى.تمييز بصري + رسالة الحدّ الأدنى.
الإجمالي: ٦٦ (من v2: حالات العنصر/الدفع/الاسترجاع/التوصيل/التعارضات) + DEL12 + PRC8 = ٨٦ سيناريو أساسياً، كلٌّ يتفرّع لمئات الفروع عند البناء.

١٣ أحدث التقنيات (محفوظة من v2 + إضافات)

  • 🌐 Line-Item Order Model (Shopify/Amazon) — العنصر ذرّة السعر/الحالة/الاسترجاع.
  • 🌐 Order Orchestration / Split Routing — تقسيم لكل مزوّد + متابعة موحّدة.
  • 🌐 Per-Item Partial Refund + Commission Recalc — استرجاع عنصر وإعادة عمولته فقط.
  • 🌐 Shipping/Delivery non-refundable on partial return (إضافة v3) — التوصيل لا يُرجَع على إرجاع جزئي (G1).
  • 🌐 Saga + Idempotent Compensation — تعويض ما بعد الدفع على مستوى العنصر/المزوّد.
  • 🌐 Idempotent Ledger + Idempotency Key — لكل قيد مرجع فريد (order_item_id).
  • 🌐 Multi-Store Single-Cart + Pre-Checkout Bundling (Uber Eats) — رسم محفّز عند التجميع.
  • 🌐 Automated RMA / Return-reason codes — سبب الإرجاع لكل عنصر (قابل لسياسات لكل مزوّد).
  • 🌐 Early fee transparency (Baymard، إضافة v3) — إظهار رسوم التوصيل في السلة يقلّل الهجر.

١٤ أفكار إضافية مقترحة (جديدة من المراجعة)

  • اقتراح تجميع ذكيّ: عند وجود متجر قريب، نقترح إضافته «بنفس رسم التوصيل تقريباً» (Uber pre-checkout bundling) — زيادة قيمة السلة.
  • الاسترجاع لوسيلة الدفع الأصلية: محفظة→محفظة؛ النقد→رصيد محفظة (لأن استرجاع النقد مختوم) — وضوح للعميل.
  • سبب إرجاع + صورة لكل عنصر: RMA حديث، يقلّل النزاعات ويغذّي كشف الاحتيال.
  • «حفظ السلة»/قائمة رغبات: سلة متعدّدة المتاجر تُحفَظ وتُستأنف.
  • سجلّ تعويضات idempotent مركزي: كل إلغاء/استرجاع يُسجَّل بمفتاحه → تدقيق ومنع تكرار.
  • «حجز مخزون» اختياري للعنصر: لتقليل «نفد بعد الدفع» في المتاجر عالية الطلب (مرحلة لاحقة).
  • عرض «وفّرت X بالتجميع»: عند سائق واحد، إظهار التوفير في رسم التوصيل (تحفيز نفسي).

١٥ أسئلة وأجوبة (تراكمية)

هل يُرجَع رسم التوصيل عند إرجاع سلعة واحدة؟
لا (G1). فقط عند إلغاء المزوّد كاملاً قبل انطلاق السائق.
كيف نسترجع جزءاً من حجز محفظة كلّي؟
بإضافة تخصيص لكل عنصر + تحرير/التزام جزئي بالمبلغ (G2).
ماذا لو نزل مزوّد تحت حدّه الأدنى بعد الحذف؟
تنبيه + حجب دفع ذلك المزوّد حتى يُحَلّ (G3).
هل يكسر هذا الطلب المفرد الحالي؟
لا — group_id=null = السلوك الحالي حرفياً، والطلب المفرد = حالة خاصّة (عنصر/مزوّد واحد).
كيف يبقى الدفتر متوازناً مع الكوبون والاسترجاع؟
نخزّن الصافي المدفوع لكل عنصر (G6)، فالاسترجاع يعيد ما دُفع فعلاً، وكل قيد idempotent.
