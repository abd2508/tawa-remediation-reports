المرحلة 2 الإنتاج + التتبّع + العناوين

التتبّع الحيّ (SSE) عبر react-native-sse مع إعادة اتصال وتراجع تلقائي إلى polling · العناوين (مخزن + شاشة + ربط بالدفع، يمنع الطلب بلا عنوان) · ربط الخادم الحقيقي للمصادقة + هيكل المتاجر/الطلبات (يُبدّل بإعداد واحد). ملاحظة صريحة: توليد الأنواع التلقائي تعذّر لأن openapi.json مُعطّل على الإنتاج (تقوية أمنية، 404) — فأبقينا النماذج المكتوبة يدوياً، والسكربت جاهز لبيئة تطوير تُفعّل فيها الوثائق.

المرحلة 3 دون اتصال + إشعارات + رصد + أمان

طابور دون اتصال: عند انقطاع الشبكة يُحفظ الطلب ويُرسَل تلقائياً عند العودة (مع idempotency يمنع التكرار) — مُختبَر · إشعارات: تسجيل رمز FCM الأصلي (getDevicePushTokenAsync) للخادم الحالي · Sentry لرصد الأعطال (خامل بلا DSN) · أمان البناء: expo-build-properties (minSdk 23، منع النص الصريح).

5) كيف تنشره (بعد تسجيل دخولك)

cd platform/apps/mobile
npm i -g eas-cli
eas login                                            # حسابك على Expo
eas credentials                                      # رفع مفتاح tawa-release.jks (نفس Flutter)
eas build --platform android --profile production    # ينتج AAB موقّعاً
eas submit --platform android                        # يرفعه إلى Google Play

البناء يتم عبر EAS السحابي — يتفادى هشاشة أدوات البناء المحلية، وينتج AAB جاهزاً. التحديثات اللاحقة الصامتة عبر eas update (OTA).

8) الخطوة التالية المقترحة

  1. تزوّدني بـ google-services.json + DSN (اختياري) → أفعّل الإشعارات والرصد فعلياً.
  2. تسجّل دخول EAS (أو تعطيني إذناً) → أبني AAB وأرفعه لمسار اختبار داخلي على Play.
  3. بناء Dev Client لتشغيل التحقّقات التقنية (OTA على جهاز قديم · SSE حيّ · الخرائط) على جهاز فعلي.
