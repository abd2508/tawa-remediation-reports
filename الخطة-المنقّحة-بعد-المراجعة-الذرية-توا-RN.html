1) كيف أجريت المراجعة الذرية

لم أكتفِ بإعادة قراءة الخطة. دقّقت كل ادعاء تقني فيها مقابل واقع React Native/Expo الأصلي (Native)، لأن «الشيطان في التفاصيل الأصلية». سألت في كل بند: هل هذا مدعوم فعلاً؟ هل يحتاج مكتبة؟ هل يعمل على الأجهزة القديمة؟ هل يتعارض مع شيء؟ هل توقيت/ترتيب التنفيذ صحيح؟

الخلاصة: الخطة السليمة في جوهرها، لكن المراجعة كشفت 24 نقطة (منها 4 حرجة) كانت ستسبّب مشاكل حقيقية لو بدأنا الكود مباشرة — أبرزها أن SSE والخرائط والإشعارات لا تعمل «تلقائياً» في RN كما توحي الخطة الأولى، وأن التحديث الذاتي قد يفشل على نفس الأجهزة القديمة لسبب الشهادة. كلها عولِجت أدناه.

3حرجإشعارات الدفع: الخطة لم تحدّد نوع الرمز. الخادم الحالي يتوقّع رمز FCM أصلي (≤500 محرف)، لا رمز Expo Push.استخدام getDevicePushTokenAsync() (رمز FCM الأصلي) وتسجيله في /notifications/device-tokens الموجود — لا رمز Expo.
4حرجالخرائط: «خرائط OSM» — لكن RN لا خرائط مدمجة؛ تحتاج مكتبة أصلية + dev build.@maplibre/maplibre-react-native (متجهات بلا مفتاح) أو react-native-maps مع بلاطات OSM. تُحسم في م2 بعد spike.
5مهم«In-App Update الأصلي» معامَل كأنه مدمج — هو ليس كذلك في RN.EAS Update هو الأساس؛ التحديث الأصلي عبر مكتبة (expo plugin/react-native-in-app-updates) كطبقة ثانوية اختيارية.
6مهم«حزم جذور الشهادات» بلا آلية دقيقة.عبر Android network_security_config (إضافة @raw/isrg_root_x1 + system) باستخدام config plugin / expo-build-properties؛ iOS تتكفّل به Apple.
7مهمMonorepo: وضع RN داخل المستودع قد يكسر محلّل Metro (hoisting/watchFolders).البدء بحزمة مستقلة (node_modules خاصة) لتقليل المخاطر، ومشاركة الأنواع لاحقاً عبر حزمة مشتركة عند الحاجة فقط.
8مهماستمرارية المتجر: لم تميّز بين «مفتاح الرفع» و«مفتاح التوقيع» عند تفعيل Play App Signing.إن كان Play App Signing مفعّلاً → المهم مطابقة مفتاح الرفع (upload key)؛ وإلا مطابقة مفتاح التوقيع نفسه. نؤكّد حالة المتجر قبل البناء.
9مهمالأنواع (types) كانت ستُكتب يدوياً → خطر انجراف عن الخادم.توليد الأنواع تلقائياً بـ openapi-typescript من /openapi.json الحيّ للخادم → عقد دقيق ومتزامن.
10مهمتوافق New Architecture غير محسوم لكل مكتبة (FlashList/Reanimated/MMKV تتطلبها).مصفوفة توافق صريحة (القسم 3) تُفحص قبل التثبيت + spike في م0.
11مهمتكيّف الجهاز اعتمد على deviceYearClass غير الموثوق.الاعتماد أساساً على totalMemory + إشارات وقت التشغيل (jank/الشبكة)؛ السنة كمؤشّر ثانوي فقط.
12مهمالحالة المخزّنة (سلة/إعدادات) بلا خطة ترحيل → خطر انهيار بعد تحديث يغيّر الشكل.رقم نسخة + دوال migration لمخزون Zustand/MMKV (تجاهل/تحويل آمن للبيانات القديمة).
13مهم«طابور العمليات دون اتصال» ذُكر بعمومية.آلية ملموسة: طابور دائم (MMKV/SQLite) + إعادة تشغيل عند عودة الاتصال + idempotency، تطبَّق على إنشاء الطلب أولاً.
14مهمRTL: لم تُذكر حاجة إعادة التشغيل عند forceRTL أول مرة/عند تغيير اللغة.ضبط الاتجاه مبكراً + إعادة تحميل مُدارة (expo-updates reloadAsync) مرّة واحدة بسلاسة.
15مهمتعايش التطوير: بناء dev بنفس ly.tawa.app يمنع التثبيت بجانب غيره.بناء dev/staging بلاحقة .dev/.staging؛ الإصدار فقط بـ ly.tawa.app المجرّد.
16مهمexpo-updates لا يعمل في Expo Go، وOTA يُطبَّق فقط ضمن نفس runtimeVersion.تطوير عبر Dev Client؛ سياسة runtimeVersion = fingerprint (تلقائية) لمنع تطبيق تحديث غير متوافق.
17تحسينالصور عبر Image الافتراضي.استخدام expo-image (كاش وذاكرة وأداء أفضل، يدعم placeholder/blurhash).
18تحسينتنسيق التواريخ/الأرقام بالعربية على Hermes محدود (Intl ناقص).دالة تنسيق مخصّصة للعربية/العملة (mills/«د.ل») + polyfills @formatjs عند الحاجة.

4) تصحيحات معمارية حاسمة

🛰️ التتبّع الحيّ (SSE)

RN لا يملك EventSource. نستخدم react-native-sse: اتصال بـ /sse/orders/{id}/track?token=، تحديث الـ Timeline والخريطة لحظياً، وعند الانقطاع إعادة اتصال بـ backoff ثم تراجع إلى polling. كل شيء fail-safe.

🔔 الإشعارات

عبر expo-notifications لكن نُسجّل رمز FCM الأصلي (getDevicePushTokenAsync) في /notifications/device-tokens الموجود — ليطابق نظام الخادم الحالي (FCM v1) بلا تغييره.

🔐 الشهادات على الأجهزة القديمة

نحزم ISRG Root X1 (+ جذر احتياطي) في network_security_config عبر config plugin. هذا يجعل التطبيق يثق بالخادم وأيضاً يغطّي حركة EAS Update (نفس طبقة OkHttp) → التحديث الذاتي يعمل حتى على القديم. يُتحقَّق بـ spike على جهاز فعلي.

🗺️ الخرائط

@maplibre/maplibre-react-native (متجهات، بلا مفتاح API) أو react-native-maps ببلاطات OSM. يتطلّب Dev Build. يُحسم في م2 ببناء تجريبي قصير.

🧩 الأنواع من الخادم

توليد الأنواع تلقائياً بـ openapi-typescript من /openapi.json الحيّ → عقد دقيق متزامن مع الخادم، يقلّ خطر الانجراف، ويُحدَّث بأمر واحد.

📦 Monorepo / Metro

حزمة مستقلة في platform/apps/mobile بـ node_modules خاصة (تتفادى تعقيد Metro/hoisting). مشاركة الأنواع لاحقاً عبر حزمة مشتركة فقط عند الحاجة.

7) الأمان العميق (مُنقّح)

  • النقل: HTTPS + جذور محزومة (network_security_config) + تثبيت اختياري + مهلة لكل طلب.
  • المصادقة: access قصير + refresh دوّار مع mutex + ربط بالجهاز + TOTP + مهلة خمول (خادم) + خروج يمسح كل شيء.
  • التخزين: الرموز في SecureStore فقط · الكاش في MMKV مشفّر · صفر أسرار في الحزمة (لا حاجة أصلاً لأسرار عميل؛ BASE_URL ليس سرّاً).
  • سلامة التطبيق: كشف Root + Play Integrity (خادم) + منع debuggable + Hermes bytecode + لا console.log في الإنتاج.
  • المدخلات/الخصوصية: تحقّق Zod لكل إدخال + أقل صلاحيات + منع نسخ بيانات الجلسة + منع لقطة الشاشة على الحسّاس (اختياري).
  • الرصد: Sentry لرصد الأعطال + ربطه بقدرة تراجع OTA (لو ظهر عطل بعد تحديث، نتراجع فوراً).
