📌 باختصار — ماذا صار

فُكّ ختم الدفع بالنقاط: يستطيع العميل الآن أن يدفع قيمة الأصناف (كلًّا أو جزءًا) بنقاط الولاء، مع إكمال الباقي (والرسوم) من المحفظة و/أو النقد — في طلب واحد بثلاثة أوعية (نقاط + محفظة + نقد). في صفحة الدفع يظهر «ادفع بالنقاط» مع رصيده «المتاح: X د.ل». النقاط تُحجَز عند الطلب، وتُثبَّت عند التسليم كـدعم تموّله المنصّة (المزوّد يأخذ قيمة الأصناف كاملةً)، وتُعاد عند الإلغاء. أثبتُّ حيًّا أنّ الدفتر يتوازن، والمزوّد يأخذ الأصناف كاملةً، ومصروف الولاء يساوي قيمة النقاط بالضبط.

① لماذا هذا آمن (ولا يلمس الختم الماليّ الكبير)

بلغة بسيطة: النقاط ليست نقودًا حقيقية تدخل أو تخرج — هي مكافأة تموّلها المنصّة. حين يدفع العميل بنقاطه، المنصّة هي من تدفع للمتجر بدله (تُسجّلها «مصروف ولاء»). لذلك لا حركة نقد خارجيّ إطلاقًا — وهذا يختلف عن الكرت/الدفع الإلكترونيّ الذي يبقى مختومًا. ففكّ النقاط تمّ عبر مفتاح مستقلّ (loyalty_redemption_enabled) دون مساس بالعقد المختوم production_payment_enabled.

② كيف يعمل (القيد المحاسبيّ)

قيد التثبيت (عند التسليم):   DR  PLATFORM_LOYALTY_EXPENSE   P   (المنصّة تتحمّل قيمة النقاط)
                            CR  ORDER_RECEIVABLE_{order}   P   (المزوّد يُدفَع كامل الأصناف)
«الأصناف أوّلًا» مع ثلاثة أوعية: النقاط تغطّي الأصناف أوّلًا، ثمّ المحفظة (أصناف ثمّ رسوم)، ثمّ النقد الباقي. النتيجة دائمًا: مستحقّ المزوّد = الأصناف كاملةً · إيراد المنصّة = الرسوم + الفكّة · مصروف ولاء = قيمة النقاط. النقاط لا تغطّي الرسوم ولا الإكراميّة (إيراد المنصّة وحقّ السائق).
الطريقة العالميّة (Amazon/Starbucks/Talabat + معيار IFRS): النقاط وعاء دفع لا خصم، تُسحَب من حساب يخصّ الولاء (هنا: مصروف منصّة — نموذج MVP مبسّط؛ يمكن لاحقًا ترقيته إلى «التزام مؤجَّل» الكامل IFRS-15). تغطّي الأصناف لا رسوم التوصيل (القاعدة الإقليمية)، وتُعاد نقاطًا لا نقدًا عند الاسترداد (ضابط مكافحة الغسل).

③ الإثبات الحيّ (توازن الدفتر بثلاثة أوعية)

أنشأتُ على السيرفر طلبًا حقيقيًّا بثلاثة أوعية (إجماليّ 23.000 = أصناف 20.000 + رسوم 3.000، مقسّم: 5.000 نقاط + 8.000 محفظة + 10.000 نقد) وقُدتُه للتسليم، ثمّ فحصتُ الدفتر:

tenders = [(LOYALTY_POINTS, 5000, HELD), (WALLET, 8000, HELD), (CASH, 10000, PENDING)]
points deducted = 500 pts   (= 5000 mills × rate 100 / 1000)   →  True
P + W + C = 5000 + 8000 + 10000 = 23000 == grand              →  True
LEDGER balanced?         DR=31000 == CR=31000                 →  True
provider receivable == goods?   20000 == 20000               →  True
loyalty expense == points value?  5000 == 5000               →  True
الخلاصة: القلب الماليّ صحيح بثلاثة أوعية — النقاط تُخصَم وتُثبَّت، الدفتر متوازن، المزوّد يأخذ الأصناف كاملةً، والمنصّة تتحمّل قيمة النقاط بالضبط.
