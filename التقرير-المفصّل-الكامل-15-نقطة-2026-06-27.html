5نظام العميل المميَّز VIP ⭐فضّي ⭐ذهبيّ ⭐بلاتينيّ حيّ
العَرَض: كان هناك «vip لكل مزوّد» (≥20 طلبًا) لكنّه غير ظاهر في الطابور، غير مستخدَم في الترتيب، بلا طبقات ولا شارة ولا لوحة.
الحلّ (كامل):
  • درجة عالميّة (0–100) = عدد طلبات العميل × وزن (افتراضي 2)، تُحسَب تلقائيًّا بعد كل طلب.
  • طبقات: فضّي ≥40 · ذهبيّ ≥65 · بلاتينيّ ≥85 (عتبات قابلة للضبط).
  • شارة ⭐ VIP ملوّنة عند المزوّد (والجوّال).
  • أولويّة التحضير: VIP يُرتَّب أوّلًا في طابور المزوّد.
  • لوحة OPS: تعيين/إزالة يدويّ (vip_ops_override يُثبّت الطبقة).
العدالة (الأهمّ — لئلّا يُجوَّع العاديّون): الترتيب = الحالة ← درجة VIP ← الأقدم؛ لكن طلب عميل عاديّ ينتظر أكثر من vip_fairness_aging_minutes (افتراضي 8 دقائق) يُرفَع إلى مستوى VIP تلقائيًّا (التقادم/aging) فلا يُنسى أبدًا. تحميل درجات الطابور دفعةً واحدة (لا N+1).

aa67 — قائمة الحظر (فوق aa66)

CREATE TABLE customer_blocklist (
  id          VARCHAR(36) PRIMARY KEY,
  customer_id VARCHAR(36) NOT NULL REFERENCES users(id),
  target_type VARCHAR(10) NOT NULL,        -- 'PROVIDER' | 'DRIVER'
  target_id   VARCHAR(36) NOT NULL,
  reason      VARCHAR(200) NULL,           -- خاصّ، لا يظهر للسائق
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT ck_block_target_type CHECK (target_type IN ('PROVIDER','DRIVER')),
  CONSTRAINT uq_block_once UNIQUE (customer_id, target_type, target_id)   -- idempotent
);
CREATE INDEX idx_block_customer_type ON customer_blocklist(customer_id, target_type);
