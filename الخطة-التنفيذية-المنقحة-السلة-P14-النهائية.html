⚖️ القرارات المعمارية — محسومة ومبرّرة

قرار 1: OTP — داخل الصفحة (Inline) لا نافذة منبثقة

الخيارات: Inline (تبقى السلة ظاهرة) · Modal (يغطي السلة) · Page redirect (يخسر السياق)

القرار: Inline. التحليل العالمي (Grab, DoorDash, Amazon) يؤكد: الـ modal مقبول لقرارات اختيارية، لكن OTP لإكمال دفع ضروري → inline أعلى معدل إكمال. الخادم يُعيد failed_index → نعرض OTP أسفل بطاقة المتجر المُسبِّب.

الكود المصدر: نسخ startOtpFlow من CheckoutPage سطر 470-491 بالضبط + resendOtp + 30 ثانية cooldown.

قرار 2: شاشة النجاح — عرض فوري ثم إثراء async

الخيارات: انتظر كل ordersApi.get() (بطيء) · اعرض فوراً من CartGroupResult ثم أضف handoff_codes لاحقاً

القرار: عرض فوري. CartGroupResult يحتوي order_id + total_minor + delivery_fee_minor — يكفي للعرض الفوري. handoff_code و cash_due_minor تُجلب async وتُضاف بـ "—" placeholder. DoorDash يعرض confirmation رقم فوراً.

قرار 3: تحذير المحفظة — عرض تحذير لا تعطيل الزر

الخيارات: عطّل الزر إذا الرصيد ناقص · اعرض تحذيراً واترك الخادم يرفض

القرار: تحذير فقط (معيار Uber Eats, Talabat, Noon). التحقق الحقيقي يكون على الخادم دائماً. إذا عطّلنا الزر client-side، قد يُفوّت المستخدم حالة تغيّر فيها الرصيد (شحن من مكان آخر). استثناء: إذا الرصيد صفر بالضبط → نعطّل WALLET مباشرة.

قرار 4: إدارة الحالة — useReducer للـ checkout flow + useState للنماذج

القرار: useReducer بـ discriminated union لحالات الـ checkout:

type CheckoutState = | { phase: 'idle' } | { phase: 'processing' } | { phase: 'otp_required'; forIndex: number; forPurpose: 'COD'|'WALLET' } | { phase: 'wallet_step_up'; forIndex: number } | { phase: 'terms_block'; missing: TermsDoc[] } | { phase: 'debt_block' } | { phase: 'locked'; reason: string } // COD_BLOCKED_HIGH_RISK | { phase: 'success'; orders: SuccessOrder[] } | { phase: 'error'; message: string; failedIndex: number|null };

لماذا: TypeScript يُجبر على معالجة كل حالة في switch/match. المطوّر المقبل لا يستطيع نسيان حالة.

قرار 5: group_map في localStorage — آخر 20 مجموعة، LRU

تُحفظ عند النجاح، تُقرأ في OrderHistoryPage. تُنظَّف إلى 20 عند الإضافة. تُحذف من الجلسة بعد خروج المستخدم من شاشة النجاح (واجهة cleanup effect). المفتاح يحمل إصدار: tawa_gmap_v1.

قرار 6: الحد الأدنى للطلب — تعطيل الزر + تحذير inline

على خلاف المحفظة، الحد الأدنى يُعرَف client-side بدقة (من بيانات المتجر المحمَّلة في المرحلة 1). تعطيل الزر + تحذير يمنع إرسالاً سيُرفَض حتماً. معيار: Shopify, WooCommerce يعطّلان الزر على minimum order.

قرار 7: انتهاء OTP — زر "أعد إرسال الرمز" بعد 30 ثانية

نسخ countdown pattern من CheckoutPage (otpResendIn, setTimeout). لا نُعيد الطلب تلقائياً — المستخدم يختار. إذا حاول التحقق بكود منتهٍ → خطأ واضح "الرمز منتهٍ — أعد الإرسال".
