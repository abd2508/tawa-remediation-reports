📌 باختصار — ماذا صار

صار بإمكان العميل أن يدفع طلبًا واحدًا بـوسيلتين معًا: جزء من المحفظة + الباقي نقدًا عند الباب. في صفحة الدفع، عند اختيار «نقدًا» يظهر مفتاح «ادفع جزءًا من المحفظة؟» — يُدخِل العميل مبلغ المحفظة، فيُحسَب الباقي النقديّ حيًّا. الخادم هو من يتحقّق أنّ المجموع = الإجماليّ وأنّ رصيد المحفظة يكفي، ويحجز حصّة المحفظة فقط، ويترك الباقي يُحصَّل (مقرَّبًا للفكّة) عند الباب. أثبتُّ حيًّا أنّ الدفتر المحاسبيّ يتوازن تمامًا وأنّ المزوّد يأخذ قيمة الأصناف كاملةً مهما قسّم العميل دفعه.

① كيف يبدو للعميل

بلغة بسيطة: العميل لديه مثلًا 23 د.ل ليدفعها. عنده في المحفظة 11.5 د.ل ومعه نقدًا 11.5 د.ل. يختار «نقدًا» ثمّ يفعّل «ادفع جزءًا من المحفظة؟»، يكتب 11.500 في خانة المحفظة — فيُظهر النظام فورًا «نقداً عند الباب: 11.500». يؤكّد الطلب، فتُحجَز 11.5 من محفظته، ويُحصّل السائق 11.5 نقدًا عند التسليم.
مفتاح + خانة محفظة + الباقي النقديّ يُحسَب حيًّا — والخادم سيّد القرار (لا يثق بحساب الهاتف)

② كيف يعمل (بأمان على القلب الماليّ)

الخطوةماذا يحدث
عند الطلبالخادم يتحقّق: فقط نقد+محفظة · المجموع = الإجماليّ · رصيد المحفظة يكفي حصّتها W → يَحجِز W فقط (لا الإجماليّ) · يضع الحالة «SPLIT»
التسجيليُسجَّل وعاءان (محفظة W محجوز · نقد C معلّق) + يُخزَّن الباقي النقديّ للعرض
عند البابالسائق يُحصّل الجزء النقديّ فقط (C مقرَّبًا + الإكراميّة) — لا الإجماليّ
عند التسليمتُثبَّت حصّة المحفظة (commit) + يُقيَّد النقد المُحصَّل — قيود متوازنة
عند الإلغاءتُعاد حصّة المحفظة المحجوزة للعميل (مُمركَز في 6 مسارات)
«الإسناد بالأصناف أوّلًا» — لماذا الدفتر يبقى صحيحًا: حصّة المحفظة تدفع قيمة الأصناف أوّلًا ثمّ الرسوم؛ والنقد يدفع الباقي. فمهما قسّم العميل، يبلغ مستحقّ المزوّد = قيمة الأصناف كاملةً، وإيراد المنصّة = الرسوم + فرق الفكّة. وهذا تعميم يطابق السلوك القديم تمامًا: الطلب النقديّ الكامل = حصّة محفظة صفر، والمحفظة الكاملة = حصّة نقد صفر. لذلك لم ينكسر شيء في الدفع المفرد.

③ الإثبات الحيّ (توازن الدفتر)

أنشأتُ على السيرفر طلب SPLIT حقيقيًّا (23.000 = أصناف 20.000 + رسوم 3.000، مقسّمًا 11.5 محفظة + 11.5 نقدًا) وقُدتُه عبر تثبيت المحفظة + تحصيل النقد، ثمّ فحصتُ الدفتر:

method = SPLIT · reservation = 11500 (الحجز = حصّة المحفظة فقط، لا 23000)
tenders = [(CASH, 11500), (WALLET, 11500)]
wallet debited by W?  11500 == 11500  →  True   (خُصِم W فقط)
LEDGER balanced?  DR=34500 == CR=34500  →  True   (مدين = دائن)
provider receivable == goods?  20000 == 20000  →  True   (المزوّد يأخذ الأصناف كاملةً)
الخلاصة: القلب الماليّ صحيح — حجز جزئيّ سليم، دفتر متوازن، ومستحقّ المزوّد دقيق مهما قسّم العميل دفعه.

④ كيف ضمنّا ألا يُفسد شيئًا

  • لا هجرة: أُعيد استخدام جدول الأوعية (aa66) القائم + قيمة payment_method="SPLIT" (الحقل نصّ، يتّسع) — لا تغيير مخطّط.
  • تعميم لا تفريع: الدفع المفرد (نقد/محفظة) = حالة خاصّة من العامّ، فالسلوك القائم مُثبَت غير متغيّر (109 اختبار أخضر).
  • تحقّق خادميّ كامل: الخادم يُعيد حساب المجموع ويرفض أي تلاعب (422) قبل أي حركة مال.
  • دالة إسناد مركزيّة واحدة (attribute_goods_fee) يستخدمها قيد المحفظة وقيد النقد معًا — فلا تتباعد الحسابات.
  • مسارات الإطلاق الستّة مُمركَزة: إلغاء طلب مقسّط يُعيد حصّة المحفظة عبر كل المسارات.
  • النقاط/الكرت مختومان: الأوعية المقبولة في هذا التفعيل = نقد + محفظة فقط.
