A.2 جَوهر العَيب — لا بوّابة دفع

الفحوصات قَبل balance += amount هي فحوصات هويّة + سرعة:

  • velocity_check (يَمنع الإفراط لكنّه لا يَتحقّق من دفع).
  • OTP gate (يُثبت ملكيّة الهاتف لكن لا يُثبت دَفع).
  • wallet_session_token (تَوكيد جلسة OTP، لا دفع).
  • beneficiary guard (يَمنع شحن محفظة غيرك، لا علاقة بالدفع).

أيّ منها لا يَلمس بوّابة دفع. النَتيجة: المستخدم يَدخل OTP صحيحاً ⇒ المبلغ يُضاف من العَدم.

مُلاحَظتان حاسمتان:
  1. _ETA_DONE_STATES = {DELIVERED, CANCELLED_*, REJECTED, EXPIRED, DELIVERY_FAILED, RETURNED, DISPUTED, DISPUTE_RESOLVED, SCHEDULED}. لا تَشمل PENDING_PAYMENT ولا AWAITING_PROVIDER_ACCEPTANCE. النَتيجة: العدّاد يَظهر منذ ثانية إنشاء الطلب.
  2. القيمة المُرجَعة هي provider.default_prep_time_min — قيمة ثابتة في إعدادات المزوّد (افتراضي 30 دقيقة في models/provider.py:46). لا تَعتمد على «متى بَدأ التحضير».

B.2 البيانات المَطلوبة موجودة بالفعل — لكنّها مُهمَلة

نَموذج Order يَحوي ثلاثة timestamps مَناسبين كَـanchor:

العمودمتى يُضبَطالموقع
created_atإنشاء الطلبتلقائيّ
provider_responded_atعند قَبول/رَفض المزوّدprovider_service.py:107

كذلك OrderSummary schema يَكشف provider_response_deadline_at (المرحلة 450-W5-1) كَ«المطعم لديه 04:32 لقَبول طلبك» — لكنّ هذا للقَبول، ليس للتَحضير.

الفرصة: أَضِف prep_deadline_at = order.prepared_at + provider.default_prep_time_min، يَكون null إلّا في حالة الطلب IN_PREPARATION أو READY_FOR_PICKUP.

B.3 لماذا يُصفَّر عند العَودة للصفحة؟

سَبب فُورِيّ: OrderCountdown مكوّن React يُحمَّل (mount) عند الدُّخول للصفحة. الحالة الابتدائيّة:

useState(etaMinutes * 60)

كلّ زِيارة جديدة:

  1. المسار /orders/:id يُفعَّل ⇒ OrderTrackingPage يُحمَّل ⇒ OrderCountdown يُحمَّل.
  2. تُنفَّذ السطر useState(etaMinutes * 60) = 30 × 60 = 1800 ثانية.
  3. الـinterval يَبدأ من 1800، يَنزل ثانية ثانية.

حتى لو كانت useQuery مُستخدِمة cache (TanStack Query يَحتفظ بـorder لـ5 دَقائق افتراضياً)، الـcomponent state يُعاد إنشاؤه عند كلّ mount جديد. الكاش لا يَعني شيئاً هنا.

الإصلاح الحَقيقيّ: الواجهة تَحسب Math.max(0, (new Date(deadline_at) - Date.now()) / 1000) — لا تُخزِّن «secondsLeft» كَحالة، بل تَحسبها فوريّاً من timestamp ثابت.

B.4 أيضاً: provider_router.py:68 يُعيد eta_minutes بنفس الالتباس

"eta_minutes": p.default_prep_time_min,        # في بطاقة بحث المزوّد

هذا يَخلط بين «وقت التحضير» و«ETA توصيل» — مَوضوع تَنظيف رمزيّ مَنفصل (لا يَؤثّر على الـbug الحاليّ مَباشرة).

الواجهة: OrderCountdown مُعاد كِتابتها

web/src/components/OrderCountdown.tsx (إعادة كَتابة كاملة)
import { useState, useEffect } from "react";
import { useTranslation } from "react-i18next";

interface Props {
  deadlineAt: string;   // ISO timestamp from server (single source of truth)
}

export function OrderCountdown({ deadlineAt }: Props) {
  const { t } = useTranslation();
  const compute = () => Math.floor((new Date(deadlineAt).getTime() - Date.now()) / 1000);
  const [secondsLeft, setSecondsLeft] = useState(compute);

  useEffect(() => {
    setSecondsLeft(compute());            // re-anchor on prop change
    const id = setInterval(() => setSecondsLeft(compute()), 1000);
    return () => clearInterval(id);
  }, [deadlineAt]);    // ← anchor باسم الـtimestamp، لا secondsLeft

  const overdue = secondsLeft < 0;
  const abs = Math.abs(secondsLeft);
  const display = `${Math.floor(abs / 60)}:${(abs % 60).toString().padStart(2, "0")}`;

  return (
    <div className="order-countdown" data-overdue={overdue}>
      {overdue
        ? `⏱ ${t("order.delay", { defaultValue: "تَأخّر" })} +${display}`
        : `⏱ ${t("order.time_left_prep", { defaultValue: "جاهز بعد" })} ${display}`}
    </div>
  );
}

F-T-03 — خطوتا «بانتظار المزوّد» و«بانتظار السائق» في الـtimeline

الـtimeline الحاليّ:

مَقبول → قَيد التَحضير → جاهز → في الطَريق → تمّ التَوصيل

المُقترَح:

بانتظار المزوّد → مَقبول → قَيد التَحضير → جاهز → بانتظار السائق → في الطَريق → تمّ التَوصيل

أو بصيغة مَدمجة عند مَلاءَمة المساحة:

بانتظار → قَبول → تَحضير → جاهز → سائق → في الطَريق → تَوصيل

المَواقع: web/src/components/OrderTimeline.tsx — يُضاف خطوتان قَبل وبعد المَواقع المَناسبة، شَرط أن تُظهَر «مُكتمَلة» لو الـorder_state تَجاوزها.

الفائدة: العميل يَفهم أنّ التَأخّر سَببه ما زال «بانتظار قَبول المزوّد» أو «بانتظار قَبول السائق»، فلا يُحبَط من «الوقت المتبقي» وَهميّاً.
