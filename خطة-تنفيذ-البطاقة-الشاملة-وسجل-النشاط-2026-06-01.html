منصّة تووا / Toowa — إظهار كل شيء (بلا إخفاء) + سجلّ الحركات + حالة/أزرار للسرّين · للمراجعة · 2026-06-01
🧭 خطّة للمراجعة — لم يُنفَّذ شيء قرار: السرّان حالة+أزرار (لا قيم خام) 🔒 لا migration · لا مساس بالمالية/FIN-COR
النطاق المُقرّ: في لوحة /ops (محروسة بدور OPS أصلاً): (1) إزالة إخفاء PII · (2) بطاقة مستخدم شاملة بكل الحقول المتاحة · (3) تبويب «سجلّ النشاط» لكل حركة · (4) السرّان (كلمة المرور/TOTP) = حالة + أزرار إعادة ضبط (لا قيم خام — قرارك). الطلبات تبقى في تبويبها. + (5، اختياريّ) بحث بالمعرّف/رقم الطلبيّة.

حقائق الجذور (من الكود الحيّ)

  • نقطة التفاصيل GET /control-panel/users/{id} (control_panel_router.py:544) تُرجع حاليّاً حدّاً أدنى فقط: id · phone(مُخفى) · email(مُخفى) · full_name · status · created_at · roles. لا تُرجع trust_score/username/email_verified/totp/updated_at/الأجهزة/العناوين.
  • الإخفاء: _mask_phone:144 · _mask_email:150 · _mask_wallet_number:160.
  • مصادر النشاط جاهزة: audit_log (actor_id/target_id/action/created_at) · login_attempts (user_id/ip/success/created_at) · otp_events (phone_hash/event_type/ip/created_at).
  • رصيد المحفظة: WalletService.get_balance(user_id) جاهز.
  • كلمة المرور: bcrypt أحاديّة (password_service.py) → النصّ غير قابل للاسترجاع. TOTP: totp_secret بذرة pyotp → لا تُكشف. /totp/disable:681 موجود للمستخدم نفسه فقط. لا توجد نقطة إعادة-تعيين كلمة مرور إداريّة.
  • المزوّد فيه opening_hours (JSON) · is_accepting_orders · active_now (نموذج Provider).

عيوب/قيود اكتُشفت في المحاكاة (مُضمَّنة)

D-1: لا عمود last_login ولا password_changed_at في نموذج User. لذا «آخر دخول» و«تاريخ آخر تغيير لكلمة المرور» يُشتقّان من السجلّ (login_attempts / audit_log)، لا من صفّ المستخدم. سنعرضهما من السجلّ، أو نعرض «—» إن غاب.
D-2: otp_events وlogin_attempts تُخزّن phone_hash (SHA256) لا الهاتف. الاستعلام يجب أن يحسب الهاش بنفس دالّة core/audit.py؛ login_attempts فيه user_id أيضاً (نُفضّله). إن اختلف الهاش → نتيجة فارغة (fail-safe).
D-3: إزالة الإخفاء + إثراء الحقول يكسر الاختبارات التي تتوقّع **** أو الحقول المحدودة → تُحدَّث في نفس الدفعة (إلزاميّ).
D-4: «إعادة تعيين كلمة المرور» — الأأمن أن يُدخل المدير كلمة مرور جديدة في الواجهة → الخلفيّة تُجزّئها → لا سرّ يُرجَع في الاستجابة إطلاقاً (لا توليد/إرجاع). يتجنّب تسريب أي قيمة.
D-5: حلّ كيان الدور: المزوّد عبر Provider.owner_user_id=user، السائق عبر Driver.user_id=user، العميل عبر CustomerProfile.user_id. الإثراء يستعلم حسب دور المستخدم.

مسارات العمل

WS-1 · إزالة الإخفاء قرار سابق

في control_panel_router.py: تجاوز _mask_phone/_mask_email/_mask_wallet_number في القوائم (users/customers/drivers/providers) ونقطة التفاصيل ونقطة المحافظ → قيم كاملة. الحارس بدور OPS يبقى. يحلّ تناقض البحث↔البطاقة.

ملفّات: control_panel_router.py (≈8 مواضع mask)
WS-2 · إثراء بطاقة المستخدم (نقطة التفاصيل)

إضافة إلى GET /control-panel/users/{id} كل حقول User (عدا password_hash+totp_secret): phone(كامل) · email+email_verified · display_name · username · status · trust_score · totp_enabled · locale · created_at · updated_at · roles(+verified_at) · حقول الحذف. + password_set (bool) · totp_enabled (bool). + حسب الدور:

  • عميل: CustomerProfile + get_balance (رصيد) + العناوين + الأجهزة/الجلسات.
  • مزوّد: كل حقول Provider incl. opening_hours · is_accepting_orders · active_now · min order · رسوم/تسعير التوصيل · التقييم · زمن التحضير · الوصف · العنوان+الإحداثيّات · المخاطرة · الشعار · كود الطاقم.
  • سائق: Driver + المركبة (اللوحة) + cash_outstanding + cash_limit + available + التقييم + الموقع.
محاكاة: استجابة أكبر (مقبول، لمستخدم واحد). الأجهزة/الجلسات/العناوين عبر علاقات User (selectinload لتفادي N+1). رصيد المحفظة استدعاء واحد. خطر: كسر اختبارات الحقول المحدودة (D-3) → تُحدَّث.
WS-3 · سجلّ النشاط نقطة جديدة

نقطة GET /control-panel/users/{id}/activity?limit=&offset= (OPS) تدمج: audit_log (actor_id=id OR target_id=id) + login_attempts (user_id=id أو phone_hash) + otp_events (phone_hash) — مرتّبة بالأحدث، صفحات. كل صف: النوع (تدقيق/دخول/OTP) · الفعل/الحدث · الوقت · IP/الجهاز · النجاح · مَن نفّذه.

محاكاة: يعرض «كل حركة». phone_hash يُحسب بدالّة core/audit (D-2)؛ login عبر user_id أساساً. حدّ افتراضيّ 50 صفّاً + «عرض المزيد». الطلبات لا تُكرَّر (تبويب منفصل).
WS-4 · السرّان: حالة + أزرار نقطتان جديدتان
  • التفاصيل تُرجع: password_set (bool) · totp_enabled (bool) + (إن توفّر من السجلّ) آخر تغيير/آخر دخول. لا hash ولا secret خام.
  • POST /control-panel/users/{id}/reset-password (SUPER_ADMIN · مُدقَّق) — يستقبل كلمة مرور جديدة يكتبها المدير → hash_password → لا يُرجع سرّاً (D-4).
  • POST /control-panel/users/{id}/disable-totp (SUPER_ADMIN · مُدقَّق) — يُفرّغ totp_secret + totp_enabled=False لمستخدم آخر.
محاكاة: مدير يفتح مستخدماً محبوساً → «إعادة تعيين كلمة المرور» (يُدخل واحدة جديدة) أو «تعطيل TOTP» → يساعده دون رؤية أي سرّ. كلاهما SUPER_ADMIN + يُسجَّل في audit_log.
WS-5 · بحث بالمعرّف + رقم الطلبيّة اختياريّ

توسيع search_users لمطابقة id أيضاً + نقطة بحث طلب order-id → يفتح الطلب/العميل. (يكمّل Rec ج؛ يمكن دفعة تالية.)

WS-6 · الواجهة

في درج كل من ControlPanelCustomers/Drivers/Providers/Users: توسيع تبويب «معلومات» بكل الحقول · تبويب جديد «السجلّ» · حالة السرّين + زرّا «إعادة تعيين كلمة المرور»/«تعطيل TOTP» (للسوبر أدمن). الطلبات تبقى كتبويب.
