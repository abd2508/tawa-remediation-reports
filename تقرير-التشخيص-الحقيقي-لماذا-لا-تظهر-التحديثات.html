المستخدم الذي سبق وزار الموقع قد يرى نسخة قديمة

تشبيه بسيط
تخيّل أن لديك موظف استقبال يحفظ نسخة قديمة من القائمة ويعطيها لكل زبون. حتى لو المطبخ غيّر القائمة، الموظف يعطي النسخة القديمة.

لكي يحدّث الموظف نسخته، يجب أن يلاحظ أن الملف الأصلي تغيّر. مشكلتنا: Cloudflare يعطيه الملف القديم لمدة ٤ ساعات → الموظف لا يعلم بالتغيير.

المرحلة الأولى: إصلاح آلية التحديث (nginx + Cloudflare)

هذا لا يُضيف ميزات — لكنه يضمن أن أي ميزة تُضاف في المستقبل تصل للمستخدم خلال ٦٠ ثانية لا ٤ ساعات.

# 1. تعديل web/nginx.conf — إضافة 3 قواعد location = /sw.js { add_header Cache-Control "no-store, no-cache, must-revalidate, max-age=0" always; add_header Pragma "no-cache" always; try_files $uri =404; } location = /index.html { add_header Cache-Control "no-cache, must-revalidate" always; try_files $uri =404; } location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable" always; try_files $uri =404; } # 2. إعادة بناء ونشر الـ dist على الخوادم الأربعة # 3. Cloudflare → Cache → Custom Purge → /sw.js
ملاحظة مهمة: هذا الإصلاح لوحده لن يظهر للمستخدم أي ميزة جديدة. يُصلح فقط آلية التحديث للمستقبل. لرؤية ميزات جديدة، يجب بناء الواجهات (المرحلة الثانية).
