5) العيب الأوّل (HIGH) — crypto.randomUUID يكسر كل طلبات الواجهة على HTTP-LAN

العَرَض

أوّل محاولة تسجيل عميل عبر الواجهة أظهرت «حدث خطأ غير متوقع» — بلا أيّ طلب يصل الخلفية وبلا خطأ في الـconsole.

التشخيص (مايكروسكوبيّ)

اختبارالنتيجةالاستنتاج

السبب الجذريّ

في web/src/api/client.ts يضيف interceptor الطلب ترويستَي X-Correlation-Id وIdempotency-Key عبر crypto.randomUUID(). هذه الدالة متاحة فقط في «سياق آمن» (HTTPS أو http://localhost). على http://192.168.178.194:8090 (HTTP + غير-localhost) تكون undefined ← الـinterceptor يرمي استثناءً على كل طلب ← axios يرفض الطلب قبل إرساله ← لا طلب يصل الخلفية، ولا خطأ console، وتظهر الرسالة العامّة.

لذلك لا يظهر على الإنتاج (HTTPS) ولا على localhost (سياق آمن) — لكنّه يُصيب أيّ نشر HTTP في شبكة/‏IP.

طلب axios من التطبيق | v [ request interceptor ] config.headers["X-Correlation-Id"] = crypto.randomUUID() // undefined على HTTP-LAN | ^^^^^^^^^^^^^^^^^^^ TypeError x axios يرفض الـPromise قبل أيّ شبكة | v [ catch في الصفحة ] ← UNKNOWN_ERROR «حدث خطأ غير متوقع» (لا طلب · لا console)

الإصلاح

// web/src/api/client.ts — بديل يعمل في أيّ سياق
function genUUID(): string {
  if (typeof crypto !== "undefined" && typeof crypto.randomUUID === "function")
      return crypto.randomUUID();        // مفضّل عند توفّره (HTTPS/localhost)
  const b = new Uint8Array(16);
  (crypto?.getRandomValues ? crypto.getRandomValues(b)
     : b.forEach((_,i)=>b[i]=Math.random()*256|0));
  b[6]=(b[6]&0x0f)|0x40; b[8]=(b[8]&0x3f)|0x80;       // RFC-4122 v4
  /* …تنسيق… */ return uuid;
}
// الـinterceptor صار يستخدم genUUID() بدل crypto.randomUUID()

6) العيب الثاني (MEDIUM) — صفحة وثائق المزوّد/السائق تستدعي endpoint إداريّاً فقط

العَرَض

عند فتح صفحة رفع وثائق KYC، ظهر «تعذّر تحميل الوثائق: 403» ولم يُعرَض نموذج الرفع إطلاقاً.

السبب الجذريّ

صفحة ProviderDocuments تجلب قائمة أنواع الوثائق المطلوبة من GET /operations/document-policies، وهو endpoint محصور بأدوار OPS/COMPLIANCE/FINANCE/SUPER. المزوّد/السائق (دور مختلف) يحصل على 403 ← يُكسَر نموذج الرفع كلّه، فلا يستطيع رفع الوثائق ← لا يُعتمَد ← دورة الحياة تتوقّف.

صفحة وثائق المزوّد (PENDING) | تطلب قائمة الوثائق المطلوبة v GET /operations/document-policies ← يتطلّب OPS/COMPLIANCE/FINANCE/SUPER x المزوّد ليس منها → 403 Forbidden | v «تعذّر تحميل الوثائق: 403» → نموذج الرفع لا يُعرَض → الرفع مستحيل

الإصلاح

القائمة بيانات مرجعيّة غير حسّاسة (أيّ أنواع وثائق مطلوبة لكلّ نوع نشاط)، فأضفتُ دورَي المُسجِّل لقراءتها:

// backend/app/modules/operations/operations_router.py

        // Agentic-staging audit (BUG-2): قراءة مرجعيّة للمُسجِّل
        PlatformRole.PROVIDER_ADMIN,   PlatformRole.DRIVER,
    )), …

الفتح: أُعيد بناء صورة الخلفية على الاستاجينج، وتحقّقتُ حيّاً: المزوّد ← GET /operations/document-policies = 200 (كان 403)، فظهر نموذج الرفع وعمل الرفع طرفاً لطرف.

11) ما يعمل جيّداً

✅ يعمل بإتقان

  • التسجيل لكل الأدوار عبر الواجهة (UI→DB).
  • اعتماد الأدمن للوثائق والإعداد (قبول/رفض من الواجهة).
  • بوّابة KYC: لا تفعيل مزوّد/سائق بلا وثائق معتمدة.
  • توقيع العقود الإلكترونيّة (صورة + توقيع + بوّابة حجب).
  • كتالوج المزوّد: إضافة/نشر منتج + فتح/إغلاق المتجر.
  • بحث المزوّدين القريبين (يعتمد active_now + الإحداثيّات).
  • الطلب الكامل: سلّة → عنوان → معاينة رسم التوصيل + الفكّة → نقديّ.
  • التوزيع التلقائيّ للعرض إلى أقرب سائق متاح.
  • الاستلام سلطة المزوّد (كود) + التسليم بكود العميل + إثبات GPS.
  • المحاسبة: كاش + عهدة + تسوية + دفتر أستاذ متوازن.
  • RBAC مُطبَّق على كل الحدود.

⚠️ قيود بيئيّة (ليست عيوب تطبيق)

3 انتقالات يقودها عادةً عتاد الهاتف (يفتقده متصفّح headless) نُفِّذت عبر API التطبيق من سياق المتصفّح (نفس ما يُطلقه الجهاز):

  • توفّر السائق والوصول للوجهة — يُطلقان تلقائيّاً بالـGPS/geofence ميدانيّاً.
  • إرسال الإثبات — الواجهة أعادت قفل علم الكاش المحلّي بعد إعادة التحميل رغم تسجيله خادميّاً.

الكاميرا (العقد/الوثائق) استخدمت fallback مُنتقي الملفّات (زرّ الكاميرا يتحوّل لمُنتقٍ على غير-المحمول) بملفّات «TEST DOCUMENT ONLY».

الـGPS حُقِن بإحداثيّات طرابلس عبر navigator.geolocation لمتصفّح بلا موقع حقيقيّ.
