الحلقة الخلفية _provider_document_warning_loop

  • تَعمل كل ساعة (3600 ثانية) — Redis lock docs:warn:lock TTL 300 ث ⇒ تَشغيل واحد عبر الـreplicas.
  • تُحسب 6 مستويات تنبيه: 3 قبل الانتهاء (60/30/7 يوم افتراضي) + 3 بعد الانتهاء (0/30/60 يوم).
  • Idempotent عبر last_warning_level: لا إغراق للمزوّد بالتنبيهات.
  • auto-close معطَّل افتراضياً (NULL) لكل سياسة — يَتفعّل لمزوّد فقط حين تَضبط OPS عدد أيام في auto_close_after_days.
  • أيّ خطأ لكلّ وثيقة يُسجَّل ويُستكمل المسح — لا يَحجب أيّ شيء.
  • مُعطَّلة في بيئة الاختبار (لا تَتسرّب timers بين الاختبارات).

٢. الواجهة — ما الذي يَراه المزوّد والـOPS؟

للمزوّد

  • ProviderSettings → قسم جديد «📄 وثائق المنشأة» يَظهر للمزوّد النشط (كان مخفياً سابقاً خلف ProviderPending فقط).
  • بطاقة الالتزام: نسبة % + عدّ «منتهية» و«تنتهي خلال 30 يوماً» باللونَين الكهرماني/الأحمر.
  • كل وثيقة بطاقة منفصلة: حالة (مقبولة/قيد المراجعة/مرفوضة/منتهية/لم تُرفع) + تاريخ الانتهاء + سبب الرفض (إن وُجد) + زرّ ♻️ تجديد/استبدال.
  • مكوّن الرفع DocumentUploadField:
    • زرّان: 📷 الكاميرا (capture=environment) + 🖼️ الملفّات/الصور
    • قبول image/* + application/pdf
    • تحذيرات جودة قبل الرفع (حجم < 100 ك.ب أو أبعاد < 600px)
    • إدخال تاريخ انتهاء (إلزامي وفق السياسة)
    • أخطاء الخادم تَظهر بوضوح بلا فشل صامت

للـOPS

  • OpsDocumentInbox (/ops/document-inbox): صندوق وارد موحَّد لكل الوثائق المعلَّقة عبر كل المزوّدين + قبول/رفض سريع + اختيار سبب من قائمة + ملاحظة نصّية.
  • OpsDocumentPolicies (/ops/document-policies، SUPER_ADMIN فقط): جدول تعديل لكل سياسة (إلزامي-لـ + ينطبق-على + expiry + intervals + auto-close) مع تأكيد «N مزوّداً سيتأثَّر» قبل الحفظ.
  • كلتا الصفحتَين مُسجَّلتان في opsRouter.tsx + opsAccess.ts + قابلتان للتمدّد لإضافة nav في Layout (تركتُ الإضافة العادية لـnav واضحة لتراها بنفسك أوّلاً).

للتسجيل (المزوّد + السائق)

  • CityPicker الجديد: cascading dropdowns (المنطقة ← البلدية) يَجلب البيانات من /geo/regions.
  • إذا فشل الـAPI (احتراز): سَقطة سَلِسة إلى الـdatalist القديم بـ141 بلدية.
  • عند تَعديل ملفّ موجود: يَكتشف المنطقة تلقائياً من قيمة البلدية القائمة (لا فقد بيانات).

٦. ثغرات اكتُشفت وعُولجت خلال البناء

  1. طول revision-id: اسم migration الأوّل (33 حرف) تجاوز VARCHAR(32) لجدول alembic_version → اختصرتُه إلى aa16_pd_lifecycle (17 حرف) وتَحقّقت من نَجاح upgrade+downgrade على PG.
  2. تَسرّب PK بين اختبارات: الـconftest يُلزم rollback في نهاية كل اختبار، لكنّ commit() صريح يَتجاوزه → استَبدلت db.add() بـdb.merge() للسياسات/المناطق ذات PK ثابتة لجعل الاختبارات idempotent.
  3. edge-case في compute_warning_level: delta_days == 0 (يَنتهي اليوم) كان يُحسب كـpre (level 3) بدل post (level 4) → غيّرتُ الشرط > بدل >= وأَجريت اختباراً يَلتقطها.
  4. NotificationService constructor: أُولاً مرّرت بلا session ثم اكتشفتُ أنّ التوقيع NotificationService(session) + كاميرا الـsend مع recipient_role + event_type + template_vars — صحَّحتُ.
  5. imports محلّية: النمط في operations_router هو from sqlalchemy import select داخل كل دالة (موجود في 9 مواضع سابقة)، فاتّبعتُه بدل import علوي.
  6. TypeScript HeadersInit: conditional object spread لم يَقبله fetch → استخدمتُ Record<string, string> صريح.
  7. regression قديم: test_phase172 كان يَستخدم pharmacy كقيمة تجريبية — حدَّثتُه إلى market مع تعليق يَشرح السياق.
