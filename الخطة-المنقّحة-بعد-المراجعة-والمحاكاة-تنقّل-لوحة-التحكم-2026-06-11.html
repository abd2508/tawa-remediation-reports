١. منهج المراجعة والمحاكاة

لكلّ مرحلة في الخطة الأصليّة: قرأتُ الكود الذي ستلمسه، حدّدتُ ماذا يتغيّر · لماذا · أثره على بقيّة الملفّات والدوالّ، ثمّ شغّلتُ محاكاة ذهنيّة: «حين أبني/أُصلح هذا، ماذا يحدث فعلًا؟ ما الحالة الحدّيّة؟ ما الذي ينكسر؟». نتائج المحاكاة (SIM) أُدمجت كعلاجات صريحة داخل المراحل.

٢. مصفوفة «ماذا نغيّر · لماذا · الأثر الكامل»

النقطةماذا نغيّرلماذاالأثر الكامل (ملفّات/دوالّ) — مؤكَّد بالكود
م0 · توحيد دور OPS isOps يصير isOpsRole(role) من opsAccess.ts؛ opsRouter يستهلك نفس الثابت. إصلاح D-1: حارس /ops يُدخِل 7 أدوار لكنّ isOps يفحص 4. واسع isOps يتحكّم بـ4 سلوكيّات: opsToken (SSE) :44 · idle effect :57,73 · render :83 → ADMIN/SUPERVISOR/MONITOR سيحصلون أيضًا على SSE + خروج خمول + القشرة. تغيير سلوك ⟵ قرار بوّابيّ.
م1 · مكوّن OpsTopNav مكوّن جديد يشتقّ من OPS_NAV_SECTIONS + canAccessOpsPath. جوهر التصميم الجديد (طبقتان). إعادة استخدام تامّة للمصدر والحارس → صفر منطق صلاحيّات جديد. يعتمد على useLocation (إعادة تصيير عند كلّ تنقّل، رخيص). لا يلمس opsNav/opsAccess.
م2 · دمج Layout + CSS استبدال كتلة nav.ops-sidebar بـ<OpsTopNav/>؛ .ops-body يصير المحتوى فقط. نقل التنقّل للأعلى وتحرير العرض. حسّاس يجب الحفاظ على سلسلة التمرير: .ops-shell flex/column/100vh · .ops-main flex:1/overflow-y:auto؛ OpsTopNav لازم flex-shrink:0 وإلّا فقد المحتوى تمريره (SIM-CSS-1). <OpsCommandPalette/> يبقى مُركَّبًا.
م3 · الاستجابة/الفيض «المزيد ⋯» + سلوك الجوّال. 9 أقسام قد تفيض. Popover/Anchor دعمها غير شامل (SIM-POP-1)؛ Priority+ معقّد (SIM-RESP-1). MVP = تمرير أفقيّ.
م4 · الحالة localStorage + تظليل. تذكّر القسم + «أين أنا». تمييز «القسم المفتوح» عن «قسم المسار الحاليّ» (SIM-STATE-1)؛ التحقّق من صلاحيّة القسم المحفوظ (SIM-PERSIST-1).
م5 · الاختبارات تحديث Layout.test + OpsTopNav.test جديد. إصلاح D-2. يُصيَّر Layout في اختبار واحد فقط (نطاق محدود) → الحلّ الأنظف: ضبط initialEntries على مسار القسم المختبَر فيُفتح تلقائيًّا (SIM-LAYOUT-1). nav-keys لا يتأثّر.
م6 · البوّابات/النشر tsc/lint/build/Vitest + نشر واجهة. ضمان عدم الانحدار. FIN-COR غير متأثّر (واجهة بحتة) · بلا migration · قابل للتراجع بإعادة deploy_web.

٣. نتائج المحاكاة (SIM) — مستخرَجة ومُدمَجة

المعرّفالخطورةما الذي ستكشفه المحاكاة أثناء العملالعلاج المُدمَج في الخطة
SIM-NAV-1عالية«أيّ قسم» بـstartsWith ساذج: /ops/cp/drivers يُطابق /ops (رئيسية) و/ops/cp (بيانات) → نسب خاطئ.خوارزميّة تحترم end + أطول تطابق (§٤).
SIM-CSS-1عاليةإن لم يكن OpsTopNav بـflex-shrink:0 فإنّه ينمو ويأكل ارتفاع .ops-main → يختفي تمرير المحتوى.flex-shrink:0; height:auto للشريط؛ الإبقاء على .ops-main flex:1/overflow.
SIM-D1-1عالية (بوّابيّ)توسيع isOps يفعّل SSE + خروج خمول + القشرة لـ3 أدوار جدد دفعةً.م0 قرار بوّابيّ منفصل + تحقّق حيّ لـADMIN/SUPERVISOR/MONITOR. إن رُفض: الخطة تعمل لـ4 أدوار كما الشريط الحاليّ.
SIM-LAYOUT-1عاليةاختبارات تؤكّد روابط من قسمين معًا → تفشل مع «قسم واحد».ضبط initialEntries لمسار القسم → يُفتح افتراضيًّا، أو نقر تبويبه أوّلًا.
SIM-VT-1متوسّطةstartViewTransition(()=>setState) لا يلتقط DOM الجديد (React يجمّع) إلّا بـflushSync → وميض/لا حركة.جوهر الكشف = انتقال CSS (opacity/translate) موثوق بلا تبعيات؛ View Transitions اختياريّ لانتقال المسار فقط خلف feature-detect+flushSync.
SIM-POP-1متوسّطةCSS Anchor Positioning غير شامل (Firefox جزئيّ منتصف 2026).Popover API (شامل) + بديل تموضع بسيط (absolute/JS) عند غياب anchor.
SIM-RESP-1متوسّطةPriority+ يتطلّب ResizeObserver وقياس عرض كلّ تبويب — هشّ.MVP = overflow-x:auto لصفّ Tier 1 (آمن RTL)؛ Priority+ تحسين لاحق.
SIM-STATE-1متوسّطةخلط «القسم المفتوح» (يتحكّم به المستخدم) بـ«قسم المسار الحاليّ» → تظليل مُربِك حين يفتح قسمًا دون تنقّل.حالتان بصريّتان: aria-selected للمفتوح + علامة aria-current لقسم المسار.
SIM-VSPACE-1متوسّطة3 صفوف علويّة (top-bar + Tier1 + Tier2) تقلّل ارتفاع الجداول على شاشات قصيرة.صفوف مدمجة + خيار إخفاء Tier 2 عند التمرير (على حاوية .ops-main، لا النافذة).
SIM-ANIM-1منخفضةتحريك height:auto متقطّع.تلاشٍ بـopacity/translateY لا height.
SIM-STICKY-1منخفضةالشريط شقيق فوق حاوية التمرير → لا يحتاج position:sticky أصلًا.تبسيط: بلا sticky (يبقى ظاهرًا طبيعيًّا).
SIM-PERSIST-1منخفضةقسم محفوظ قد لا يراه الدور الحاليّ (تغيّر الدور).التحقّق من وجوده في الأقسام المفلترة، وإلّا fallback لقسم المسار/الأوّل.
SIM-KBD-1منخفضةأسهم لوحة المفاتيح في RTL معكوسة؛ تفعيل تلقائيّ أم يدويّ؟roving + قلب الأسهم بـRTL + تفعيل-عند-التركيز (كشف لا تنقّل) + Home/End + Tab للدخول لـTier 2.
SIM-EMPTY-1منخفضةدور يرى 0 أقسام (نظريًّا) → تعطّل.حارس sections[0]?.titleKey + تصيير فارغ آمن.

٤. خوارزميّة «أيّ قسم» المُحصَّنة (علاج SIM-NAV-1)

التصادم المؤكَّد: /ops (end) · /ops/cp (end) · /ops/cp/providers|customers|drivers · /ops/cp/audit-log. الحلّ: احترام end + أطول to مطابق.

function sectionOf(pathname, sections) {
  let best = null, bestLen = -1
  for (const s of sections)
    for (const it of s.items) {
      const exact  = pathname === it.to
      const prefix = !it.end && pathname.startsWith(it.to + "/")   // end ⟵ تطابق تامّ فقط
      if ((exact || prefix) && it.to.length > bestLen) { best = s.titleKey; bestLen = it.to.length }
    }
  return best   // قد يكون null ⟵ fallback: localStorage ثمّ sections[0]
}

/ops/cp/driversرئيسية/بيانات ✗الكيانات ✓ (تطابق تامّ)
/ops/cpرئيسية ✗البيانات ✓ (end تامّ)
/ops/finance/ledger (ليس عنصر تنقّل)رئيسية ✗المالية ✓ (بادئة /ops/finance)
/ops/kpiرئيسيةالرئيسية ✓ (تطابق تامّ)

٥. الخطة المنقّحة بالمراحل

م0 — توحيد دور OPS قرار بوّابيّ (SIM-D1-1)
  • تصدير OPS_ROLES + isOpsRole() من opsAccess.ts؛ استهلاكهما في Layout وopsRouter.
  • قبل التنفيذ: موافقتك صريحة (يفعّل القشرة + SSE + خروج الخمول لـADMIN/SUPERVISOR/MONITOR). إن رُفض ⟵ نتخطّى م0 وتعمل الخطة لـ4 أدوار (تكافؤ مع الحاليّ).
م1 — مكوّن OpsTopNav
  • اشتقاق الأقسام المفلترة (إخفاء قسم بلا عناصر) من المصدر المشترك.
  • sectionOf المُحصَّنة (§٤) لتحديد القسم النشط من المسار · effect يتبع useLocation.
  • Tier 1 role="tablist" + roving (SIM-KBD-1، قلب أسهم RTL) · Tier 2 role="tabpanel" يلفّ <nav> روابط NavLink (تمرير end={it.end}).
  • كشف Tier 2 = انتقال CSS opacity/translateY (SIM-ANIM-1)، لا View Transitions في الجوهر (SIM-VT-1).
  • حارس sections[0]? (SIM-EMPTY-1).
م2 — دمج Layout + CSS (SIM-CSS-1 · SIM-STICKY-1)
  • Layout (فرع isOps): <OpsTopNav/> بين الترويسة و.ops-body؛ إزالة nav.ops-sidebar.
  • CSS: .ops-topnav{flex-shrink:0} (يحفظ تمرير .ops-main)؛ بلا sticky (شقيق فوق حاوية التمرير)؛ .ops-body = المحتوى فقط. الإبقاء على .ops-sidebar* خاملةً إن أُقرّ تبديل «كلاسيكيّ».
م3 — الاستجابة (SIM-RESP-1 · SIM-POP-1 · SIM-VSPACE-1)
  • MVP: overflow-x:auto لصفّ Tier 1 (آمن RTL) · «المزيد ⋯» بـPopover + بديل تموضع · صفوف مدمجة + (اختياريّ) إخفاء Tier 2 عند تمرير .ops-main.
م4 — الحالة (SIM-STATE-1 · SIM-PERSIST-1)
  • حالتان: aria-selected للقسم المفتوح + aria-current/نقطة لقسم المسار الحاليّ.
  • localStorage مع تحقّق صلاحيّة القسم المحفوظ ضدّ الأقسام المفلترة.
م5 — الاختبارات (SIM-LAYOUT-1 · إصلاح D-2)
  • Layout.test: ضبط initialEntries=["/ops/finance"] (مثلًا) ليُفتح القسم تلقائيًّا فيُؤكَّد رابطه دون نقر؛ أو نقر التبويب أوّلًا. تحديث تأكيدات :57,62,90,96,74.
  • OpsTopNav.test.tsx جديد: فلترة الدور · افتراض قسم المسار · sectionOf للتصادمات (/ops/cp/drivers→الكيانات) · roving keyboard · الكشف · 0-روابط من أقسام غير نشطة.
م6 — البوّابات + النشر + تحقّق حيّ بالصور
  • tsc 0 · lint 0 · build · Vitest ثمّ deploy_web.sh + تحقّق (62 مسارًا 0-مكسور · تطابق الأدوار · a11y · RTL · إن أُقرّ م0: الأدوار الثلاثة).

الخلاصة

قارنتُ كلّ نقطة بالكود وحاكيتُ تنفيذها، فاستخرجتُ 14 عيبًا/خطرًا (3 عالية: NAV-1 تصادم البادئات · CSS-1 تمرير المحتوى · D1-1 الأدوار) ودمجتُها كعلاجات صريحة. المخاطر مُحاطة، والحدود واضحة (واجهة بحتة قابلة للتراجع، بلا مساس بالمصدر/الحارس/المالية). هذه الخطة المنقّحة جاهزة للمراجعة — لم يُبنَ شيء. بانتظار حسم القرارات البوّابيّة (خاصّة م0/D-1) و A/B/C/E، ثمّ أبدأ م0→م6 بثقة.
