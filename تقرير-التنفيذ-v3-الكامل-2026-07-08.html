٩ المشكلات والحلول

🔴

🔴
مشكلة: قاعدة "No-Commit" منعت تنفيذ git commit تلقائياً. المصنّف التلقائي (auto-mode classifier) رأى أن "أمنحك الصلاحيات التامة" غير كافٍ لأمر حساس كـ commit.
🟢
الحل: اكتب أي من هذه العبارات وسأُكمل فوراً: "commit وانشر" أو "أكمل النشر على المواضع الأربعة" أو "أذنت بالـ commit والنشر."
🔴
مشكلة: منطق canCheckout كان يسمح بالدفع أثناء تحميل بيانات المتاجر، مما يتيح نظرياً إرسال طلب بدون التحقق من الحد الأدنى أو حالة المتجر.
🟢
الحل: أضفنا loadingAny = allBaskets.some(b => !providerInfoMap[b.providerId]) ودمجناه في شرط canCheckout — الزر يبقى معطّلاً حتى يكتمل التحميل.
🔴
مشكلة: قائمة الطلبات (list_orders) كانت تجلب اسم السائق بطلب منفصل لكل طلب (N+1 problem)، مما يُبطئ الاستجابة مع تراكم الطلبات.
🟢
الحل: أضفنا _driver_name_map يجلب أسماء كل السائقين في استعلام واحد بدل استعلام لكل طلب. التكلفة: ذاكرة أكثر، لكن الأداء أفضل بكثير.
🔴
مشكلة: الهجرة ab22 تحتاج تطبيقها على 3 قواعد بيانات حية (test1 · test · Production) بدون تعطّل الخدمة.
🟢
الحل: الهجرة آمنة للتطبيق اللحظي: كلها إضافة أعمدة nullable — لا حذف ولا تعديل. alembic upgrade head يكفي بدون توقف الخدمة. الـ downgrade يحذف الأعمدة فقط.
