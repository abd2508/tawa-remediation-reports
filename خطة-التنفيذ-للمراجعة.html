٢ · ما قبل التنفيذ (Pre-flight) — التقاط أساس أخضر

قبل لمس أي ملف، نثبت أن الشجرة نظيفة والأساس أخضر، لنعرف أن تغييرنا هو الفارق الوحيد.

P0 تأكيد نظافة الشجرة.
git -C platform status --short → يجب أن يكون فارغاً (تأكّد بالفعل: لا تغييرات معلّقة).
P1 تشغيل خطوط الأساس وتسجيل الأرقام: 
cd platform/web
npm run typecheck      # متوقّع: exit 0
npm run lint           # متوقّع: 0 errors
npm run build          # متوقّع: exit 0
npx vitest run         # سجّل العدد الإجمالي (الأساس)
P2 تحقّق عقود FIN-COR (إن وُجد السكربت): 
python3 platform/_ai_tools/bin/contract_flag_hash_check.py  # يجب PASS

٣ · WI-1 — السماح ببلاطات الخريطة في CSP كود · web/

🔵 قرار مطلوب (١): أي خيار للبلاطات؟
خيار أ (سريع — موصى به الآن): السماح بمضيف OSM العام في CSP. سطر واحد، يُصلح الخريطة فوراً.
خيار ب (الأمثل للإنتاج): استضافة بلاطات ذاتية (يتماشى مع توجّه «الخرائط الذاتية» — المرحلة 385)، لأن بلاطات OSM العامّة تخالف سياسة الاستخدام العادل في الإنتاج. أكبر حجماً (إعداد خادم بلاطات).
توصيتي: «أ» الآن لإعادة الخريطة للعمل، و«ب» كبند تطوير لاحق منفصل.

التغيير الدقيق (خيار أ) — web/nginx.conf السطر ١١

- img-src 'self' data: blob:;
+ img-src 'self' data: blob: https://*.tile.openstreetmap.org;
// مع تعليق توضيحي مختصر بنفس أسلوب الملف؛ بقية التوجيهات بلا تغيير
  • connect-src يبقى 'self' — البحث/التوجيه يمرّان عبر وسيطنا /api/geo/* (نفس الأصل).
  • اختبار الهيدرز يبقى أخضر: nginx-security-headers.test.ts يفحص وجود default-src 'self' وframe-ancestors 'none' فقط — لا يقيّد img-src. (مؤكَّد.) فلا حاجة لتعديل اختبار.
معيار القبول WI-1
بعد إعادة البناء/التشغيل الحيّ: بلاطات الخريطة تظهر، وconsole خالٍ من انتهاكات CSP الخاصّة بالبلاطات.

٤ · WI-2 — توحيد ماركر LocationPicker كود · web/

الأشقّاء الثلاثة يُضمّنون الأيقونة محلياً (→ data: → آمن مع CSP). نجعل LocationPicker مثلهم ونحذف اعتماد cdnjs.

التغيير الدقيق — web/src/components/LocationPicker.tsx الأسطر ٢٢–٢٤

- iconRetinaUrl: "https://cdnjs.cloudflare.com/ajax/libs/leaflet/1.9.4/images/marker-icon-2x.png",
- iconUrl:       "https://cdnjs.cloudflare.com/ajax/libs/leaflet/1.9.4/images/marker-icon.png",
- shadowUrl:     "https://cdnjs.cloudflare.com/ajax/libs/leaflet/1.9.4/images/marker-shadow.png",
+ iconRetinaUrl: new URL("leaflet/dist/images/marker-icon-2x.png", import.meta.url).href,
+ iconUrl:       new URL("leaflet/dist/images/marker-icon.png",    import.meta.url).href,
+ shadowUrl:     new URL("leaflet/dist/images/marker-shadow.png",  import.meta.url).href,
معيار القبول WI-2
  • rg "cdnjs" web/src → لا نتائج فعلية (عدا التعليقات).
  • إعادة البناء: حِزمة LocationPicker تحوي data:image/png;base64 (الأيقونة مُضمّنة) ولا روابط cdnjs.
  • اختبارا LocationPicker وnginx-security-headers يمرّان (تحقّقتُ مسبقاً: ٦/٦).

٥ · التحقّق بعد WI-1 + WI-2 (قبل أي نشر)

V1 فحص الأنواع + lint + build: 
cd platform/web
npm run typecheck && npm run lint && npm run build   # كلها تنجح
V2 اختبارات مُوجّهة ثم كاملة: 
npx vitest run src/test/nginx-security-headers.test.ts src/components/LocationPicker  # 6/6
npx vitest run   # نفس عدد الأساس (P1)، 0 فشل جديد
V3 فحص ناتج البناء يدوياً: 
rg -c cdnjs web/src            # 0 (عدا التعليق)
rg "tile.openstreetmap" web/nginx.conf  # مسموح به الآن في img-src
🚦 بوابة مراجعة: هنا تتوقّف السلسلة. أعرض عليك نتائج V1–V3، وتقرّر الانتقال إلى النشر (WI-3).

٦ · WI-3 — بحث العنوان (نشر + تشغيل، بإذنك) نشر

لا تعديل كود. المسار موجود وصحيح؛ المطلوب نقل الكود الحالي للخادم الحيّ + تشغيل خدمة الجيوكودينغ.

🔵 قرار مطلوب (٢): نطاق النشر
نشر الكود الحالي للخادم الحيّ سيحمل كل التغييرات منذ ١١ مايو (عشرات المراحل، وميزات مالية ودفع وتتبّع…)، لا مجرّد إصلاح البحث. هذا حدث نشر كبير يتبع runbook النشر وتحقّق الأساس على staging أولاً. هل نمضي بنشر شامل، أم نُبقي WI-1/2 فقط ونؤجّل النشر؟
🔵 قرار مطلوب (٣): خدمة الجيوكودينغ
حتى بعد النشر، البحث يحتاج Nominatim ذاتي الاستضافة (متغيّر NOMINATIM_BASE_URL + بناء بيانات ليبيا — وثيقة deploy/maps/README.md، المتبقّي C-R01). الخيارات: (أ) بناء Nominatim ذاتي الآن (ساعات، حجم بيانات) · (ب) توجيه مؤقّت لمزوّد geocoding مُستضاف ريثما يُبنى المحلي.

الخطوات (إجراء المشغّل، أتولّى التحضير والتحقّق)

D-A نشر الكود الحالي عبر runbook النشر → يُزيل الـ404 (المسار يصبح موجوداً).
تحقّق أساس على staging قبل الترقية + جاهزية rollback.
D-B تجهيز Nominatim (الخيار أ) أو مزوّد مؤقّت (الخيار ب) + ضبط NOMINATIM_BASE_URL.
يجعل البحث يُرجع نتائج فعلية لا فارغة.
معيار القبول WI-3
على الموقع الحيّ: /api/geo/geocode?q=طرابلس يُرجع 200 مع نتائج، والبحث في نموذج العنوان يُظهر اقتراحات قابلة للاختيار.

٧ · التحقّق الحيّ النهائي (بعد النشر)

إعادة فحص tawanow.com عبر المتصفّح الآلي:

  • الخريطة تعرض البلاطات (لا مربّع رمادي) في نموذج العنوان والتتبّع.
  • دبّوس الماركر يظهر في LocationPicker.
  • بحث «طرابلس» يُرجع نتائج.
  • console خالٍ من انتهاكات CSP و404 الخاصّة بالخريطة/البحث.
  • مسار الطلب الكامل (تصفّح ← عنوان ← دفع ← طلب) سليم.
