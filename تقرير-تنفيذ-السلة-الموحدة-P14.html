الأخطاء المُصلَحة (5 أخطاء)

بناءً على التحليل العميق ومقارنة أفضل الممارسات العالمية (Stripe / Grab / Talabat / Uber Eats / Amazon) — اكتُشفت وأُصلحت 5 أخطاء حرجة:

BUG-1 — حالة سباق (Race Condition)
أسعار التوصيل تظهر بيانات قديمة عند تغيير العنوان بسرعة
لو غيّر العميل عنوان التوصيل بسرعة، الطلبات القديمة كانت تكتب فوق الجديدة. النتيجة: يظهر سعر توصيل غلط.
الإصلاح: نمط cancelled flag — عند تغيير العنوان، يُلغى الطلب القديم فوراً. 
useEffect(() => {
  let cancelled = false;
  cartsApi.quote(selectedAddressId, providerIds)
    .then(({ data }) => {
      if (cancelled) return; // ← تجاهل النتيجة القديمة
      setQuotes(data.providers);
    });
  return () => { cancelled = true; }; // ← تنظيف عند التغيير
}, [selectedAddressId]);
BUG-2 — خطأ مالي حرج (Duplicate Orders)
انقطاع الشبكة يُنشئ طلبين مكررين
الكود القديم يُولّد مفتاح أمان جديد عند كل خطأ — حتى لو الخادم استقبل الطلب (مثل خطأ 504 Timeout). عند الإعادة، يُنشأ طلب ثانٍ مكرر.
الإصلاح (نمط Stripe): نحفظ المفتاح قبل الإرسال، ولا نُجدّده إلا عند أخطاء 4xx فقط. 
// 1. احفظ قبل الإرسال
sessionStorage.setItem("tawa_group_idem", idemKeyRef.current);

// 2. في معالج الخطأ
const status = err?.response?.status;
if (status >= 400 && status < 500) {
  // خطأ العميل = مفتاح جديد آمن
  idemKeyRef.current = genUUID();
  sessionStorage.removeItem("tawa_group_idem");
}
// 5xx / انقطاع شبكة = احتفظ بنفس المفتاح للإعادة الآمنة
BUG-3 — إمكانية وصول (ARIA Accessibility)
المكفوفون لا يسمعون رسائل الخطأ
عنصر الخطأ كان يُضاف/يُحذف من DOM ديناميكياً. قارئات الشاشة لا تُعلن عن العناصر الجديدة في بعض المتصفحات.
الإصلاح: العنصر يبقى دائماً موجوداً في DOM، نُغيّر محتواه فقط. 
<div role="alert" aria-live="assertive" aria-atomic="true">
  {errorMsg && <div style={s.errorBox}>{errorMsg}</div>}
</div>
BUG-4 — موثوقية البيانات
فشل جلب اسم متجر واحد يُعطّل عرض جميع المتاجر
Promise.all القديم: إذا فشل طلب واحد، يفشل الكل.
الإصلاح: استخدام Promise.allSettled — كل طلب مستقل عن الآخر. 
Promise.allSettled(pids.map(pid => providersApi.get(pid)))
  .then(results => {
    results.forEach((r, i) => {
      if (r.status === "fulfilled") {
        names[pids[i]] = r.value.data.name || "متجر";
      }
      // "rejected" لا يوقف عرض بقية المتاجر
    });
  });
BUG-5 — تجربة المستخدم (Focus Management)
قارئ الشاشة لا يُعلن عن نجاح الطلب تلقائياً
بعد نجاح الطلب، لم يكن التركيز ينتقل لعنوان "تم الطلب!" تلقائياً.
الإصلاح: ننقل التركيز برمجياً عند ظهور شاشة النجاح. 
useEffect(() => {
  if (successOrders !== null) {
    successHeadingRef.current?.focus(); // ← قارئ الشاشة يُعلن النجاح
  }
}, [successOrders !== null ? 1 : 0]);

شاشة النجاح + حفظ خريطة المجموعة

شاشة النجاح تظهر فوراً من بيانات الاستجابة. ثم يُجلب رمز التسليم بشكل غير متزامن عبر Promise.allSettled. يُحفظ group_id → [order_ids] في localStorage.

صفحة OrderGroupPage مُرجَأ

8

تجميع السجل التاريخي مُرجَأ
