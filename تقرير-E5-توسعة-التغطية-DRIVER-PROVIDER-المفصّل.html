① الخلاصة والدافع

المرحلة أ من E5 ربطت مُطلِق التحقّق الاستشاريّ بوثائق AGENT فقط، بينما جدول document_verifications صُمِّم منذ البداية ليغطّي الأنواع الثلاثة عبر العمود doc_kind (AGENT | DRIVER | PROVIDER). وثائق السائق والمزوّد هما سطحا KYC المركزيّان (صفحة /ops/onboarding)، فكان وصلهما هو الجزء الناقص. هذه التوسعة تُكمله بنفس النمط بدقّة: خامل/استشاريّ/غير حاجب، بلا migration، بلا مساس بالقلب الماليّ.

قبل
التحقّق موصول: AGENT فقط (المرحلة أ)
بعد
التحقّق موصول: AGENT + DRIVER + PROVIDER (نفس المُطلِق الخامل)
على الإنتاج
خامل — is_enabled=False ⇒ كلّ وثيقة جديدة تُسجَّل SKIPPED، لا تحجب

③ الدالّة المشتركة + إعادة التوظيف (تقليل التكرار)

بدل تكرار منطق «أرفِق آخر تحقّق» في ثلاثة مواضع، أضفتُ دالّة مشتركة واحدة، ثمّ أعدتُ توظيف مسار AGENT عليها:

# modules/kyc/doc_verification.py — دالّة جديدة مشتركة
async def latest_verifications_for(db, doc_ids: list[str]) -> dict[str, dict]:
    if not doc_ids: return {}
    rows = (await db.execute(
        select(DocumentVerification)
        .where(DocumentVerification.doc_id.in_([str(d) for d in doc_ids]))
        .order_by(DocumentVerification.created_at.desc()))).scalars().all()
    out = {}
    for v in rows: out.setdefault(v.doc_id, {"status": v.status, "score": v.score, "flags": v.flags})
    return out  # desc ⇒ أوّل ظهور لكلّ doc_id = الأحدث
# settlement/agent_admin_router.py — list_documents (AGENT) أُعيد توظيفه على الدالّة
vmap = await latest_verifications_for(db, [d.id for d in rows])
return {"items": [{..., "verification": vmap.get(d.id)} for d in rows]}

④ وصل المُطلِق — مزوّد + سائق

# provider_router.upload_provider_document — بعد flush، قبل commit
await queue_document_verification(db, doc_id=doc.id, doc_kind="PROVIDER",
                                 doc_type=doc.doc_type, object_key=doc.object_key)
await db.commit()
# dispatch_router.upload_driver_document — أُضيف flush ثمّ المُطلِق
db.add(doc); await db.flush()
await queue_document_verification(db, doc_id=doc.id, doc_kind="DRIVER",
                                 doc_type=doc.doc_type, object_key=doc.object_key)
await db.commit()
رفع وثيقة سائق/مزوّد← إنشاء الصفّ + flush← queue_document_verification← خامل ⇒ SKIPPED← commit (لا يحجب الرفع)
fail-open محفوظ: queue_document_verification لا يرفع أبدًا داخل المُستدعي؛ الرفع يبقى 200 / PENDING كما كان (مؤكَّد باختبار «غير حاجب»).

⑤ إرفاق التحقّق بنقاط قراءة OPS

# GET /drivers/{driver_id}/documents  و  GET /providers/{provider_id}/documents
vmap = await latest_verifications_for(db, [d.id for d in docs])
return {"items": [{**_doc_dict(d), "verification": vmap.get(d.id)} for d in docs], "total": len(docs)}

المُسلسِلات الأصليّة (_doc_dict / _prov_doc_dict) لم تُلمَس — تُستعمَل في مسارات غير OPS (وثائق السائق/المزوّد لنفسه)؛ الإرفاق يقع فقط في نقطتَي قراءة OPS.
